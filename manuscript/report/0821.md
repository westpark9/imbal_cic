## §1. EXP13 판정 재분류 — "TTA 축 종결"을 "공유-사본 K-평균 변형 종결"로 정정

사용자 확인: exp13은 원 의도가 아니었다. 의도는 **SADE(Self-supervised Aggregation of
Diverse Experts, AgnosticLT)의 test-time aggregation** — perturbation 하 **안정성(stability)**
으로 expert 가중치를 얻는 방식. 구현된 exp13은 (a) benign/tail 쌍으로 대상 제한, (b) 두
expert가 **동일 사본** 공유, (c) 가중치 없이 K-사본 **평균 점수의 argmax** — 세 지점 모두
의도와 다름 (`nfv3_v3_exp13_tta_tiebreak.py:383-410`).

따라서 0820.md §12m의 "TTA 축 완전 종결" 판정은 **공유-사본 K-평균 점수 비교 변형에
한정**으로 정정. 단, exp13의 메커니즘 관찰("가우시안 입력 perturb 하 원시 게이트 점수의
평균은 조밀 클래스에 불리한 bias" — 사본 공유/독립과 무관하게 성립)은 유효하므로,
**점수-평균을 쓰는 어떤 SADE 변형에도 경고로 남음**. 안정성(분산·flip율)-가중 방식은
미검증 — 단 s23("비소유 expert도 owner만큼 confident·stable") 전례가 있어 사전 등록 시
그 실패 양식을 어떻게 피하는지 명시 필요.

exp13 run 3개 주의: `20260821_102249`(GPU, full)만 기록-등급. `080323`/`082218`은
context 2000·cap 800 CPU 스모크이고 **본 run과 반대 방향(소폭 양성)** 신호를 보임 —
인용 금지.

## §3. EXP14 사전 등록 — activation expert system의 ton_iot 전이 (결과 전 고정)

   xss} / stealth_malware{backdoor,mitm,ransomware}.
2. **aux 미러링**: cic2018 타깃의 [bot_iot, ton_iot] ↔ ton 타깃은 [bot_iot, cic2018].
   이름 겹침(ddos/dos) 자동 제외, (bot_iot, theft) 제외 유지 → 예상 aux = bot_iot recon
   + cic2018 {bot, brute_force, infiltration, web_attacks}.
3. **global 비교열은 같은 run에서 fit** (§12n 원칙): 자연-비례 --global-context-size

**판정 튜플 (결과 전 고정)**: known macro-F1 vs 같은 run global / tail(mitm,
ransomware) F1 / benign 유지. 구조적 관심사 두 개 — ① ton은 benign이 지배적이지
않아(공격-과다 데이터셋) cic2018의 "benign 기준선 겨루기" 구도가 뒤집힘: benign→tail

조건부가 흡수하므로 그룹 간 누수만 본다. 스모크(CPU, ctx 2000·cap 800) 통과 후
GPU 단독 실행 (§12n: 기록-등급 run은 단독).

## §4. slowhttptest mislabel 문헌 확증 (워크플로 조사, 6건 원문 검증 통과)

우리 실측(0819 §3)의 상류 원인이 **이미 문헌에 문서화**되어 있음을 확인:

1. **Liu, Engelen, Lynar, Essam, Joosen, "Error Prevalence in NIDS datasets: A Case
   Study on CIC-IDS-2017 and CSE-CIC-IDS-2018" (IEEE CNS 2022)** + 공식 부속 문서
   "Improved CSE-CIC-IDS 2018 Documentation" (DistriNet/KU Leuven,
   intrusion-detection.distrinet-research.be/CNS2022/CSECICIDS2018.html). 원문 verbatim:
   *"No succesful DoS Slowhttptest attack was found in this dataset. Instead, it looks
   like the tool was mistakenly launched against port 21."* — 도구가 **port 21로
   오발사**됐고 포트가 닫혀 있어 SYN→[RST,ACK]만 오간 실패 트래픽. 개선판은 해당
   시간창(2018-02-16 14:12:14–15:05:13 UTC, 13.59.126.31→172.31.69.25)을
   **"FTP-BruteForce – Attempted (Category 1 – Port/System closed)"로 재라벨**.
   같은 문서: 14-02의 원조 FTP-BruteForce도 port 21이 닫혀 credential을 보낸 적 없는
   payload-less 시도 → 두 클래스가 flow 수준에서 동일해지는 것이 필연.
   TCP_FLAGS=22 = SYN(2)+RST(4)+ACK(16) — 우리 실측 vector와 정합.
2. **Liu & Patras, "NetSentry" (arXiv:2202.09873, 2022)** 독립 확인: *"FTP-Bruteforce
   and DoS-SlowHTTPTest attacks were erroneously collected in CSE-CIC-IDS2018, the
   generated traffic merely contains SYN and RST packets"* — mislabeled 트래픽을
   제거하고 자체 수집(4,050 flows)으로 대체했다고 보고.
3. **NF(NetFlow) 변환본 쪽은 공백**: Sarhan et al. NF 논문들은 해당 클래스의 DR≈0
   증상만 보고하고 원인 미진단; NF-v3 에라타·이슈 트래커 부재. "v3가 이 결함을
   상속하며 시나리오 전체가 단일 vector로 축퇴한다(105,550행 → distinct 1개)"는
   관측은 문헌에 없음 → **우리 실측이 NF-v3 수준 최초 보고일 가능성 — 논문에 novel
   observation으로 기재 가능**.

교차 검증: 워크플로 4각도 탐색 + 6건 전부 원문 fetch 재검증 통과 (2017 논문을 2018로
오인한 사례 아님을 별도 확인). 결론: dos→bf_bot 축은 "우리 발견 + 문헌 확증"으로
이중 지지 — 라벨 교정(slowhttptest→brute_force)은 Liu et al. 개선판의 재라벨과 같은
방향이므로 §12i의 교정 수치 인용 시 이 문헌을 함께 인용할 것.

**상류(원본) 직접 확인 (사용자 요청)**: `data/cic2018/`의 원본 CSE-CIC-IDS2018
CICFlowMeter CSV에서 — `2_Friday-16-02-2018` 파일의 SlowHTTPTest 139,890행 **전부
Dst Port 21**, 1 fwd + 1 bwd pkt; `0_Wednesday-14-02-2018`의 FTP-BruteForce 193,360행도
전부 port 21 동일 형태. 첫 행 타임스탬프 10:12:14(UTC-4) = Liu et al. 재라벨 시간창
시작 14:12:14 UTC와 정합. **판정: 결함은 pcap 수집 단계(원본) — NF-v3는 상속만 했고,
NF-v3 고유 기여는 nProbe flow 절단에 의한 단일-vector 축퇴 형태(105,550행 vs 원본
139,890행)뿐.** 부산물: `data/NF-CICIDS2018-v3_attacks_only.csv` (benign 제거 열람용,
547MB, 2,600,903행 — 재현 기록 아님, 뷰어용).

## §5. inf↔benign — "XGB는 어떻게 구분하나" 메커니즘 분해 (scratchpad 진단, 기록 run 아님)

스크립트: `scratchpad/inf_vs_benign_xgb_diag.py` (원본 NF-CICIDS2018-v3.csv, suite 46-feature,
클래스별 시간순 60/20/20 재현, 이진 XGB 프로젝트 파라미터 + benign 전체-prior 가중).
결과 검증: est F1 0.427 = 기록된 global XGB inf F1 0.4291과 일치 → 재현 유효.

**test-inf 37,627행의 train 대비 동일-벡터 지위 분해**:
| 그룹 | 비율 | XGB recall |
|---|---|---|
| twin_inf_only (train에 inf로만 등장) | 3.8% | **0.938** |
| twin_both (train에 inf·benign 양쪽 라벨로 등장) | **58.4%** | 0.369 |
| twin_benign_only (train에 benign으로만 등장) | 12.9% | 0.000 |
| no_twin (train에 없는 새 벡터) | 24.8% | 0.293 |

**해석**: XGB의 recall 0.324는 ① 극소수 순수-inf 벡터 암기(0.94), ② 다수(58%)를
차지하는 **라벨-충돌 벡터에서의 train 다수결 베팅**(0.37 — 이 지역은 원리상 per-vector
다수결이 상한 = 1-NN purity 천장의 실체), ③ 새 벡터 일반화(0.29)의 합. top-gain 축은
DST_TO_SRC_AVG_THROUGHPUT(중앙값 inf 320,000 vs benign 14,680), CLIENT_TCP_FLAGS(0 vs 2),
PROTOCOL(17=UDP vs 6), MIN_TTL(0 vs 100), TCP_WIN_MAX_IN(0 vs 252) — 즉 **분리 가능한 inf
하위집단은 "UDP·플래그0·TTL0·고역방향처리량"의 sharp 임계값 시그니처**이고 축-정렬 분할이
정확히 잘라냄. TabPFN 유사도-기하가 같은 지역에서 약한 것(0.097)과 정합: 한두 축의 sharp
차이는 46차원 유사도 평균에서 희석되고, 충돌-벡터 다수결도 benign-지배 retrieval에서 짐
(해석 — 별도 검증은 안 함).

## §5b. TabPFN v3 전처리 실측 (ckpt 저장 config + 소스 확인) — feature 전처리 개입 지점

사용자 질문("전처리 잘 하면 argmax 배정이 나아지나, 상수 feature 제거 등")에 대한 실측.
v3는 전처리 config를 **ckpt에 저장** (`inference_config.get_default`는 v2까지만) — 우리
ckpt의 `PREPROCESS_TRANSFORMS` = [squashing_scaler_default(+ordinal cat, SVD ¼, append 없음),
none(무변환)]. **n_estimators=1이라 `_balance`(1//2=0→leftover) 규칙으로 첫 번째만 사용** —
무변환 view는 우리 설정에서 안 돎.

우리 run에 실제 적용되는 파이프라인:
1. 우리 쪽: suite 생성 시 nonfinite→0 대치 + 스크립트 np.nan_to_num — 그 외 없음(원시 46).
2. **상수 feature 제거: 이미 내장** (`remove_constant_features_step`, context 기준) —
   FTP_COMMAND_RET_CODE(2M 표본에서 단일값 100%)는 자동 제거. 사용자 아이디어의 완전-상수
   부분은 이미 적용돼 있음.
3. 타입 감지: unique≤30 → categorical. 46개 중 **PROTOCOL(5)·DNS_QUERY_TYPE(7)만** 해당.
   **TCP_FLAGS(38)/CLIENT(40)/SERVER(36)는 30 초과라 연속 수치 취급 — 비트마스크 의미 상실.**
4. squashing scaler: robust scale 후 x/√(1+(x/3)²) soft-clip(±3 포화) — quantile 아님,
   heavy-tail(THROUGHPUT류) 상위 구간 해상도 압축. outlier ±12σ→NaN(분류 기본).
5. SVD ¼ 성분(~11개) + fingerprint feature 1개 추가, feature/class shuffle(시드 고정),
   v3 아키텍처는 feature를 **3개씩 그룹 임베딩**(feature_group_size=3, 그룹 구성은 셔플 의존).
6. `use_nan_indicators=True` — 모델에 NaN 지시자 채널이 있는데 **우리가 0으로 선대치해 죽여
   놓은 상태** (NetFlow의 0은 "해당 없음" placeholder와 진짜 0이 혼재: UDP의 TCP_WIN/TTL 등).

**개입 가능성 판정**: 동일-벡터 지역(dos 전체, inf의 58.4%)은 전처리로 원리적 불가(같은 입력
→ 같은 출력). 개입이 닿는 곳은 inf 분리가능 지역(§5의 sharp-축 하위집단)뿐이고 후보는:
(a) TCP_FLAGS 3종 **비트 분해**(sharp 경계 복원), (b) **준-상수 feature 정리** — 완전 상수는
이미 제거되므로 실질 대상은 RETRANSMITTED×4(91–97% 단일값)·ICMP×2(91%) 등 8개 내외의 유사도
희석 축, (c) **0→NaN 복원**으로 nan_indicator 활성화, (d) heavy-tail log1p 사전변환(포화 완화).
주의: 전처리는 게이트·조건부·global 모두에 걸리므로 비교군 동일 적용이 원노브 성립 조건.

## §12. EXP17 사전 등록 — global-vs-expert 학습 선택기 (구조 변경, 결과 전 고정)

사용자 설계: "지금 구조는 잘못 배정되면 반환 출구가 없다. x에 대해 global과 각 공격
expert의 클래스-확률 예측을 산출하고, CE loss로 'global을 따를지 expert k를 따를지'를
학습해 선택된 쪽의 예측으로 라벨 결정. x가 benign이면 global을 따르는 게 이상적."
스크립트: `tabpfn/nfv3_v3_exp17_selector.py` (frozen).

**설계 (사용자 정정 반영: 후보 5개)**: 후보 = {global(자연-비례 1M), flood{ddos,dos},
bf_bot{brute,bot}, **inf{infiltration}, web{web_attacks}**} — tail을 단일-클래스 expert
둘로 분리, benign expert는 제거되고 global이 benign 출구를 겸함(반환 경로). 단일-클래스
expert는 TabPFN fit의 2-클래스 요건 때문에 **benign filler 20k**를 context에 포함
(selector-holdout 슬라이스 뒤의 서로소 구간에서 추출 — 누수 없음); filler는 fit 합법화
+ selector용 P(own) 특징 생성이 목적이고, **선택 시 라벨은 소유 클래스로 결정적**.
선택기 입력 = [p_global(7), p_flood(2), p_bf(2), p_inf(2), p_web(2)] 15차원, 2층
MLP(32) → 5-way CE. 학습 타깃(라벨 유도): y=benign → global, y∈owned(k) → expert k.
학습 데이터 = train-측 holdout (benign 15k + expert별 holdout; 타깃-균형 배치). 추론:
argmax 선택 → global 선택 시 7-way argmax, 다중-클래스 expert는 소유-내 argmax,
단일-클래스 expert는 소유 클래스.

**SRC_HISTORY 근접성 고지 (필수)**: 이 설계는 실패양식 **#2(예측에 적합된 competence
모델은 chrono 전이 실패)** 및 exp5 D1(view-선택기 사망), #1(라우팅 오류 증폭)에 가장
가깝다. 탈출 논거: ① 학습이 val 예측이 아니라 **train-측 holdout**(게이트 head와 같은
데이터 체제 — 이 체제의 게이트는 전이에 성공한 전례 있음), ② 입력이 확신도 스칼라가
아닌 **전체 확률 분포**(s23의 사망은 confidence-스칼라 선택), ③ benign 출구가 구조에
존재(#1의 강제 환전 제거). 판정: 선택 정확도(true class × 선택 source 표) + 튜플 vs
같은 run global vs exp12c — 선택기가 argmax-게이트(12c)나 global에 못 미치면 #2 재현
으로 기록. 비용: featurize 불필요(확률만) → expert당 predict_proba 4M, 총 ~1.5h.
