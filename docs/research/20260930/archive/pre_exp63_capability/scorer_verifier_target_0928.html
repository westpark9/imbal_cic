2. 정정한 oracle: 담당 expert의 예측을 그대로 평가

아래 2~3장은 09/28에 저장한 expert의 진단(EXP59)이다. 09/30 S/V 실험은 같은 context로 재학습했으므로 진단 수치와 최신 정책 성능을 같은 fitted bank의 결과로 혼합하지 않는다.

Test 정답을 포함해 residual을 계산한다 → 가장 가까운 학습 residual cluster를 찾는다 → 그 expert가 예측한 클래스를 그대로 채점한다.

기존의 “여러 expert 중 맞힌 예측 선택, 없으면 Global 유지”를 바꿨다. 이 값은 정답을 사용한 residual 배정의 조건부 진단이다. 실제 추론 성능이나 가능한 모든 정책의 절대 상한은 아니다.

클래스 하나에 expert 하나를 대응시키지 않는다. 한 클래스도 여러 residual cluster에 분포할 수 있다. 온라인 배정에는 정답을 쓸 수 없으므로 다음 A/B 분석으로 실제 입력 기반 배정의 교정·훼손을 확인한다.

3. Expert 역량: 담당 residual 영역과 입력 기반 배정군

09/28 저장 예측 재집계 · 새로운 context 개입 실험을 포함하지 않음

A · 담당 residual 영역

정답을 포함한 residual에서 해당 expert에 배정된 표본이다. 이 범위의 같은 표본에서 Global과 expert의 교정·훼손, 클래스별 F1을 비교한다.

B · 입력 기반 배정 표본군

정답 없이 입력 표현과 Global 확률로 최근접 배정한 표본이다. A에 속하는 표본과 속하지 않는 표본이 함께 있으므로 담당영역 밖을 뜻하지 않는다.

A/B는 평가 표본이 다르다. 두 범위의 F1을 직접 빼기보다, 각 범위 안에서 Global 대비 교정과 훼손을 읽는다.

호출·채택은 저장된 예측에 정책을 적용해 집계한 논리적 건수다. 준비 단계에서는 모든 expert의 예측을 계산했으므로 이 실행시간을 희소 호출의 온라인 추론 비용으로 사용하지 않는다. 채택해도 Global과 같은 클래스를 예측할 수 있어 채택 수와 출력 변경 수는 다르다.

CIC2018 · 유효한 개입 후보 확보

Validation에서 탐색한 78개 개입 정책 모두 Macro-F1이 감소하고 Benign 오탐·tail F1 조건을 위반했다. 최종 정책은 Global 유지다.

현재 후보·S/V 점수가 교정과 훼손을 구분하는지 validation에서 먼저 점검하고, Infiltration·Web attack의 혼동을 줄이는 expert와 채택 기준을 개선한다.

ToN · 성능 개선, 호출과 오탐 개선 필요

S가 expert를 고르고 V가 일부를 채택한다. 호출률은 100%이므로 호출을 생략하는 기능은 아직 없다. 개선은 Scanning 중심이며 Benign 정답 1,101건을 훼손했다.

Validation 성능이 같은 후보 중 호출이 적은 정책도 있지만, 현재 선택기는 동점에서 먼저 본 정책을 유지한다. 다음에는 호출 비용을 동점 선택 기준으로 반영하고 Benign·tail 성능을 확인한다.

다음 개선과 실험 순서

  1. CIC2018: validation의 후보별 교정·훼손을 확인한다. 교정 가능한 후보가 있는데 선택·채택이 놓치면 S/V를, 후보 자체의 손해가 크면 해당 expert의 context와 사용 대상을 개선한다.
  2. ToN: 검증 성능이 같은 정책 사이에서 낮은 호출률을 우선하고, Benign 훼손과 tail 성능을 확인 구간에서도 점검한다. Test 결과로 임계값을 조정하지 않는다.
  3. 최종 후보 이후: 같은 bank에서 S/V 제거 비교를 수행해 각 요소의 기여를 검증하고, 학습 데이터 예산과 실제 추론 비용을 맞춰 SOTA와 비교한다.
