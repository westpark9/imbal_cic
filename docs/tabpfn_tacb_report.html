1제안 모델 — Activation Expert System

frozen TabPFN + context = expert. 테스트 행은 4개 expert 모두에 병렬 입력되고 (라우터·사전 배정 없음), 각 expert는 자기 context에 대한 유사도 logits에서 energy 기반 게이트 점수를 뽑는다. 점수가 argmax인 expert 하나만 activate되어 소유 클래스 안에서 분류한다. 학습은 expert당 소형 score head 하나(수 초)뿐.

각 설계 결정의 실측 근거는 §3(기각된 접근이 남긴 것)과 §4(OOD 축 발견)에.

이외 완결 기록: TACB(희소 전량 anchor + disjoint 배깅)의 TabPFN 본실험은 보류 중이며, 그 XGB 대조군과 view-평균의 infiltration 시너지(0.45)는 랩 로그에 보존. 아래 그림은 view 실험의 구성 (여정의 참고 자료).

4OOD 축의 발견들 (제안 모델의 이론적 기반)

  • TabPFN-v3의 분류 헤드는 context 행에 대한 retrieval attention — 출력이 확률의 로그일 수밖에 없어 고전 energy가 퇴화하는 이유이자, softmax-직전 유사도가 정통 OOD 신호가 되는 이유. 실측: unseen=bot에서 최대 유사도 AUROC 0.9839 (이 suite의 기록된 MLP energy 0.954 상회).
  • expert별 게이트의 성립 조건과 한계 (6-family unseen 스윕): taxonomy-간 unseen은 0.92–1.00으로 성립, taxonomy-내 unseen(dos만 배우고 ddos 검출)은 원리적 불가(형제 context가 더 강하게 retrieval), benign 분리가 병목 — 이 병목이 이후 activation 3연전의 주제가 됨.
  • energy score fine-tuning은 score 층에서 하면 일반화: aux로 학습한 score가 본 적 없는 family에 0.57→0.98 (in-context OE의 실패 0.39와 대비) — 게이트를 학습된 score로 만드는 결정의 근거.

환전 분해 — expert들의 분류 자체는 정확하다

시스템 recall은 발화율 × 조건부 정확도로 정확히 인수분해된다. 옳은 expert에 도착한 행의 분류 정확도(조건부)는 0.98–1.00 — 즉 도착만 하면 분류는 끝나 있고, 손실은 전부 배정(활성) 단계에서 난다:

web은 무너진 게 아니다. web 509행 중 437행(86%)이 tail expert에 도착했고 그중 92%가 web으로 정확 분류 — recall 0.788은 global(0.442)의 1.8배, 프로젝트 역대 최고다. F1을 무너뜨린 것은 web 행이 아니라 유입: web으로 예측된 11,887행 중 진짜 web은 401행이고 11,142행이 benign이다(아래 박스). 완벽 배정 시의 상한은 oracle macro 0.964(exp10)로 이미 측정되어 있다 — 남은 문제는 분류기가 아니라 배정이다.

병목은 게이트 정확도가 아니라 불균형 산수다. benign→tail 오발화는 4.2% (14.8만 행)뿐이지만 tail 조건부에는 benign 출구가 없어 전량 inf/web으로 강제 환전된다. 그중 11,142행이 web(지지 509행)에 꽂힌다. benign:web = 6882:1이므로 web precision 0.5가 되려면 이 누수가 0.15% 아래여야 한다 — 게이트가 0.85→0.96으로 크게 좋아져도 요구 사양은 두 자릿수 더 아래에 있다 (SRC_HISTORY 실패양식 #1 "라우팅 오류가 불균형을 증폭"의 정량판). 다음 원노브 후보: 공격 expert의 조건부에 benign 반환 출구(context에 benign 포함) — 누수 14.8만의 패자부활로 web·inf precision을 직접 겨냥.
