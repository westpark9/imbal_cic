신호의 위치 — energy score는 게이트에만 있다. exp19의 두 단계는 서로 다른 신호를 쓴다. 배정(게이트) = §3의 energy score(softmax-직전 유사도의 LSE·max → 학습 head)의 4-way argmax. 반환(조건부) = energy 개념이 전혀 없는 순수 TabPFN retrieval 분류 — 들어온 행을 context의 benign 블록 vs 소유 블록과 이웃-비교해서 argmax할 뿐이다 (exp17의 확률-입력 CE 선택기와도 무관). 즉 "내 것인가"의 주장은 energy가 재고, "돌려보낼까"의 판정은 이웃이 잰다.

2직전 시도 — 구조 변경: global-vs-expert 학습 선택기 (exp17)

§3(제안 모델) 구조의 진단된 약점: 게이트가 한 번 잘못 배정하면 조건부에 반환 출구가 없어 강제 환전된다. exp17은 구조를 바꾼다 — benign expert를 없애고 global TabPFN이 benign/기본 출구를 겸하게 한 뒤, "global의 예측을 따를지, expert k를 믿을지"를 후보들의 확률 분포로부터 학습한다:

학습 목적함수 (코드 그대로). 후보 확률 결합 z(x) = [ p_global(x)⁷ ‖ p_flood(x)² ‖ p_bf(x)² ‖ p_inf(x)² ‖ p_web(x)² ] ∈ ℝ¹⁵ (표준화)에 대해, 선택기 f = Linear(15→32) → ReLU → Linear(32→5)를 5-way cross-entropy로 학습한다 (torch.nn.CrossEntropyLoss):

L = −(1/B) Σᵢ log [ exp(f_{t(yᵢ)}(zᵢ)) / Σ_{c=0}^{4} exp(f_c(zᵢ)) ],  t(y) = global (y=benign) · expert k (y∈owned(k))

즉 "x가 benign이면 global을 따르는 것이 정답"이라는 라벨-유도 타깃으로, 후보들의 확률 분포만 보고 소스를 고르도록 배운다. 배치는 5개 타깃 균형(각 2,048), 학습 데이터는 train-측 holdout — validation 예측은 쓰지 않는다.

부수 발견 — global 기준선은 추첨 복권이다. exp17의 global(원시 표현·원시 풀, 다른 1M 추첨)이 macro 0.6210 — 기록 bar(0.7012)와 0.08 차이, brute는 0.916↔0.493으로 스윙. 같은 설정에서 context 추첨만 바꿔도 mega-vector(port-21 블록 등) 베팅의 향방이 뒤집히기 때문 (exp16의 인과 실증과 같은 뿌리). 따라서 global 대비 판정은 반드시 같은-run·같은-추첨으로 하며, 추첨이 다른 run 간 global 비교는 무효. 이 발견으로 0821 §9의 "표현 번들이 global을 손상" 해석도 정정됨: 같은 1M 행(seed-990)에서 raw 0.6210 vs 번들 0.6657 — 표현은 오히려 +0.045 개선 (0821 §14).

"전부 같은 벡터면 지워버리면 되지 않나" — 안 된다, 두 겹으로. ① test는 못 지운다: 벤치마크 평가셋을 임의로 덜어내면 기록·타 연구와의 비교 가능성이 깨진다(취사선택). slowhttptest 21,110행과 그와 동일-벡터인 ftp-bruteforce 77,344행이 test에 공존하는 한, 모델은 벡터당 예측 하나만 낼 수 있어 제로섬이다 — brute로 베팅하면 dos가 21k를 잃고(현 시스템·global의 최적 베팅), dos로 베팅하면 brute가 77k를 잃는다. ② train만 지우는 것은 실측으로 기각됐다 (exp16): 중복 질량을 제거하자 베팅의 근거가 무너져 21,110 블록이 flood·tail로 산개했고 dos F1은 0.781→0.681로 오히려 하락, brute는 0.916→0.492로 반토막, 시스템·global이 동시에 붕괴했다(macro 0.566/0.599). 중복 빈도는 노이즈가 아니라 라벨-확률과 패턴-빈도를 나르는 정보였기 때문. 정당한 처리는 삭제가 아니라 결함 공개 + 라벨-교정 부지표 병기(교정 시 dos 0.991, Liu et al. IEEE CNS 2022 인용)다.

3제안 모델 — Activation Expert System

frozen TabPFN + context = expert. 테스트 행은 4개 expert 모두에 병렬 입력되고 (라우터·사전 배정 없음), 각 expert는 자기 context에 대한 유사도 logits에서 energy 기반 게이트 점수를 뽑는다. 점수가 argmax인 expert 하나만 activate되어 소유 클래스 안에서 분류한다. 학습은 expert당 소형 score head 하나(수 초)뿐.

각 설계 결정의 실측 근거는 §5(기각된 접근이 남긴 것)과 §6(OOD 축 발견)에.

6OOD 축의 발견들 (제안 모델의 이론적 기반)

  • TabPFN-v3의 분류 헤드는 context 행에 대한 retrieval attention — 출력이 확률의 로그일 수밖에 없어 고전 energy가 퇴화하는 이유이자, softmax-직전 유사도가 정통 OOD 신호가 되는 이유. 실측: unseen=bot에서 최대 유사도 AUROC 0.9839 (이 suite의 기록된 MLP energy 0.954 상회).
  • expert별 게이트의 성립 조건과 한계 (6-family unseen 스윕): taxonomy-간 unseen은 0.92–1.00으로 성립, taxonomy-내 unseen(dos만 배우고 ddos 검출)은 원리적 불가(형제 context가 더 강하게 retrieval), benign 분리가 병목 — 이 병목이 이후 activation 3연전의 주제가 됨.
  • energy score fine-tuning은 score 층에서 하면 일반화: aux로 학습한 score가 본 적 없는 family에 0.57→0.98 (in-context OE의 실패 0.39와 대비) — 게이트를 학습된 score로 만드는 결정의 근거.
