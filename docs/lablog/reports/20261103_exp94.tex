\section{왜 CIC2017 전체 망인가}
\begin{itemize}
\item \textbf{EXP93의 한계.} CIC2018은 host별 캡처(하루 약 440개 파일, 45 GB)라 날짜당 피해 host 1대만 추출했다. 그 결과 benign 모집단이 CSV와 달라지고(train 47배, test 74배 차이), family 범위가 비었으며(LOIC-HTTP·Hulk·SlowHTTPTest·FTP·03-01 inf), Bot은 잘못된 host에 alias를 걸어 결함이 됐다. 이 상태로는 head 조기 포화를 판단할 수 없다.
\item \textbf{CIC2017의 구조.} 스위치에서 전체 망을 하루 한 파일로 캡처한다(월~금 5개). host 선택이 없고 benign 모집단이 CSV와 같다. 월요일은 benign 전용이다.
\item \textbf{크기.} 5개 파일 약 50 GB. CIC2018 전체(450 GB)보다 작고, host별 중복 패킷 dedup도 필요 없다.
\item \textbf{수집 경로.} 공식 PCAP URL은 cicresearch.ca로 리다이렉트되고 파일 대신 안내 HTML(106 KB)을 돌려준다. 신청 양식 뒤 링크는 자동화할 수 없어 사용자가 직접 받는다. 저장 위치는 \path{data/pcap/cic2017/<Day>-WorkingHours.pcap}.
\item \textbf{EXP94의 두 축.} (a) CSV 쪽: 원본 CICFlowMeter CSV에서 문제1·문제2 기준치를 먼저 만든다(이 보고서). (b) PCAP 쪽: 같은 망의 PCAP에서 flow를 재구성해 CSV와 2$\times$2로 비교한다(준비 완료, 실행 대기).
\end{itemize}

\section{CSV 쪽 구성}
\begin{itemize}
\item \textbf{입력.} MachineLearningCVE 배포본 8개 파일, 2,830,743행, 통계 78열 + Label(Flow ID·IP·Timestamp 없음). \texttt{Fwd Header Length}가 두 번 있어 한 번만 쓴다.
\item \textbf{전처리.} NaN 또는 $\pm$Infinity가 있는 2,867행 제거 → 2,827,876행. 원 라벨 15종을 9 family(benign, bf, dos, heartbleed, web, inf, bot, portscan, ddos)로 매핑.
\item \textbf{분할.} 파일 내 행 순서는 CICFlowMeter의 flow 시작 순서다. 파일$\times$원 라벨(15종)마다 앞 70\%를 train, 다음 15\%를 validation, 마지막 15\%를 test로 둔다. 파일 전체를 위치로 나누면 공격 창이 일찍 끝나는 family(web, Hulk)의 test가 비어 smoke에서 기각했고, family 단위로 나누면 화요일 bf의 test가 SSH만 남아(FTP가 오전, SSH가 오후) 원 라벨 단위로 바꿨다. 첫 실행(family 단위)은 기록으로 보존한다. test는 전량 평가한다.
\item \textbf{coverage.} train $\ge$ 50행이고 test $\ge$ 1행인 family만 학습·채점한다. inf(train 25)·heartbleed(train 7)는 제외하고 기록한다.
\end{itemize}

\begin{itemize}

\end{itemize}

\section{문제2: CSV의 few-shot 학습곡선}
\begin{itemize}
\item \textbf{설정.} class당 n=2·3·5·10·20·50, seed 43--47, XGBoost(300 trees, depth 8)와 frozen TabPFN(v3, 4 estimators), 두 모델에 같은 행. 정상 포함 test 424,183행, 공격만 83,482행. 7 family 채점(inf·heartbleed 제외). 아래 수치는 원 라벨 단위 분할 실행이다.
\item \textbf{head는 n=20에서 이미 포화한다.} portscan 94--98\%, ddos 88--94\%, dos 75--92\%가 n=20에서 나오고 n=50으로 가도 portscan·ddos는 거의 변하지 않는다. CIC2018 CSV(EXP89)와 PCAP(EXP93)에서 본 것과 같은 현상이다.
\item \textbf{macro-F1은 낮다.} 정상 포함 n=20에서 XGB/TabPFN 60.56/56.82\%, n=50에서 63.18/63.67\%. 낮은 평균은 bot 0\%, web 7--16\%, bf 27--64\%가 만든다.
\item \textbf{bot F1 = 0은 라벨 결함이 시간순 분할에서 드러난 것이다.} test의 bot 294행은 전부 Fwd 3패킷·fwd payload 0·bwd 18바이트·지속 1.01초·port 8080인 같은 모양의 flow이고, 두 모델 모두 전부 benign으로 예측했다. 이것은 CNS2022가 Attempted 범주 1(포트/시스템 닫힘)로 분류한 ``master 종료 뒤 CnC 재접속''이며, 원본 CSV는 이를 Bot으로 라벨했다. 시간순 분할이 실제 C\&C 통신(train)과 재접속 시도(test)를 갈라놓았으므로 0\%는 모델의 실패가 아니라 라벨의 시간 내부 이질성이다. PCAP 쪽에서는 이 flow가 unresolved로 분리된다.
\item \textbf{bf는 분할 단위에 민감했다.} 첫 실행(family 단위)에서는 화요일 FTP-Patator(:21, 오전) 뒤에 SSH-Patator(:22, 오후)가 와서 test bf가 전부 SSH였다. 원 라벨 단위 재실행에서 test bf는 FTP·SSH를 모두 포함하며 정상 포함 n=20 bf F1은 XGB 63.75\%, TabPFN 26.94\%다. TabPFN이 bf를 benign으로 보내는 경향은 두 실행에서 같다. 첫 실행의 macro는 정상 포함 n=20 57.16/54.93\%였고 \path{exp94_csv_byfamily_summary.json}에 보존한다.
\item \textbf{TabPFN$-$XGBoost 차이는 작고 방향이 섞인다.} 정상 포함 n=3--10에서 +2.3--3.2 pp, n=20에서 $-$3.7 pp, n=50에서 +0.5 pp. 공격만에서는 n$\le$10에서 음수, n=20·50에서 +3.0·+2.7 pp. CIC2018 PCAP에서 본 일관된 TabPFN 이득은 여기서 재현되지 않는다.
\item \textbf{상한 대비.} oracle 상한(99.997\%)에 비해 n=50 macro가 63--64\%이므로, 이 CSV의 room은 문제1이 아니라 bot·web·bf의 라벨·표본 문제와 benign 오탐에 있다.
\end{itemize}

\section{CIC2017 데이터 결함 검토}
CNS2022 저자 문서와 notebook에서 확인한 사실(출처는 \path{configs/experiments/exp94_cic2017_labels.json}의 \texttt{known\_issues})과 이번 감사를 합친다.
\begin{itemize}
\item \textbf{라벨 생성 방식.} 2018과 같이 시간창 + endpoint 규칙이다. 원 CIC 웹페이지의 시간창은 부정확해 저자들이 첫/마지막 패킷 기준으로 다시 잡았고, 7개 Attempted 범주(payload 없음, 포트 닫힘, 시작/종료 산물, 악성 payload 없음, 공격 산물, 잘못 구현, 대상 무응답)를 분리했다.
\item \textbf{DoS Hulk는 거의 무효 공격.} urllib2가 Connection: close를 보내 서버가 매 연결을 끊었다. 545,438 flow 중 8개를 제외한 전부가 네 가지 Total Length of Bwd Packets 값으로 걸러진다. CSV 충돌의 대부분(Hulk/BENIGN)이 여기서 온다.
\item \textbf{Apache KeepAliveTimeout 5초.} Slowloris·Slowhttptest·GoldenEye 연결이 5초에서 잘려 IAT 지름길을 만든다. 서버 설정은 CIC가 문서화하지 않았다.
\item \textbf{DDoS LOIC-HTTP.} 대부분 빈 GET 요청이며, 같은 패킷·flow가 창 밖에서도 5--12초마다 2--3개씩 배경으로 생성된다. 창 안/밖 라벨만 다른 동일 flow의 전형적 원인(EXP93 보고서의 원인 ①)이다.
\item \textbf{Web attack.} XSS는 startup/teardown 트래픽이 섞여 652 Attempted 대 27 유효 flow. Brute Force는 DVWA 로그인 페이지 공격이라 5패킷 flow 72개·204/105패킷 flow 69개 두 군집이다. SQL Injection은 CIC 창보다 5분 일찍 시작했다.
\item \textbf{Infiltration.} Dropbox로 전달된 payload 다운로드는 암호화돼 식별 불가(benign 유지). Cool disk-MAC 감염은 원 라벨에서 완전히 누락됐다. 목요일 NMAP은 공식 창 밖 17:33 UTC 회차가 원 데이터에서 benign이다.
\item \textbf{Heartbleed.} 단일 port pair의 긴 세션 하나가 120초 timeout으로 11개 flow로 쪼개진 것이다. 표본 수가 아니라 세션 하나다.
\item \textbf{Botnet Ares.} master 종료 후 CnC 재접속이 Attempted 범주 1이다. notebook과 저자 페이지의 창 시작이 14초 다르다(notebook 채택).
\item \textbf{특징 버그(원본 CSV).} TCP flag 수가 0/1만 있고(첫 패킷만 계산), PSH/URG 방향별 수는 증가하지 않으며, Fwd Header Length가 중복이다. 원 flow 구성은 첫 FIN에서 종료하고 RST를 무시하며 timeout 후속 flow가 방향을 상속한다(TCP-appendix).
\item \textbf{이번 감사가 더한 것.} 정확 중복 행 308,381개(10.9\%). train$\to$test 중복률이 portscan 56\%·bf 46\%다. 포트스캔과 brute force는 같은 벡터가 반복되는 공격이라 few-shot 점수가 ``암기''로도 오를 수 있다. PCAP 쪽에서는 3층 감사로 이 중복이 패킷 수준인지 통계 요약 수준인지 가른다.
\item \textbf{문서에 없는 것.} ``Friday timezone shift''는 저자 자료 어디에도 없어 결함으로 적지 않는다. TCP segmentation offload 수정은 한 줄 언급뿐이다.
\end{itemize}

\section{PCAP 쪽 준비(실행 대기)}
\begin{itemize}
\item \textbf{규칙 전사.} CNS2022 CICIDS2017 notebook을 \path{configs/experiments/exp94_cic2017_labels.json}으로 옮겼다. 5일, confirmed 22 + attempted 31 = 53 rule. 시간은 notebook의 UTC 나노초를 그대로 쓰고 ADT 환산을 \texttt{window\_note}에 병기했다. 합성 flow 31개로 notebook 우선순위를 재현했다.
\item \textbf{매처 확장.} peer 측 payload·패킷 수 상한/하한, 공격 측 최대 payload 길이·총 payload 제외 조건 5개를 \path{scripts/v7/exp94/run_pcap_cic2017.py}의 \texttt{EvidenceRuleSet}에 구현했다. 목요일 portscan round 3의 benign 배경 제외(Fwd Packet Length Max 408, payload 176·20514)는 ``매칭 안 됨 → background''로 처리한다.
\item \textbf{3상태 라벨.} confirmed(창·endpoint·증거), unresolved(창·endpoint만: Attempted 범주 또는 증거 조건 실패; label None, benign으로 보내지 않음), background(규칙 미매칭 → benign), boundary.
\item \textbf{분할.} capture$\times$family 안에서 시작 시각 순 70/15/15. EXP93의 5-tuple hash 분할과 달리 같은 5-tuple group이 train/test에 걸칠 수 있으며 그 수를 기록한다. 보존 상한은 기본 없음(전량).
\item \textbf{두 view, 같은 flow.} flowstats-v1(모든 패킷에서 계산한 CICFlowMeter류 통계 45개, PCA 없음)과 netfound-v2-small(512 → PCA 64). XGB·TabPFN이 두 view에서 같은 flow ID·분할·라벨·n개 표본을 받는다. 이것이 EXP92에서 계획한 2$\times$2다.
\item \textbf{3층 감사.} L1 flow 전체 signature(통계 + 전체 burst 토큰), L2 tokenizer 출력(ms iat, 12버스트$\times$6패킷 절삭), L3 모델 입력 vector(통계 / PCA). 층마다 전체·test의 cross-label group과 행, train$\to$test 중복률, oracle 상한을 저장한다.
\item \textbf{smoke test.} CIC2018 02-14·03-02 capture 2개(307,139 flow)로 corpus → 두 view → 감사 → few-shot 8 job을 끝까지 실행했다. 라벨 상태 분포는 background 200,868 · confirmed 104,080 · unresolved 2,177 · boundary 13. 3층 감사는 L1 7 group → L2 94 group → netFound PCA 81 group으로, tokenizer 절삭이 충돌을 만드는 것을 그대로 보여줬다(oracle 정상 포함 99.94\% → 97.9\% → 98.9\%). 수치는 코드 검증용이며 결과로 쓰지 않는다.
