\section{한눈에 보기}
\textbf{무엇을 했나.} 잔여 flow는 닫힌 연결의 꼬리 패킷이 만든 패킷 1--2개짜리 flow다. 이를 네 방식으로 처리했을 때 충돌 수를 세고, 삭제 조건의 few-shot 점수를 EXP94와 짝지어 비교했다.

\textbf{무엇을 알았나.}
\begin{itemize}
\item 잔여 flow를 없애면 netFound 입력 충돌이 110,324개에서 43,066--43,380개로 줄고, 세 처리 방식의 차이는 최대 314개다.
\item 같은 PCA와 같은 학습 행으로 비교하면 잔여 삭제의 few-shot 변화는 정상 포함 n=50에서 TabPFN $-$0.5 pp, XGB $-$0.1 pp다. 잔여 삭제는 충돌을 줄이지만 few-shot 점수를 바꾸지 않는다.
\item 전체 9종에서 netFound+TabPFN n=50은 58.8로 CSV 53.6보다 높다. 최근 60초 포트 수를 붙이면 60.2가 되고 validation에서도 2.3 pp 오른다. 원본 seq 표시는 효과가 불분명하다.
\item 최근 60초 포트 수는 충돌 flow를 43,380개에서 964개로 97.8\% 줄이지만 점수 상승은 작다. 충돌 flow의 98.2\%가 Portscan이고, TabPFN은 이 class를 이미 97.3\% 맞히고 있었다.
\item 패킷 2개 이하 flow는 지울 수 없다. 남은 충돌의 99.7\%가 여기에 있지만 Portscan의 88.4\%도 여기에 있다.
\item 첫 실행의 큰 변동은 삭제 효과가 아니라 표본 재추첨과 PCA 재적합에서 왔다. 공격만 과제의 netFound+XGB 변화는 같은 PCA에서 $-$0.9 pp 이내이고, PCA를 다시 맞추면 $-$3.7 $\sim$ $-$11.6 pp다.
\end{itemize}

\section{설정}
\begin{itemize}
\item 기준 실행: \texttt{tabpfn/results/v7/exp94/20261104\_104228\_pcap\_cic2017\_9faba40e}.
\item 잔여 flow 판정: 직전 flow가 RST나 양쪽 FIN으로 닫힌 뒤 0--2초 안에 시작, 패킷 2개 이하, payload 0, 첫 패킷에 SYN 없음. 284,600개이고 EXP94 분석값과 일치한다.
\item 네 옵션: 그대로 둠, 삭제, 삭제 + 꼬리 수(직전 flow에 잔여 패킷·RST·FIN 수 열 추가), 직전 flow에 합침(라벨은 합치기 전 값 유지).
\item 합침은 원본 PCAP을 재생해 만들었다. 다섯 캡처 모두 flow ID, 꼬리 패킷 수, 제외 ACK 수가 EXP94와 일치했다. 합친 입력은 재인코딩하지 않았다.
\item few-shot: 7종, seed 43--47, n=2,3,5,10,20,50, 정상 포함과 공격만 두 과제, XGB와 TabPFN.
\item 채점: 삭제 후 남은 test 행 하나만 쓴다. 정상 포함 319,814행, 공격만 76,103행이다. EXP94는 저장된 예측을 같은 행으로 다시 계산했다.
\item 짝지은 실행은 EXP94가 고른 학습 행을 그대로 쓰고 잔여 flow로 뽑힌 행만 같은 자리에서 교체했다. n=50에서 350행 중 평균 7행, 300행 중 평균 4.2행이다.
\end{itemize}

추가 열을 붙인 입력의 feature 충돌 flow는 잔여 삭제 후 43,380개(2.04\%)에서 원본 seq 표시 42,571개(2.00\%), 최근 60초 포트 수 964개(0.05\%), 둘 다 302개(0.01\%)다. 입력마다 가장 많은 라벨을 골라도 틀리는 flow는 212, 64, 26, 17개다. 원본 seq 표시의 충돌 수가 거의 그대로인 것은 라벨이 섞인 입력의 flow를 전부 세기 때문이다. EXP94 분석의 1,143개는 포트 수에 잔여 flow를 포함한 초기 열 기준이고, 위 값은 few-shot에 넣은 열 기준이다.

\section{근거가 뒷받침하는 해석}
\begin{itemize}
\item 잔여 flow는 충돌의 주원인이지만 few-shot 점수의 주원인은 아니다. 같은 PCA에서 n$\ge$10의 변화는 대부분 seed 표준편차 안에 있고 부호도 섞여 있다.
\item 이전에 보고한 n=50의 +0.5--1.4 pp는 test에서 잔여 행을 뺀 채점 효과다. 예를 들어 netFound+TabPFN은 EXP94 전체 행 71.6에서 같은 행 72.1이 된다.
\item PCA 재적합은 축을 바꿔 XGB에 큰 변동을 준다. 공격만 과제에서 TabPFN은 변화가 작고 XGB만 크게 움직이므로, 축 방향 분할의 민감도로 보인다.
\item 처리 방식은 충돌 수로 구분되지 않는다. 충돌만 보면 삭제로 충분하다.
\item 남은 충돌은 flow를 잘못 만든 결과가 아니라 패킷이 적은 실제 연결이다. flow 안에 없는 정보는 flow 경계로 만들 수 없어서, 같은 두 IP의 다른 flow를 참고하는 열이 충돌을 줄인다.
\item 최근 60초 포트 수의 스캔 구분 효과는 XGB에서 확인된다. n=50 Portscan F1이 94.2에서 98.5로 오른다. TabPFN은 97.3에서 97.7로 변화가 작다.
\item TabPFN n=50의 test 상승 +1.40 pp는 스캔 효과로 읽지 않는다. class별 몫은 web 65.5\%, heartbleed 22.8\%, Portscan 3.3\%이고, web과 heartbleed의 test는 16행과 2행이다.
\item 충돌 감소가 점수로 그대로 이어지지는 않는다. 충돌 flow 43,380개를 입력마다 가장 많은 라벨로 정하면 212개만 틀리므로, 없앨 수 있는 오류의 상한이 처음부터 작다.
\item 원본 seq 표시는 seed 편차 안에 있어 효과를 말할 수 없다.
\end{itemize}

\section{미검증 설명과 한계}
\begin{itemize}
\item 삭제 + 꼬리 수와 합침의 few-shot은 평가하지 않았다. 사용자 판단으로 충돌 집계까지만 수행했다.
\item 합침의 netFound feature 충돌은 재인코딩을 하지 않아 측정하지 않았다.
\item 같은 PCA 조건의 PCA는 잔여 flow가 포함된 train 행으로 맞춘 EXP94 값이다.
\item 추가 정보는 few-shot으로만 평가했고 전체 라벨 학습과 세션 교차 검증은 하지 않았다.
\item 두 추가 정보를 함께 붙인 조건은 충돌 수 302개만 세었고 few-shot은 실행하지 않았다.
\item validation 상승 +2.28 pp의 class별 구성은 확인하지 않았다.
\item 9종 평가의 inf, heartbleed 점수는 test 6개, 2개라 해석하지 않는다. 7종 macro-F1은 9종 모델에서 74.9로 7종 모델의 71.6보다 높지만 변별력 향상으로 읽지 않는다. bf 정답은 1,047개를 유지하고 bf 오탐이 472개에서 125개로 줄었는데, 7종 모델의 bf 오탐 중 282개(59.8\%)는 9종 모델에서 inf나 heartbleed로 예측된다. 오탐이 다른 class로 옮겨 간 몫이 크다.
\item PCA 민감도의 원인이 축 회전이라는 설명은 추정이고 별도 실험으로 확인하지 않았다.
\end{itemize}

\section{다음 개선안}
\begin{itemize}
\item 데이터 정의로는 잔여 flow 삭제를 채택한다. 충돌이 줄고 소수 class 손실이 없기 때문이다.
\item 입력에는 최근 60초 포트 수를 채택 후보로 두고 다른 데이터와 세션에서 일반화를 확인한다.
\item flow 단위를 같은 IP 쌍의 시간 구간으로 넓히는 방법은 실험하지 않았다. 최근 60초 포트 수가 이 방향의 가장 단순한 형태다.
\item 비교 실험에서는 PCA를 고정하거나 PCA 변동을 함께 보고한다.
\item 소수 class 개선은 잔여 처리와 별도로 다룬다. bf, bot, web 오탐은 잔여 flow가 아니라 정상 세션에서 나온다.
\end{itemize}
