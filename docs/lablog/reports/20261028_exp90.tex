\reporttitle{2026-10-28}{EXP90: 소수 라벨을 공유하는 TabPFN 전문가 구조 탐색}
\subsection{핵심 질문과 수행 상태}
TabPFN을 포함한 전문가 구조가 동일한 라벨 예산의 단독 모델과 단순 평균을 넘어 공격 분류를 개선하는지가 본 실험의 핵심 질문이다. 기존 EXP89의 TabPFN·XGB 비교만으로 제안 구조의 효과를 입증할 수 없다는 사용자 지적을 출발점으로 삼는다. 연구 버전은 승인된 v7을 유지하고 새 모델 후보를 EXP90에서 탐색한다. 실행 시작은 2026-10-28T00:41:25.303838+\allowbreak{}09:00이며 문서 작성 시각은 2026-10-28T05:58:36.259421+\allowbreak{}09:00이다.

실행 ID는 20261028\_\allowbreak{}004124\_\allowbreak{}shared\_\allowbreak{}context\_\allowbreak{}experts\_\allowbreak{}overnight\_\allowbreak{}227bdd85이다. 현재 상태는 전체 조건 실행 및 독립 검증 완료이다. 구성과 계수는 각 조건의 test 예측 전에 고정하고 성능을 본 뒤 후보를 수정하지 않는다. 이 기록의 비교와 후보 순위는 탐색 결과이며 영어 논문이나 발표자료에 자동 채택하지 않는다.

\subsection{기존 구조의 병목과 새 가설}
기존 TAILGUARD 구현은 라벨을 Global·expert·route·tune·cal 역할로 나눴다. 이전 EXP82의 ToN 점검에서는 695개 Global의 52.89\%와 전체 1,700개 PFN의 66.61\%가 비교됐고, 당시 제안 출력은 Global과 같았다. 이 수치는 정제 후 데이터와 당시 표본 구성의 결과여서 EXP90 점수와 직접 차감하지 않는다. 이번 설계는 라벨 분할로 Global의 정보를 줄이지 않고 모든 확보 사례로 Global을 다시 맞춘다.

전문가는 같은 라벨을 재사용하면서 입력 표현 또는 분류 과제를 바꾼다. 입력을 달리한 전문가가 상보적인 오류를 내는지, 정상/\allowbreak{}공격과 공격 종류를 분리하면 정상 오탐을 줄이는지, 선택기가 실제 수정 이익을 남기는지를 각각 검증한다. 기존 residual 군집·S/\allowbreak{}V 구조를 그대로 재현한 실험은 아니며 제안 모델의 교체 가능한 구조 후보를 평가한다. 기존 제안 대비 개선을 확정하려면 향후 동일 표본·동일 예산에서 직접 재실행해야 한다.

\subsection{문헌과 설계의 연결}
BoostPFN은 PFN context를 약한 학습기로 보고 잔차에 따라 후속 context의 추출 가중치를 바꿨다. 이번에는 큰 pool에서 잔차 표본을 추가하지 않고 이미 받은 소수 라벨을 공유한다. 따라서 BoostPFN 재현이나 신규 부스팅 알고리즘으로 부르지 않는다. 단순 평균보다 학습된 결합이 나은지를 별도 비교하는 설계 원리만 참고했다. https:/\allowbreak{}/\allowbreak{}arxiv.org/\allowbreak{}abs/\allowbreak{}2503.01256

LoCalPFN은 근접 사례 검색과 가중치 fine-tuning을 결합했다. 이번에는 매 query마다 context를 검색하거나 backbone을 fine-tuning하지 않고 고정된 전문가들을 재사용한다. 검색·학습을 생략한 동등한 LoCalPFN 구현이라는 의미는 아니다. 속도 이점도 측정 전에는 주장하지 않는다. https:/\allowbreak{}/\allowbreak{}arxiv.org/\allowbreak{}abs/\allowbreak{}2406.05207

TabFM+\allowbreak{}는 여러 입력 표현과 앙상블·보정을 결합했다. 이번 log view는 그 방향을 참고한 자체 실험이며 TabFM의 모델이나 32-view 절차를 재현하지 않는다. DistPFN은 학습 context prior와 test posterior의 차이를 보정했다. 이번 실험은 실제 test prior를 선택기에 전달하지 않으며 batch posterior 기반 보정도 수행하지 않는다. https:/\allowbreak{}/\allowbreak{}arxiv.org/\allowbreak{}abs/\allowbreak{}2609.37959 https:/\allowbreak{}/\allowbreak{}arxiv.org/\allowbreak{}abs/\allowbreak{}2605.04363

\subsection{데이터·라벨 예산·평가 범위}
원래 outer split의 CIC2018·ToN-IoT를 사용하고 전역 충돌 정제를 적용하지 않는다. EXP89와 같은 46개 float32 특징, family 라벨, nan-to-num 처리와 공격 학습 행 ID를 유지한다. 여기서 정제 전은 충돌 행 제거만 끈 버전이며 PCAP나 원래 CICFlowMeter 특징 버전으로 바꿨다는 뜻이 아니다. 같은 벡터의 다른 라벨도 이번 train과 test에 남아 있다.

공격 클래스당 n은 2·3·5·10·20이고 seed는 43·44·45다. 정상 n개 조건은 EXP89와 동일하며 정상 750개 조건은 기존 정상 20개에 같은 train pool의 730개를 추가하고 n에 따라 바꾸지 않는다. 같은 조건의 모든 모델은 동일한 행 ID와 라벨 예산을 받으며 별도 검증 라벨을 추가하지 않는다. 신규 공격만 적고 기존 공격 125개를 고정했던 순차 실험과는 다른 최종 다중분류 시나리오다.

선택기 학습에는 정확히 같은 특징 벡터를 하나의 group으로 묶은 out-of-fold (OOF) 예측을 사용한다. n=\allowbreak{}2·3은 2-fold, 그 외는 3-fold이며 fold 경계의 동일 벡터 누출을 막는다. 특정 클래스가 하나의 group에만 있으면 해당 fold 학습에서 클래스가 사라질 수 있고 그 클래스 확률을 0으로 정렬한다. 이 경우를 조용히 제거하거나 추가 라벨로 보완하지 않고 아래에 기록한다.

고정 패널은 정상 최대 100,000개와 공격 클래스당 최대 20,000개를 무작위 추출하고 같은 데이터셋의 모든 조건에 공유한다. 각 클래스의 전체 test 수/\allowbreak{}패널 수를 가중치로 삼아 혼동행렬을 추정하지만 패널 F1은 전체 test의 정확한 값이 아니다. 전체 평가는 사전에 정한 정상 750개·n=\allowbreak{}5/\allowbreak{}20·3 seed·2 데이터셋의 12조건에 대해 수행하며 패널 성능에 따라 대상 조건을 고르지 않는다. 전체 평가는 같은 split의 정밀한 계산이고 새로운 독립 test 검증은 아니다.

\subsection{후보 구조와 학습 규칙}
PFN4 Global은 확보한 모든 학습 행을 context로 쓰며 backbone 가중치를 갱신하지 않는다. Log PFN은 같은 행에서 부호를 보존한 log1p 입력을 사용하되 protocol, flag, TTL 및 일부 유형 코드 필드는 변환하지 않는다. 정상/\allowbreak{}공격 PFN gate는 전체 라벨을 이진으로 바꾸고 공격 PFN specialist는 정상 행을 뺀 공격 종류만 학습한다. 계층형 출력은 정상 확률과 공격 확률×공격 종류의 조건부 확률로 결합한다.

학습형 결합 bank는 OOF-selected XGB, PFN4, Log PFN, PFN hierarchy의 네 확률이다. OOF convex는 클래스 균형 negative log likelihood (NLL)와 균등 가중치 기준 L2=\allowbreak{}0.01로 비음수 합 1 가중치를 맞춘다. OOF gate는 각 전문가의 confidence·entropy·margin·정상 확률·Global과의 불일치 및 Global 예측 클래스로 query별 softmax 가중치를 학습하고 L2=\allowbreak{}0.1을 적용한다. Anchored gate는 OOF gate와 전체 Global을 50:50으로 섞어 Global을 명시적으로 유지한다.

XGB OOF는 depth 8/\allowbreak{}3과 min-child-weight 1/\allowbreak{}0.1의 네 설정 중 클래스 균형 OOF NLL로 선택하고 나머지는 300 trees, learning rate 0.05, subsample/\allowbreak{}colsample 0.8을 유지한다. XGB fixed는 기존 depth 8, min-child-weight 1 설정이다. PFN4는 기존 v3 checkpoint와 4 estimators, CPU context cache, fit-with-cache를 사용하며 subsampling하지 않는다. PFN16은 내부 estimator 수만 16으로 늘린 연산량 비교 기준이며 실제 context 크기가 다른 외부 bank와 비용이 완전히 같다고 가정하지 않는다.

모든 결합 계수는 OOF 예측에서만 학습하고 test 라벨·실제 test prior는 입력하지 않는다. 현재 gate는 이미 계산한 네 전문가 확률을 사용하므로 expert를 부르기 전 선별하는 비용 절감 구조가 아니다. test-time 전문가 계산을 모두 지불하며 sparse routing이나 S/\allowbreak{}V 속도 개선을 주장하지 않는다. 가중치 fine-tuning 없이 바뀌는 것은 context, 입력 표현, XGB 및 결합 계수다.

\subsection{지표와 비용의 의미}
공격 Macro-F1은 정상 포함 평가에서 각 공격 클래스 F1의 평균이며 정상에서 유입된 false positive를 포함한다. 정상 false positive rate (FPR)와 공격 탐지 recall을 함께 제시한다. 정상 정답 행을 제외한 공격-only 지표는 같은 예측에서 계산한 보조 진단이며 정상 출력 열을 지우거나 확률을 재정규화하지 않는다. 평균과 표준편차는 고정 split에서 세 표본 seed의 변동이다.

OOF 준비, 최종 fit/\allowbreak{}cache 준비, 구성요소별 추론 비용을 분리한다. 학습형 결합에는 필요한 모든 OOF 학습과 결합 최적화 비용을 더한다. 추론 시간 표는 필요한 모든 구성요소의 합이며 여러 방법을 한꺼번에 계산한 공통 결합 처리 시간은 별도 원시 기록에 남긴다. sparse 호출이 없는 현재 구현의 비용을 Global 단독 비용으로 표시하지 않는다.

\subsection{해석의 범위와 다음 개선안}
Global의 라벨을 유지하는 설계는 기존 분할 구조의 정보 손실을 제거하지만 분류 성능 향상을 보장하지 않는다. 계층형이 개선되면 정상 gate와 공격 종류 specialist의 분리 효과를 all-XGB 및 PFN gate+\allowbreak{}XGB 대조로 확인해야 한다. View mean이 학습형 gate와 비슷하거나 더 좋으면 선택기를 복잡하게 만드는 대신 입력 표현의 상보성을 우선 검증해야 한다. PFN16이 같은 수준이면 단순 estimator 증가 대비 새 구조의 추가 가치를 다시 평가해야 한다.

OOF 선택기가 개선되지 않으면 극소수 공격의 검증 예측이 불안정한 것이 한 설명 후보지만 결과만으로 원인을 확정하지 않는다. 다음 단계는 기존 충분한 정상·공격으로 선택기를 먼저 개발하고 신규 공격 라벨만 소량 제공하는 분리 실험, 정상 오탐 제한을 명시한 선택 목적, 동일 벡터 그룹 기준 외부 split 및 별도 IDS 데이터 검증이다. 이런 후속 설계에서 추가 개발 라벨을 공짜로 취급하지 않고 별도로 계산해야 한다. 현재의 query별 결합은 모든 전문가 결과가 필요하므로, 성능 이익이 남는 경우에만 사전 호출기를 증류해 실제 비용 절감을 검증한다.

원래 test는 여러 선행 실험에서 이미 관찰한 벤치마크이고 원본 행 ID만 train과 분리돼 있다. 동일 벡터가 outer train/\allowbreak{}test에 남아 있을 수 있으며 group OOF만으로 외부 누출 가능성이 제거되지 않는다. 동일 특징의 다른 라벨은 이 특징만 보는 결정적 모델로 완벽하게 동시에 분류할 수 없으므로, 어려운 충돌 사례를 삭제한 점수를 일반 운영 성능으로 해석하지 않는다. 세 seed의 평균 차이는 실제 수집환경 일반화나 통계적 유의성을 입증하지 않는다.

이 결과로 영어 원고의 TAILGUARD 구조·제목·주장을 바꾸지 않는다. 다음 제안은 후보의 실제 이익, 정상 오탐, 희귀 공격 precision, 단순 대조군 및 계산량을 함께 본 뒤 구체화한다. 모델 실행 성공과 논문 근거 채택은 구별한다.

\subsection{실행 전 구현 검증과 정정}
작은 CIC2018 실행에서 같은 벡터의 group이 한 fold에 몰리면서 특정 클래스가 OOF 학습에서 빠지는 조건을 실제 확인했다. 최초 simplex 최적화는 그 클래스의 0 확률과 계층 결합의 극소수 epsilon 차이 때문에 수렴하지 않았다. 본 실행 전에 모든 전문가의 정답 확률에 같은 수치 바닥 1e-9를 적용하고 softmax 계수 최적화로 바꿨다. 수정은 test 성능을 보고 선택한 것이 아니며 실패한 smoke 실행과 수정 후 실행은 별도 실행 ID로 보존한다.
