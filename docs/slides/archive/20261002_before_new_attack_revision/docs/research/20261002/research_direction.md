# r06 · 희소 라벨 공격 탐지를 위한 context 설계

갱신: 2026-10-02. 사용자 피드백 및 후속 답변을 반영한 연구 방향. **이 문서 작성으로 새 실험을 실행하지 않았다.**

후속 확정(같은 날): 사용자가 신규 라벨의 뜻을 **기존에 없던 공격 종류의 도입**으로 명확히 했고, 실제 클래스 최초 출현 순서를 보존한 실행을 승인했다. 따라서 아래의 초기 시나리오 개념안과 미정 사항 중 이와 상충하는 부분은 역사적 초안이다. 현재 실행은 [EXP69 protocol](exp69_protocol.md)을 따른다. 초기 정상+기존 공격 → 신규 공격 사례 추가를 반복하며, 동일 누적 라벨에서 XGBoost 전체 재학습과 TabPFN context 확장을 비교한다. EXP69는 실행 중이며 결과 우위는 아직 판단하지 않았다.

## 목적과 주장

목적은 전체 Macro-F1을 계속 높이는 것이 아니라 **라벨 사례가 적은 공격을 Benign 및 다른 공격과 더 잘 구분하는 것**이다. TabPFN이 처리할 수 있는 제한된 context에 어떤 공통·전문 사례를 담아야 이 목적에 도움이 되는지가 연구 질문이다. 기존 탐지 성능과 Benign 오탐을 함께 확인한다.

TabPFN은 사전학습된 backbone이 라벨 context를 조건으로 추론한다는 점에서 후보가 된다. 사례 구성을 바꿀 때 backbone 재학습이 필요 없다는 구조적 특성과, 실제 성능·운영 비용에서 이득이 있다는 주장은 구분한다. XGBoost 대비 소수 라벨 성능과 총비용 우위는 아직 입증하지 않았다. XGBoost는 강한 비교 기준이며 전체 재학습 외에 추가 학습도 가능하다.

- [TabPFN 공식 구현](https://github.com/PriorLabs/TabPFN): 현재 repo의 새 기본 모델과 달리, 이 프로젝트 실험은 저장된 v3 설정을 유지
- [XGBoost 추가 학습 예제](https://xgboost.readthedocs.io/en/stable/python/examples/continuation.html)

## 사용자 확인으로 확정된 범위

- `OOM`은 `OOD`: 학습 분포 밖 데이터·새 공격을 의미
- 실제 수집 timestamp를 그대로 재현하는 것은 필수 아님
- 소수 라벨 확보 전후의 적응 성능 비교도 필수 목적이 아님
- 순차 공격 도입은 **평가 시나리오의 축**. Context를 온라인으로 갱신할지는 별도 선택
- 학습 라벨이 적은 공격과 학습에서 전혀 보지 못한 공격을 구분
- 기존 Claude 실행의 시나리오(EXP68)는 사용자가 의도한 설계로 채택하지 않음

## 시나리오 개념안과 아직 정하지 않은 것

Benign과 일부 공격이 섞인 배경에서 공격을 순차적으로 도입하고, 혼합 비율이 달라질 때 각 공격의 탐지 성능을 관찰한다. 이는 자연 수집 시간을 재현했다고 주장하는 실험이 아니라 통제된 도입 시나리오로 구성할 수 있다. 나중에 평가에 등장한 공격도 초기 학습에는 소수의 라벨 사례가 있을 수 있다. 이 경우 단순히 나중에 등장했다는 이유로 OOD로 부르지 않는다.

아직 정하지 않은 사항: 대상 희소 공격의 정의·라벨 수, 초기 학습 데이터, 도입 순서와 구간, 혼합 비율, Global/expert/S/V의 고정·갱신 여부, context 전체 예산. `5구간`, `첫 10%`, `클래스당 50라벨` 등 기존 구현의 수치를 이번 설계에 자동 상속하지 않는다.

현재 모델과 context를 고정하면 같은 표본의 개별 예측은 평가 순서를 바꿔도 동일하다. 따라서 단순 재정렬만으로 시간 적응 성능을 주장할 수 없다. 순차 시나리오에서는 구간별 공격 등장·혼합 변화에 따른 탐지와 오탐을 보는 목적을 명시한다. 적응 자체를 평가하려면 별도의 갱신 규칙을 정의해야 한다.

온라인 갱신을 나중에 추가하는 경우에만 예측 → 라벨 확보 → 이후 표본에 갱신 적용의 인과 순서를 엄수한다. 자연 시간 흐름을 주장한다면 초기 학습·검증에도 미래 시점 행이 없어야 한다.

## 주장에 필요한 근거

| 질문 | 통제할 조건 | 볼 결과 |
|---|---|---|
| 희소 공격을 더 잘 구분하는가? | 동일한 보유 라벨, 동일 평가 표본, 학습 단계에서 정한 희소 클래스 | 공격별 Precision/Recall/F1, Benign 오탐, 기존 공격 성능 |
| Context 구성이 기여하는가? | 전체 context 크기, 추가 학습 데이터, backbone·추론 설정 | Global/단순 구성/제안 구성의 차이 |
| Expert와 S/V가 필요한가? | 유용한 구성을 validation에서 정한 뒤 같은 조건으로 비교 | 요소 제거 시 성능·교정·훼손·호출 변화 |
| 비용 면의 선택 근거가 있는가? | 같은 하드웨어와 라벨 정보, 캐시·병렬 조건 명시 | 구성·학습·적재·추론 비용과 메모리 |
| OOD까지 확장되는가? | 학습에 없는 공격 또는 별도의 분포 변화 | 미지 인지와 라벨 후 적응을 별도 평가 |

혼합 비율·출현 클래스가 달라지면 Precision/F1/Macro-F1도 달라진다. 각 구간의 support와 prevalence를 함께 보고하고, 구간 간 Macro-F1을 그대로 성능 상승으로 해석하지 않는다. Benign 오탐률은 `실제 Benign 중 공격으로 예측한 비율`이다.

## 현재 결과의 역할

EXP61·63은 정제 데이터에서 수행한 단일 seed 43의 탐색 근거다. 대표 K=4는 기존 대표 설정을 유지하며 test 최고 K로 치환하지 않는다.

| 구성 | CIC2018 Macro-F1 | ToN Macro-F1 |
|---|---:|---:|
| XGBoost, 같은 C0 100k | 0.7821 | 0.6983 |
| Global TabPFN | 0.7824 | 0.6796 |
| Anchor + residual expert, K=4, S/V 포함 | 0.7824 | 0.7617 |

ToN K=4의 Scanning F1은 0.0394→0.8587. CIC2018은 선택된 정책의 expert 호출 0건. ToN 호출률 100%는 **정책상 호출률**이며 출력 채택률은 1.23%. 저장된 예측에 적용한 정책 수치로 실제 조건부 추론 시간을 대체하지 않는다. 제안 구성은 Expert/Route 풀의 추가 라벨 정보를 사용하므로 위 표로 같은 100k 예산 우위를 주장하지 않는다.

이 결과는 residual 기반 context가 일부 공격에 유효할 수 있음을 보여준다. 모든 희소 공격의 개선, 특정 혼동의 인과적 원인, 시간 적응의 효과는 입증하지 않는다. 최근접 거리만으로 분류 불가능·라벨 모순·분포 변화의 원인을 확정하지 않는다.

## 보존하되 이번 주장에 자동 채택하지 않은 결과

EXP64–67은 기존 Claude의 별도 탐색 실행으로 보존한다. 방법 충실성·부분집합 평가·정보량·최적화 비용이 서로 달라 단일 승패표로 정리하지 않는다. EXP68은 사용자가 의도한 시나리오가 아니므로 현재 발표 근거에서 제외한다. 기존 출력 파일은 수정하지 않았다.

EXP68 코드 검토 메모: 같은 구간에서 정답 클래스별로 라벨 사례를 선택한 뒤 그 구간의 나머지를 평가한다. 따라서 엄격한 도착 순서 기반 예측을 입증하지 못한다. `benign_fpr`는 실제로 공격을 Benign으로 예측한 비율이어서 Benign 오탐률로 인용하지 않는다. 원본 기록의 이름을 바꾸지 않고 제외 근거를 남긴다.

## 후속 접근의 위치

Benign 다양화 / tail 합성 / 표현 학습 / context 최적화는 각각 다른 정보 부족을 겨냥한 가설이다. 소수 라벨이라는 목적과 동일 context 예산에서 도움이 되는지 비교한다. 합성은 같은 수의 실제 사례·단순 복제, 표현·context 최적화는 별도 학습 데이터와 비용까지 대조한다.
