# EXP71 · 제한된 과거 사례로 새 공격 반영

2026-10-13 사용자 실행·HTML 보고 승인. 기존 승인 연구 버전 v7에서 실행한다. 신규 연구 버전은 만들지 않는다. 이번 실행은 제한된 과거 조건만 다루고, 누적 전체는 결과 검토 후 같은 stream IDs로 별도 실행한다. Expert·S/V는 제외한다.

두 데이터셋 CIC2018·ToN, seed 43, 단일 TabPFN-v3와 XGBoost를 비교한다. 공격의 최초 출현 순서는 EXP69/70에서 검증한 순서를 유지한다. Benign은 모든 단계에 새 사례를 공급한다. Raw timestamp 재현이나 네트워크 환경 변화 실험은 아니다.

Case 1은 각 공격 1,024행을 배정하되 CIC2018 Web attack만 가용 train 450행으로 제한한다. Case 2는 Case 1의 전체 공격 예산(CIC2018 5,570, ToN 9,216)을 정제 train의 공격 클래스별 빈도 비례로 정수 배분한다. 자연 분포는 공격끼리의 비율이며 Benign을 포함한 전체 자연 분포를 재현하지 않는다. Test 빈도는 배분에 쓰지 않는다.

최종 Benign 75%를 맞춰 CIC2018 16,710행, ToN 27,648행을 공급한다. CIC2018은 초기 포함 5단계에 각 3,342행, ToN은 6단계에 각 4,608행이다. Benign IDs와 단계별 공급은 두 case에서 동일하다. 최종 공급 총량은 각각 22,280행, 36,864행이다. 공격별 공급량과 시점이 case 간 달라지므로 단계별 업데이트 규모도 함께 보고한다.

매 단계 직전 학습 집합에서 최대 4,096행을 보존하고 이번 단계의 신규 Benign·공격 사례를 모두 더한다. 따라서 4,096은 전체 context 상한이 아니라 과거 보존 상한이다. 이미 버린 과거 사례는 다시 가져오지 않는다. 과거 선택은 Benign 목표 75%와 해당 case의 공격 비율을 사용하며, 직전 집합의 클래스별 가용량을 넘을 수 없다. 이미 도입한 클래스는 최소 1행을 유지한다. 최소 보존 때문에 자연 비율이 보정된 클래스와 보정 전후 quota를 기록한다. 가용량 부족 시 전체 보존 예산을 다른 클래스로 재배분한다.

두 모델에는 같은 학습·평가 IDs를 제공하고 미래 클래스가 context·전처리에 들어가지 않는지 검증한다. 모델 설정은 EXP69/70과 같다: TabPFN v3_20260417_multiclass, ensemble 4, frozen backbone, fit_with_cache, CPU cache; XGB 300 rounds, depth 8, lr .05, CUDA hist. GPU worker는 하나씩 실행해 비용 경합을 피한다. 초기 구축과 후속 갱신을 구분한다.

갱신 시간은 과거 선택·입력 구성, 모델 생성, XGB 학습 또는 TabPFN 전처리·context 캐시 구성의 GPU 동기화된 경과 시간 합이다. 최초 checkpoint 적재는 초기 fit에 포함될 수 있다. 갱신된 모델이 메모리에서 준비되는 시점까지 측정하며 결과 파일 기록, 운영 배포·모델 직렬화, 전체 test 추론은 포함하지 않는다. 첫 추론 batch 지연과 전체 test 추론 시간은 별도로 저장한다. Test 전처리는 기존 정제 기준을 따르고 별도 tuning은 수행하지 않는다.

평가는 기존 정제 test 중 도입한 클래스의 전체 행을 사용한다. 클래스별 P/R/F1·support와 Benign 오탐을 저장한다. 이전 클래스 유지 평가는 새 클래스의 정답 행만 제외하고 새 클래스로의 오분류는 유지한 동일 과거 표본군에서 계산한다. 갱신 전후 교정·훼손도 같은 행에서 비교한다. 동일 feature가 context에 있는 test 행을 제외한 보조 평가를 제공한다. 기존 개발 holdout·단일 seed라는 범위는 유지한다.

재현을 위해 단계별 유입 IDs, 보존 IDs, 학습 IDs, 평가 IDs, 확률, 예측, confusion matrix, 비용 phase, checkpoint·입력·코드 hash를 보존한다. 준비된 공급 stream을 나중에 `--history-mode cumulative --stream-root EXISTING_RUN`으로 재사용할 수 있다. 실행 성공과 논문 주장 채택은 구별한다.
