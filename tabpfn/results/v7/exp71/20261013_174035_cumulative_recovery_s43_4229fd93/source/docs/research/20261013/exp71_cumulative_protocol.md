# EXP71 · 같은 공급 사례의 누적 전체 비교

2026-10-13 사용자가 제한된 과거 결과를 검토한 뒤 “keep going”으로 후속 실행을 요청했다. 승인된 연구 버전 v7 / EXP71 안에서 누적 전체 조건을 별도 run으로 실행한다. 기존 제한된 과거 결과는 보존한다. 10만 행 공급 확대는 이번 누적 비교 이후의 단계로 남긴다.

기준 실행은 `tabpfn/results/v7/exp71/20261013_140543_bounded_uniform_natural_s43_731a4a80`이다. 이 실행의 준비된 train bank, 단계별 신규 공급 IDs, 정제 test 전체를 그대로 사용한다. 공격 균등 / 공격 내 자연비율, Benign 75%의 단계별 공급, 최초 출현 순서, seed 43, 두 모델의 설정을 유지한다. 미래 클래스의 사례는 최초 도입 전에 사용하지 않는다.

각 단계에서 그때까지 공급된 모든 행을 학습 집합으로 사용한다. XGBoost는 해당 집합으로 새로 학습하고 TabPFN은 같은 집합으로 전처리 및 context 캐시를 재구성한다. 이전 단계에서 버리는 행이 없으며, 최종 입력은 CIC2018 22,280행, ToN 36,864행이다. CLI의 `--history-cap 4096`은 공급 stream의 기존 설정 일치 확인용이며 `--history-mode cumulative`에서는 보존 상한으로 작동하지 않는다.

이번 비교는 과거 보존 정책을 바꾼 결과다. 총 입력량뿐 아니라 클래스별 잔존 수와 비율도 변하므로 효과를 데이터 양 하나로 설명하지 않는다. 특히 ToN 자연비율의 신규 MitM은 양쪽 모두 같은 11행, Ransomware 최초 공급은 같은 8행이다. 마지막 단계의 Ransomware 보존은 제한 조건 1행과 누적 조건 8행으로 달라진다.

갱신 시간은 동일한 GPU 동기화 구간에서 입력 구성·모델 생성·fit/cache의 합을 측정한다. 초기 구축은 별도이며 test 추론과 결과 기록·배포 비용을 갱신 시간에 합산하지 않는다. GPU 모델 worker는 순차 실행해 비용 경합을 피한다. Seed는 단일이며 비용은 단계별 1회 관측값이다. 실제 규모에 따른 비용 차이는 측정 후 판단한다.

두 모델 및 두 보존 정책 사이에 test IDs가 일치하는지, 누적 조건에서 모든 과거 공급 IDs가 남았는지, 각 단계의 신규 공급이 기준 실행과 같은지 검증한다. 저장한 확률·예측으로 클래스별 P/R/F1, 정상 오탐, 동일 기존 test 행의 유지·교정·훼손을 재계산한다. 완료 후 10/13 HTML 탭에 제한/누적 비교와 소표본 공격의 해석을 추가하고 연구 기록을 남긴다.

2026-10-13 시스템 재부팅으로 첫 누적 실행이 중단되었다. 사용자가 NVIDIA 복구 후 재개를 요청하여 `recover_exp71.py`로 같은 v7/EXP71 안에 별도 복구 실행을 등록했다. 첫 실행과 손상 파일은 덮어쓰지 않는다. CIC2018 두 배정의 두 모델 및 ToN 균등의 두 모델은 완료된 32단계를 복사하고, ToN 자연비율은 두 모델 모두 초기 단계부터 다시 실행한다. TabPFN의 초기 cold fit와 후속 warm fit 측정이 섞이지 않도록 부분 worker에서 바로 이어 측정하지 않는다.

복구 후 커널은 7.0.0-38, NVIDIA 드라이버는 580.178.04이다. 기존 제한 조건과 복사한 누적 결과는 커널 7.0.0-31, 드라이버 580.173.02에서 측정했다. GPU 모델·Python 패키지·TabPFN 소스·checkpoint의 일치를 검사하고, worker별 환경 및 재사용 출처를 `recovery.json`에 기록한다. ToN 자연비율의 제한/누적 비용 차이는 환경 변경도 포함하므로 보존 정책만의 인과 효과로 해석하지 않는다. 재실행한 초기 두 단계의 예측이 기존 완료 결과와 일치하는지도 별도로 검증한다.
