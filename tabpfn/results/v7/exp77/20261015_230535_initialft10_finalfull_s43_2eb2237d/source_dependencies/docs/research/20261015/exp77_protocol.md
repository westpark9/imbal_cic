# EXP77 · 초기 IDS fine-tuning과 최종 상태 평가

사용자가 요청한 두 가지 수정, 즉 실제 초기 IDS 파라미터 미세조정과 최종 모델의 전체 test 평가를 반영한다. 승인된 연구 버전 v7 안의 새 실험이다. EXP76의 공개 라벨 ID, 클래스 도입 순서, 기존 test를 그대로 사용한다. 초기 1,000개는 정상 750개와 최초 두 공격 각 125개이며, 이후 신규 클래스마다 100개를 추가한다. 최종 라벨 예산은 CIC2018 1,400개, ToN 1,700개다. 모든 검증·보정용 라벨은 이 예산 안에서 배정한다.

## 파라미터 학습과 context

공식 TabPFN 8.2.0의 `FinetunedTabPFNClassifier`로 v3 본체를 AdamW, learning rate 1e-5, weight decay 0.01, 고정 10 epoch로 학습한다. 각 학습 과제는 최대 1,024개 사례의 context/query 분할이며 query 비율은 20%다. 학습 ensemble은 1개, 최종 추론은 4개다. 초기 공개 라벨을 특징 중복 그룹 단위로 약 90:10 학습·검증에 배정한다. 검증 log-loss는 모니터링용이며 epoch나 모델 선택에 test를 사용하지 않는다. 예비 2 epoch 실행의 early stopping은 ToN에서 원래 가중치를 다시 선택했으므로, 본 실행은 사전에 정한 고정 학습량으로 파라미터 갱신 효과를 직접 평가한다. 이는 성능 개선을 보장하는 설정이 아니다.

초기 fine-tuning 완료 checkpoint 하나를 각 context 정책이 공유한다. 이후 누적·FIFO·신규 학습 사례와 유사한 기존 사례 삭제·무작위 삭제·고정 context를 비교한다. 고정 버퍼는 1,000개를 유지하고 기존 클래스당 최소 한 사례를 보존한다. FIFO는 확보 순서의 대리 기준이며 실제 노후화 판정이 아니다. 신규 context는 검증용을 포함한 현재 공개 라벨 전부에서 구성할 수 있다. 가중치 학습과 별도로 추론 context가 현재 라벨 공간을 제공하기 때문이다. 기존 클래스 context 없이 신규 클래스 사례만 넣는 조건을 전체 클래스 분류 방법으로 취급하지 않는다.

대조군은 미세조정 없는 사전학습 PFN의 누적 context와, 매 단계 이전 checkpoint에서 누적 공개 학습 사례로 다시 10 epoch 미세조정하는 PFN이다. 반복 미세조정의 검증 역할은 단계 사이에 유지하며 과거 검증 행을 나중에 gradient 학습에 편입하지 않는다. 매 단계 가중치 digest를 기록하여 초기 미세조정에서는 실제 변화가 있고 context 갱신에서는 변화가 없는지 확인한다.

## 제안 모델과 비교 모델

XGBoost는 동일 공개 라벨로 매 단계 누적 재학습한다. BoostPFN은 기존 프로젝트의 50 learner, learner당 500개 설정으로 누적 재구성한다. DistPFN은 초기 미세조정 후 누적 PFN의 확률에 현재 query 배치 posterior 보정을 적용한 변형으로, 같은 준비 비용과 backbone을 공유한다. LoCalPFN은 사용자 요청에 따라 제외한다. 서로 다른 원 논문의 leaderboard 수치를 옮기는 것이 아니라 기존 프로젝트 구현의 동일 소규모 예산 비교다.

제안 모델은 기존 K=4 anchor/residual expert와 S1V0 선택·검증 구조를 유지한다. 공개 라벨 내에서 Global/expert/route/tune/cal에 40/20/20/8/12%를 특징 그룹 단위로 배정하고 그룹 역할을 단계 사이에 유지한다. 모든 역할에 현재 클래스가 존재하는지와 역할 간 특징 중복이 없는지 확인한다. 별도 10,000개 validation 등의 외부 라벨은 사용하지 않는다. 기존 pretrained backbone을 유지한다. 전체 초기 라벨로 학습한 PFN checkpoint를 이 모델에 그대로 공유하면 route/cal 라벨까지 가중치 학습에 들어가므로 보정 독립성이 훼손된다. 이 때문에 이번 비교는 ‘동일 초기 FT backbone을 쓰는 구조 ablation’이 아니라 ‘동일 공개 라벨 예산의 방법 비교’다. 같은 FT backbone의 구조 효과는 별도 역할 분할을 사전 지정한 후속 과제다.

## 평가와 비용

각 단계에서는 갱신만 수행하고, 모든 클래스가 도입된 마지막 가중치·context·S/V 상태로 기존 test 전체를 원본 파일 순서대로 한 번 예측한다. CIC2018 3,042,473개, ToN 2,271,723개이며 batch 8,192, seed 43, 단일 RTX 4090이다. 과거 단계 예측을 합치거나 단계 F1을 평균하지 않는다. 전체 test Macro-F1, 클래스별 F1, 정상 오탐률, 공격 탐지 recall을 저장하며 공통 특징 중복 제외 집합의 보조 지표도 제공한다.

GPU 동기화한 wall-clock으로 초기 IDS 미세조정, 초기 준비, 후속 갱신 합계, 최종 전체 추론을 분리한다. 초기 FT checkpoint 재사용 정책마다 같은 실측 초기 FT 비용을 회계상 배정한다. Context 선택·삭제 시간은 갱신에 포함하고 디스크 저장·검증 digest·로그는 모델 준비 시간에서 제외한다. 제안 모델은 Global/expert/S/V의 모든 재구성을 갱신에 포함한다. 작은 학습 데이터가 전체 test 추론을 빠르게 만든다고 가정하지 않는다.

1014의 10만 라벨 결과와 EXP76의 단계별 예측 합산 결과는 보존하되, 새 슬라이드의 주 결과를 대신하지 않는다. 최종 상태 평가만으로 중간 단계 망각이나 실제 네트워크 drift 강건성을 입증하지 않는다. 단일 seed 탐색 실험의 관찰과 성능·비용에 대한 일반적 주장을 구분한다. HTML과 Overleaf는 수정하지 않고 원고에는 반영안만 정리한다.
