입력은 1,024행 배치로 수집한다. 유입률은 100행/초 · 1,000행/초 두 값으로 둔다. 단계 끝의 잔여 행도 처리한다.

배치 크기와 유입률은 민감도 분석을 위한 설계값이다. 논문에서 그대로 가져온 값이나 실제 IDS 트래픽률이 아니다.

대기열과 버전

갱신이 밀리면 다음 갱신은 FIFO에서 기다린다. 입력 배치는 수집 완료 시점의 최신 완료 버전에 배정한다. 추론 큐에서 기다리는 동안에는 배정 버전을 바꾸지 않는다.

추론은 별도 FIFO로 처리한다. 마지막 입력 이후 남은 처리시간도 보고한다.

자원 가정: 실제 GPU에서는 측정 간섭을 피하려고 한 worker씩 실행한다. 이 시간을 이용한 재생에서는 갱신 worker와 서비스 worker가 독립된 자원을 가진다고 가정한다. 따라서 갱신과 추론의 GPU 경합·단일 GPU에서 여러 버전 동시 적재의 영향은 포함되지 않는다.

5. 분류 능력과 응답 지연을 함께 읽는다

관점비교할 내용해석
갱신 지연 없는 비교전체·단계별 클래스 P/R/F1, 정상 오탐률각 단계에 맞는 모델이 즉시 준비됐을 때의 분류 능력
갱신 지연 포함실제 배정 버전의 P/R/F1, 구버전 처리량, 공격→Benign 누락새 사례가 반영되기까지의 탐지 영향
공격 종류 식별공격으로 탐지했지만 다른 공격 유형으로 분류한 행공격 자체를 놓치는 것과 구분
응답과 처리량수집·추론 큐·연산을 포함한 행별 평균/p50/p95 응답시간, 입력 종료 후 잔여 처리시간빠른 갱신이 느린 추론을 상쇄하는지, 처리 지연이 쌓이는지

Precision의 FP는 정상과 다른 공격을 포함한 평가 구간 전체에서 계산한다. Tail은 기존 test의 희소성에 연결해 클래스별로 확인한다. 구버전은 새 클래스 이름을 출력할 수 없으므로, 공격→Benign 누락과 공격 종류 오분류를 따로 보고한다. 탐지·유형 식별·학습 및 추론 비용을 함께 보는 근거는 Pragmatic Assessment의 평가 기준이다. [4]

갱신비용 사전 실험의 측정 보완
  • 누적 전체·10만 행·자연/균등 조건을 유지한다. 제한 보존은 도입하지 않는다.
  • 모델 생성·학습/캐시 준비 및 train-only 첫 1,024행 응답을 단계당 3회 측정한다. 재생에는 첫 번째 갱신 측정값을 사용하고 중앙값과 범위는 비용 변동 확인용으로 별도 보존한다.
  • 초기 구축과 이후 갱신을 구분한다. TabPFN은 매 단계 누적 전체의 캐시를 다시 만든다는 점을 기록한다.
  • 실제 test 추론은 배치별로 측정한다. Context 전처리, 캐시, 첫 응답으로 계산이 어떻게 배분되는지 구분하여 해석한다.
  • 실험용 checkpoint 저장·복구, 결과 기록, 프로세스 시작과 사전 데이터 준비는 서비스 연산시간과 구분한다.

검증된 결과는 3절에 수록했다. 기존 갱신 완료 후 성능·비용은 10/13 탭에 보존한다.

DistPFN [7]기반 TabPFN 갱신 + 현재 도착 배치의 posterior 분포로 보정후속 비교 · 이번 큐에서 제외

세 SOTA의 단계별 실행은 원 방법을 반복 적용하는 방식이며, 원 논문이 신규 클래스 증분 갱신 알고리즘을 제안했다고 해석하지 않는다. DistPFN에 전체 미래 test 분포를 제공하지 않는다. 기존 BoostPFN·LoCalPFN 포트는 v1 기반이므로 추후 비교 시 backbone 차이를 명시한다.

7. 근거 논문과 이번 설계에 가져온 부분

  1. INSOMNIA: Towards Concept-Drift Robustness in Network Intrusion Detection · AISec 2021 · §4.2

    새 버전이 준비될 때까지 이전 버전을 사용하는 지연 반영 평가를 참고한다. 본 실험은 논문의 binary DNN·pseudo-labeling을 채택하지 않고 확인된 다중 클래스 사례 공급을 가정한다.

  2. Continuous Learning for Android Malware Detection · USENIX Security 2023 · §4.1–4.3

    라벨 확보·학습 데이터 누적·모델 갱신·후속 구간 평가를 참고한다. 본 실험은 active learning이나 사람의 라벨링 지연을 측정하지 않는다.

  3. TESSERACT: Eliminating Experimental Bias in Malware Classification across Space and Time · USENIX Security 2019 · §4.1–4.2

    미래 정보 접근을 제한하고 구간별 성능을 보는 근거다. 본 실험의 클래스 공개 순서 제어는 실제 timestamp 기반 분할을 대신하지 않는다.

  4. SoK: Pragmatic Assessment of Machine Learning for Network Intrusion Detection · EuroS&P 2023 · Appendix E.3

    정상 오탐·공격 탐지·공격 종류 식별과 학습·추론 비용을 함께 평가한다. 이번에는 그 구분을 지연 포함 재생 결과에 적용한다.

  5. Prior-Fitted Networks Scale to Larger Datasets When Treated as Weak Learners · AISTATS 2025

    BoostPFN의 약한 학습기 결합 구조를 유지해 단계별 모델을 재구성할 수 있다.

  6. Retrieval & Fine-Tuning for In-Context Tabular Models · NeurIPS 2024

    LoCalPFN의 검색과 미세조정을 모두 반영해야 하므로 context 교체만으로 갱신 비용을 계산하지 않는다.

  7. Mitigating Label Shift in Tabular In-Context Learning via Test-Time Posterior Adjustment · ICML 2026

    DistPFN의 posterior 보정은 현재 배치에만 적용한다. 공식 구현의 test posterior 평균 계산 범위를 미래까지 넓히지 않는다.
