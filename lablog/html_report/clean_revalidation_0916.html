02 · CIC2018 · Calibration / 임계값 결정

“최소 30건”은 호출이나 승인 수가 아닙니다.

승인된 후보 중 global 오답 → expert 정답(교정) 또는 global 정답 → expert 오답(훼손)이 발생한 행을 셉니다. 둘 다 정답이거나 둘 다 오답인 행은 포함하지 않습니다.

저장된 77개 후보를 조회합니다. 선택용 cal: 124,856행

훼손 후보는 호출과 승인 사이에서 얼마나 걸러지는가?

동일 calibration · 같은 top-1 후보행 수교정 가능 H훼손 가능 D둘 다 정답둘 다 오답

이 조합을 쓴다고 가정했을 때의 calibration 집계입니다. 최종 test 정책에서는 어느 조합도 채택되지 않아 실제 호출 0건입니다. 호출된 모든 행을 강제 채택했을 때의 H/D와 verifier를 통과한 H/D를 구분합니다.

77개 조합 전체 보기 · 셀 숫자는 교정 + 훼손

행은 호출 임계값, 열은 승인 임계값입니다. 셀을 누르면 위 계산이 바뀝니다. 가장 느슨한 조합도 6 + 3 = 9건이며, 일부는 다른 조건도 위반합니다.

임계값은 어디까지 탐색했는가?

연속 범위 전체가 아니라 11 × 7 = 77개 조합을 평가했습니다. 호출 점수는 행별 expert 점수의 최댓값이고, 승인 점수는 q_hat − q_corr입니다. 비교는 모두 임계값보다 엄격히 큰 값(>)입니다.

호출 임계값: calibration 최대 scorer 점수의 0, 30, 50, 60, 65, 70, 75, 80, 85, 90, 95 백분위수. 실제 최솟값 약 0.000069, 최댓값 약 0.999239입니다.

승인 임계값: 0, 0.25, 0.5, 1, 2, 4, 8. 음수 승인 임계값과 95백분위보다 높은 호출 임계값은 이 실행의 후보에 없습니다. 따라서 “모든 실수 임계값에서 불가능”이라고 결론 내리지는 않습니다.

공통 조건: 호출률 ≤ 35%, 승인 ≥ 200건, H+D ≥ 30건, D/(H+D) ≤ 10%, benign FPR 증가 ≤ 0.0005. 통과 후보 중 실제 weighted NLL gain 합이 가장 큰 조합을 선택합니다. 통과 후보가 없으면 두 임계값을 ∞로 둡니다. 추론 중 30건이 쌓일 때까지 기다리는 규칙이 아닙니다.

36,156건을 승인해도 30건 조건에 미달할 수 있습니다. 기본 표시 조합은 교정 6건, 훼손 0건, 나머지 36,150건은 정답 여부가 같습니다. 따라서 판단 근거가 되는 결정은 6건뿐입니다. 최소 승인 200건은 별도의 조건입니다.

03 · CIC2018 · Gate를 생략한 진단 / 실제 정책과 별도

Scorer의 후보에는 훼손이 많고,
verifier는 교정 후보도 대부분 거절합니다.

막대 길이는 log₁₀(건수 + 1) 눈금입니다. 큰 수와 작은 수를 함께 보이게 했습니다. 정확한 건수는 표를 확인하세요.

가정한 적용 규칙교정 · H훼손 · D의미

Top-1은 각 행에서 8개 expert 중 점수가 가장 높은 하나를 고른 후보입니다. 점수가 낮아도 하나는 정해지므로, 실제 호출 여부는 pre gate가 따로 결정합니다. 이 강제 적용 수치만으로 실제 라우팅의 성능을 판정하지 않습니다. 호출 가능한 영역에서 교정 기회를 얼마나 회수하고 훼손을 얼마나 통제하는지 함께 봅니다.

Scorer: 4,685는 무엇을 놓쳤는가?

정답을 사용한 bank 교정 기회 10,085행 중 top-1이 찾은 것은 4,685행(46.46%)입니다. 동시에 global 정답 553,246행을 틀리는 답도 선택합니다.

클래스별 회수율: infiltration 4,062 / 5,375 = 75.57%, benign 83 / 4,151 = 2.00%. Scorer는 호출 전 expert 후보를 정합니다. 이 표는 호출 gate까지 생략한 진단입니다.

Verifier: 보정량만 줄이면 해결되는가?

선택용 cal 교정 후보 2,816행 중 원시 점수가 양수인 것은 6행입니다. 보정 후에도 6행입니다.

q_corr = 0.0007752. 교정 후보의 원시 점수 중앙값 −1.2168, 교정/훼손 구분 AUC 0.4465. 먼저 원시 점수가 실제 교정을 구분하도록 목표·입력을 검증할 필요가 있습니다.

Test에서 원시 verifier 양수인 815,032행 대부분은 둘 다 정답인 행입니다. 양수 호출 수가 많아도 교정 13건·훼손 106건에 그칠 수 있습니다. 최종 정책의 실제 test 교정·훼손은 여전히 0 / 0입니다.

기존 EXP39 legacy 정책의 별도 재확인

EXP39는 같은 새 bank를 사용하지만 scorer/verifier 설정과 정책 선택 규칙이 다릅니다. 선택 cal 87,399행에서 top-1 교정/훼손 1,599/4,812 → post 양수 2/3, 확인 cal 35,879행에서는 727/2,003 → 2/2입니다. 후보 78개가 모두 support 조건을 통과하지 못했습니다. Full test 최종 macro-F1 0.810653, 채택 0건입니다. 위 EXP31 숫자와 중간 단계를 합치지 않습니다.

04 · CIC2018 · Expert의 입력 구성과 적용 영역

각 expert는 어떤 사례를 보고 답하는가?

Expert의 context = 공통 anchor 12,224행 + 해당 residual 군집에서 고른 전용 block. Residual 숫자를 expert의 추가 입력 feature로 주는 구조가 아닙니다. Residual은 사례를 묶고 고르는 데 쓰고, TabPFN expert에는 선택된 원래 46개 feature와 라벨을 줍니다.

1

Global의 응답을 조사

Expert용 학습 풀 200만 행에서 global의 확률과 residual을 계산합니다. 이미 정답인 행도 포함합니다.

2

비슷한 응답·오차 양상을 묶기

입력 embedding, global 클래스 확률, 정답과 확률의 차이, residual을 합쳐 군집화합니다. Residual을 군집 가중치로도 씁니다.

3

Block + anchor로 expert 구성

군집마다 최대 186,000행을 고릅니다. 작은 군집은 전부 쓰고, 공통 anchor를 더해 각 expert를 구성합니다.

공통 anchor: benign·bot·brute_force·ddos·dos·infiltration 각각 2,000행 + web_attacks 224행. 모든 expert는 7개 클래스 중 하나를 출력하는 분류기이며, 자기 block의 클래스만 출력하도록 제한돼 있지 않습니다.

Expert전용 block 구성 · anchor 제외Block 행 수그중 global 오분류Anchor 포함 context

표의 global 오분류 수는 expert용 학습 풀에서 block을 고르기 전 global로 평가한 값입니다. 아래 test 교정·훼손 수와는 데이터와 의미가 다릅니다.

Benign 훼손이 반드시 block의 주 클래스로 바뀌는 것도 아닙니다. Bot 중심인 expert 1은 benign 훼손 499,183행 중 482,849행을 infiltration으로 예측했습니다. 모든 expert의 anchor에 infiltration 2,000행이 들어 있고, 출력 클래스를 제한하지 않으며, 이번 prior 보정의 beta는 0이었습니다. 공유 anchor와 부족한 benign 대조 사례가 공통 오탐에 기여하는지는 동일 예산의 context 대조로 확인해야 합니다.

“Residual expert”가 곧 “오분류 사례만 학습한 교정 expert”는 아닙니다. Expert 3·4의 block에는 global 오분류가 0건입니다. 맞혔더라도 정답 확률과 클래스 가중치에 따라 residual이 남습니다. 위 구성은 학습 사례의 성격이며, 실제 전문화 성능은 별도 검증해야 합니다.
왜 8개인가? · 군집 수 선택과 추론 시 정보
시험한 expert 수 KTune NLL-oracle macro-F1

K=2·4·8 중 tune에서 정답 라벨의 NLL이 가장 작은 global/expert를 골랐을 때의 macro-F1이 가장 높은 K=8을 선택했습니다. 실제 scorer/verifier가 회수한 성능으로 K를 선택한 것은 아닙니다. 이후 최소 coverage·regime support를 모두 충족했고, marginal-gain pruning은 off여서 8개가 남았습니다.

학습 군집에는 정답 라벨이 필요한 정보도 사용됩니다. 추론 시에는 정답을 모르므로 embedding·global 확률·관측 가능한 거리 등을 이용해 scorer가 적절한 expert를 추정해야 합니다. 군집이 존재하는 것만으로 라우팅 가능성이 보장되지는 않습니다.

전역 강제 적용은 역할과 잘못 라우팅했을 때의 영향을 보는 진단입니다.

Expert가 전체 test에서 global을 이겨야 한다는 요구는 없습니다. 맡길 수 있는 영역에서 교정이 발생하고, 그 영역을 관측 가능한 정보로 찾아 승인할 수 있어야 합니다. 아래는 expert 하나를 모든 행에 적용했을 때 어디로 오분류하는지 확인하는 별도 진단입니다. Expert의 정보량이 항상 더 작은 것도 아닙니다. Expert 2·7은 context 198,224행으로 global의 100,000행보다 많습니다.

Expert 6의 “4,827 교정 · 804,855 훼손”은 서로 다른 클래스에 대한 수치입니다.

학습된 expert 6 하나를 test 전 행에 적용해서 global과 비교했습니다. Infiltration의 교정 4,827행과 benign의 훼손 804,855행을 강조한 것입니다. 모든 클래스를 합치면 교정 5,720행 / 훼손 804,905행입니다.

05 · CIC2018 · Residual → context → scorer 학습 목표

어려운 사례는 expert에 전달됐습니다.
그다음 학습 신호와 대조 사례를 바꿔볼 차례입니다.

Residual은 행마다 계산한 우선순위 점수입니다.

Global이 정답에 낮은 확률을 줄수록 커지고, 희귀 클래스에는 큰 가중치를 곱합니다. 따라서 정답/오답을 나타내는 0·1 값이 아닙니다. 정답 확률이 0.9여도 residual은 0보다 큽니다.

행의 residual = 클래스 가중치 × −log(global이 정답에 준 확률)
Clipping 후 점수 = min(원래 점수, 0.601645)

Clipping = 점수에 상한을 씌우기. 예를 들어 점수가 0.01, 3, 50이면 0.01, 0.601645, 0.601645가 됩니다. 여기서 행·feature·라벨을 삭제하는 것은 아닙니다.

“질량”은 점수의 합계라는 뜻입니다. Infiltration 질량 68.14% → 6.34%는 행의 비율이 그만큼 줄었다는 뜻이 아닙니다. 큰 점수에 상한을 씌우면서 전체 점수 합에서 차지하는 비중이 줄었습니다.

이 점수는 K-means의 행 가중치, 군집 signature의 한 항목, 큰 군집에서 block을 고르는 가중치에 쓰입니다. 원래 feature와 라벨만 받는 expert가 이 점수 자체를 입력으로 받지는 않습니다.

Residual clipping이 질량을 압축

Residual = 클래스 가중치 × −log p₀(정답). 전체 99.5% 분위값 0.601645에서 상한을 적용했습니다.

Scorer 양성의 97.06%는 둘 다 정답

현재 양성은 OOF verifier 판단과 weighted NLL gain으로 만듭니다. 확률만 개선돼도 양성이 될 수 있습니다. 실제 교정 가능 학습 쌍 26,570개 중 OOF verifier를 통과한 것은 43.17%입니다.

개선 가설: 교정·훼손·중립을 분리해 학습하면, “이미 맞힌 답의 확률 개선”보다 “틀린 답을 고치는 expert”를 더 잘 구분하는지 확인할 수 있습니다.

06 · EXP48 / ToN-IoT 정제 후 같은 구조 재검증

ToN에서도 전체 경로를 다시 실행합니다.

같은 라벨 중복과 원래 outer split을 유지합니다. C0 100k·benign 0.75·공격 균등·n_estimators 4를 시작점으로 두고 global, bank, scorer, verifier를 새로 학습합니다. 진단용 전체 expert 예측도 저장합니다. 이전 EXP46 global context 비교는 중단 상태를 유지합니다.

추가 EXP39 legacy 정책의 보호 클래스는 두 데이터셋에 공통인 ddos·dos로 사전 지정했습니다. ToN의 tail은 mitm·ransomware입니다. 이는 주 실험 EXP31 설정과 구분됩니다.

ToN의 추가 점검: 모순 제거량이 split마다 달라 클래스 비중도 바뀝니다. Calibration의 승인 수만으로 test의 유용성을 예상하지 않고, 시간상 뒤의 확인 구간과 클래스별 교정·훼손을 함께 확인합니다. C0의 적합성은 이 정제 기준선을 만든 뒤 별도 비교합니다.

07 · 다음 실험 / 유용한 expert 채택까지

채택률과 함께, 채택된 답이 만드는 개선을 확인합니다.

우선 CIC2018의 저장 캐시로 verifier·scorer를 분리해서 검증합니다. ToN 기준선이 끝나면 같은 진단표로 비교하고, 확인 구간에서 교정 기회와 사례 수가 확보되는 데이터셋을 주 실험 대상으로 정합니다.

1

Verifier target 대조 · 첫 실험

같은 bank·기존 scorer·같은 post feature에서, NLL 기반 target과 실제 교정 / 훼손 / 중립 target을 비교합니다.

Global 정답 여부와 expert 정답 여부로 학습 라벨을 만들고, 중립 사례가 학습을 지배하지 않도록 표본·가중치를 통제합니다. Target 변경 효과를 먼저 분리하며 raw/z feature 추가는 다음 대조로 둡니다.

관찰: 교정 후보 생존율 ↑
동시에: 훼손 · benign FPR 통제
2

Scorer target 대조 · 후보부터 개선

같은 bank에서 실제 교정 가능성 − 훼손 위험으로 후보를 선택하도록 비교합니다. 호출 전 알 수 있는 feature만 사용합니다.

기존/변경 scorer × 기존/변경 verifier의 2×2 대조로 각각의 효과와 상호작용을 봅니다. Scorer의 OOF teacher 조건도 기록·고정해 둘을 동시에 바꾼 효과로 오해하지 않습니다.

관찰: bank 교정 기회 회수율 ↑
동시에: 위험한 top-1 선택 ↓
3

Expert context · 같은 예산에서 대조 사례 보강

Global과 residual 군집을 고정하고 공통 anchor / benign 대조 사례 / 공격 사례의 구성을 바꿉니다. Expert별 context 총행 수를 맞춥니다.

Infiltration recall을 유지하며 precision과 benign 훼손이 개선되는지 확인합니다. 대조 사례는 train 내 별도 mining fold에서 고르고 route/cal/test는 context에 넣지 않습니다. Residual clipping 변경은 별도 대조입니다.

관찰: expert 자체 H / D 개선
그다음: 최종 정책 채택 · 성능 개선
4

데이터셋 선택 · 확인 구간과 반복 실행

ToN에서 정제 후 약한 클래스의 사례와 유용한 expert 답이 충분하면 ToN을 주 실험으로 이어갑니다. 조건이 부족하면 CIC2018 infiltration·benign 교정을 먼저 진행합니다.

ToN C0가 계속 병목이면 같은 100k 예산에서 기존 C0 / 무작위 / train 관측 특성에 따른 구성을 비교하고 새 기준선을 고정합니다. 최종 선택은 validation에서 끝내고 후행 confirm, seed 43·44로 재확인합니다.

진행 기준: confirm에서 채택 > 0
Δmacro-F1 > 0 + 클래스별 보호 조건 충족
공통 기록 항목: 호출 수 · 승인 수 · 실제 라벨 변경 수 · 교정 H · 훼손 D · 클래스별 F1 · benign FPR · bank 기회 회수율. 최소 결정 30건은 유지하고, 교정과 훼손을 충분히 구분하는 점수 영역을 확보하는 것을 첫 목표로 둡니다. 현재 선택용 calibration에서만 좋은 조건은 후행 확인 구간 통과 전까지 채택하지 않습니다.
Expert의 행동 범위를 제한한다면?

예를 들어 benign–mitm expert는 global의 예측이나 top-2 후보에 두 클래스가 나타나는지처럼 추론 시 관측할 수 있는 정보로 호출 대상을 좁힐 수 있습니다. Global top-1이 둘 중 하나인 경우만 허용하는 방식은 한 가지 실험 후보이며, 아직 이번 실행에 적용하지 않았습니다. 이 제한이 다른 클래스에서 넘어오는 교정 기회를 얼마나 놓치는지도 함께 셉니다. “실제 정답이 benign/mitm일 때”라는 조건은 배포 시 사용할 수 없습니다.

같은 모델 입력 벡터에 서로 다른 정답이 있으면 deterministic expert가 두 행을 동시에 맞힐 수 없습니다. 이번 실험은 해당 그룹을 제외한 데이터에서 모델이 구분할 수 있는 교정 사례를 찾아 채택하는 과정을 검증합니다.
