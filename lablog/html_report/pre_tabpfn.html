TabPFN 도입 이전 연구 기록

2026-04-24 – 2026-06-26 · XGBoost 기반 Mixture-of-Experts로 CIC-IDS의 심한 클래스 불균형에 맞선 두 달의 기록.

휴리스틱 라우팅 방법 — confusion-matrix 전문가, TTA/perturbation 안정성 라우팅, OOD 임계값 폴백 — 을 차례로 소진하며 "전문가 품질이 아니라 라우팅 자체가 병목"이라는 것을 세 가지 독립 증거로 확증했다. 이 결론이 8월 이후 frozen TabPFN을 컨텍스트/라우팅의 새 기반으로 채택하게 된 직접적 동기다.

라우팅 병목 확증

Oracle 0.9507 vs 최선 라우팅 0.17–0.32 — 격차 0.78. 전문가 품질은 문제가 아니었다.

최초 양의 결과

CIFAR-10-LT, DCE-XGB(3-expert 가중 + 학습 라우터): 0.1718 → 0.1938 (+0.022)

완전 폐기 판정

exclusive-partition + TTA-stability 라우팅: 3가지 독립 섭동 방식 전부 구조적으로 불가능 확정

임계값 재보정

hard-negative 보정으로 0.7175 → 0.7341 부분 회복, 그러나 구조적 상한 도달

연구 흐름

—

전환: XGBoost 라우팅 한계 → TabPFN 도입

학습된 라우터로도 못 넘은 구조적 상한과, "XGBoost의 부스팅 자체가 이미 암묵적 MoE"라는 재인식이 8월부터 frozen TabPFN을 컨텍스트 구성·라우팅의 새 기반으로 채택하는 동기가 됐다.

방향 전환
06-26

fallback 구조 디버깅 5회 반복 끝에 hard-negative 보정으로 0.7175→0.7341. rare-class expert가 primary가 거부한 행만 구제할 수 있다는 구조적 한계에 부딪힘.

06-03

15클래스·282만행 전체로 재현: 3가지 독립 섭동(VIME/gaussian/mask) 전부 Oracle≈0.95, TTA≈0.17–0.29. 학습된 라우터로 전환을 명시적으로 권고.

05-21

MATI 이식 포기 후 TTA 안정성 라우팅 시도, 배타적 분할에서 파국적 실패(0.17–0.32). 진단 결과 Oracle 0.9507 vs baseline 0.8737 — 전문가는 건강하고 라우팅만 고장.

05-11

저장소 구조화, 문헌 24→44편 확장. FAR-MoE를 4개 비전 벤치마크로 이식하는 스크립트는 작성했으나 미실행.

04-24

4가지 실패 모드 진단 후 CIFAR 벤치마크로 대조 실험 — MoE 설계 자체는 무죄, CIC-IDS의 temporal/file 분포 이동이 범인으로 지목됨.

핵심 발견 (최신순)

  1. (06-26) 임계값 재보정의 구조적 한계. ssh-patator는 WebBot_Main이 잘못 채가서 약함(F1 0.37→0.56, 재구조화 전 0.98에는 못 미침), web-sql은 rare여서 primary expert들이 전부 거부하는 경우가 드물어 구제용 fallback이 애초에 발동하지 않음 — rare-class 구제는 "primary가 전부 거부"라는 조건 자체가 병목.

  2. (06-03) 안정성 신호는 섭동 강도와 무관하게 실패. gaussian σ 0.01–2.0, mask p 0.05–0.7 전 구간에서 flip-rate가 높아 안정성 격차가 거의 0에 수렴 — 튜닝 문제가 아니라 방법 자체의 한계. CIC-IDS의 70개 feature가 attack-type 구분이 아니라 benign-vs-attack 구분에 최적화돼 있어, 비소유 전문가가 겹치는 feature 분포 위에서 confident하게 계속 틀린다.

  3. (05-21) "라우팅이 병목" — 3종 독립 증거. 샘플의 83.1%에서 비소유 전문가의 안정성이 소유 전문가보다 높았고, 15개 클래스 중 14개가 평균 델타 음수, 3가지 섭동 유형 모두 같은 패턴(Oracle≈0.95, TTA≈0.17–0.29) — exclusive-partition + TTA-stability 라우팅은 구조적으로 불가능하다는 결론.

  4. (05-21) MATI 이식 포기. 회귀 기반 prior 추정이 이산 다중분류로 깔끔히 변환되지 않아 SADE 영감의 TTA 라우팅으로 방향 전환.

  5. (04-24) 도메인이 아니라 분포 이동이 원인. 4가지 진단된 실패 모드(라우팅 오류의 불균형 증폭, expert 내부 불균형, confusion-matrix 누수, XGBoost의 암묵적 MoE 특성) 중, CIFAR에서는 양의 결과가 나온 것으로 보아 CIC-IDS 고유의 temporal/file 분포 이동이 진짜 원인으로 지목됨.

다음 단계 — 이 시점에 제안된 방향

  1. 학습된 라우터(메타 분류기 또는 게이팅 네트워크)로 전환 — 안정성/휴리스틱 기반 라우팅을 포기하고 명시적으로 권고된 방향(0603).
  2. 더 표적화된 hard-negative 압력과, primary가 거부하지 않아도 강한 마진에서 이길 수 있는 "rare override" 규칙(0626).
  3. 비전 벤치마크(CIFAR-LT, ImageNet-LT, iNaturalist, mini-ImageNet)로 FAR-MoE 이식 완주(0511, 미실행 상태로 남음).

실제로 다음 국면(8월–)은 이 목록을 그대로 따르지 않았다 — "학습된 라우터"를 XGBoost 위에 얹는 대신, frozen TabPFN이라는 사전학습된 in-context 학습기 자체의 표현·행동을 전문가 구성과 게이팅에 활용하는 방향으로 도약했다. 이어지는 기록은 TabPFN 도입 이후 연구 기록 →에 있다.
