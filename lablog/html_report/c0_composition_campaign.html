① 헤드라인 요약

  • "추첨 복권"의 정체는 C0 행이 아니라 TabPFN의 단일 config(random_state)였고, config 앙상블 4가 그것을 없앤다. exp34에서 같은 C0 추첨이 random_state에 따라 0.675↔0.750을 오가는 것이 드러났고(§8ah), --n-estimators 4로 바꾸자 100k 균등 7 seed가 0.758~0.769로 모이며 7/7 full XGB 상회, 붕괴 0/7(§8ai). 지금까지의 seed 스윕은 C0 추첨과 모델 config를 함께 바꾸고 있었다. 이것이 이 보고서의 핵심 결론이다. 대조군 확인(체인 14): 같은 n=4에서 자연 비율은 0.719(seed 43 port-21→dos, 복권 잔존), S=0.75 자연 배분은 0.749, S=0.75 균등만 0.764 — 구성이 수준을 정하고 앙상블이 config 복권을 없앤다. 250k 균등 n=4도 6-seed 0.759–0.766으로 6/6 XGB 상회.
  • 컨텍스트 구성이 아키텍처보다 중요하다 — 단, TabPFN에만. 같은 C0 행으로 XGB는 구성에 무관하게 0.754~0.756이고, TabPFN global은 benign 비중에 따라 0.62~0.75를 오간다.
  • benign 비중 0.87 → 0.75 원노브가 개입층 전체보다 크다 — 단 250k 이하에서. 250k 3-seed 짝 3/3 우위(평균 +0.077). 1M에서는 3-seed 0.743/0.684/0.639로 평균 −0.04 열세: inf 사본 18k가 임계 근처라 seed에 따라 inf 붕괴 또는 port-21 흡수가 터진다. 1M 열은 주표에서 뺀다.
  • 최종 후보: 100k + 0.75 + 공격 균등 배분 = 3-seed 평균 0.754, full XGB(0.7548)와 동률. seed 42/43/44 = 0.756/0.762/0.744, 2/3 상회. tail-macro 0.553 vs XGB 0.531은 3/3 상회, web +0.07, inf·dos·brute 동률, benign −0.004, ddos −0.06(hoic 추첨 0.74~0.90이 유일한 열세). 개입층 없이 frozen global만으로, 컨텍스트는 훈련 풀 12.07M의 0.8%. 균등 배분은 100k(자연 0.749/0.653/0.738)와 250k(0.743/0.732/0.748) 모두 3/3 짝 우위. C0 추첨 bagging은 hoic 분산을 못 잡아 종결. (17:42 추가) seed 45 0.754 정상, seed 46 0.675 붕괴(benign 1.29M행→inf); (20:26 추가) seed 47 0.7647(hoic 0.990, 신기록)·48 0.7574 → 7-seed 중앙값 0.7562, 정상 6 평균 0.7564, 붕괴 1/7. 표는 7 seed 전부 보이고 붕괴를 숨기지 않는다. 처방: 정제 축(dedup·conflict·dup-cap)은 3연속 음성으로 종결, exp34 추첨 선택(K=5 추첨 중 D_cal benign recall로 선택)이 seed 46의 붕괴 추첨을 cal에서 0.632로 잡아내 배제(test 0.675 → 0.744), 7 seed 진행 중.
  • 안전 변수는 비율이 아니라 C0의 benign 절대 행 수다. benign ≤ 190k인 run(100k 전부, 250k S≤0.75)은 13 run 중 12 무사 — 100k 균등 seed 46이 반례(benign 75k인데 1.29M행→inf); benign ≥ 217k인 run(250k 자연 s44, 1M 8개 중 5개)에서 inf recall 붕괴(0.03~0.06) 또는 port-21 98k행의 inf 흡수가 seed에 따라 터진다. 1M은 구성과 무관하게 3/8만 정상 — "1M은 필요 없다"가 아니라 "1M은 불안정하다". benign 절대 행 수는 위험을 낮추지만 0으로 만들지는 못한다.
  • 1M에서 남은 격차는 hoic 하나. 1M S=0.75에서 XGB-c0까지 −0.011, 그중 ddos(0.9345 vs 0.995)가 0.0086.
  • 3-seed 짝 비교 3/3 우위 — 자연 비율의 추첨 복권(hoic 0.58~0.84)이 S=0.75에서 평균 +0.11 올라가고, port-21 벡터가 셋 다 brute로 고정된다.
  • 주의해서 말할 것: S=0.75에서도 hoic 분산(0.74~0.96)은 남고, benign→inf 붕괴도 seed 추첨이다(100k 1/5, 1M 5/8). 표는 seed 전부 표기 + 평균±범위로.

실패 지점 (6g 시나리오 recall)

  • hoic (ddos, 206,463행): seed별 0.742–0.955. XGB 대비 유일한 체계적 열세(ddos F1 4-seed 0.938 vs 0.992). C0의 hoic 사본은 3.7–3.8k로 같은데 결과가 다르다 → 어느 benign 행이 뽑혔나의 추첨.
  • slowhttptest (dos, 21,110행): 5/5 recall 0, 전량 brute_force. ftp_bruteforce와 바이트 동일 벡터라 XGB도 동일(brute precision 0.845 = XGB). dos F1 0.781 상한은 데이터 라벨의 문제.
  • infiltration (37,631행): 정상 seed에서 recall 0.27–0.32, 25–27k행이 benign으로. precision은 benign→inf 유출량에 반비례(512행 → 0.95, 8k행 → 0.60). seed 46은 반대로 benign 1.29M행이 inf로 넘어가 recall 0.84 / precision 0.02 — 1M 균등(inf 41.7k 사본)에서 본 붕괴가 100k(inf 4.8k)에서도 1/5로 터진다. "benign ≤ 190k면 안전"의 반례.
  • web (509행): recall 0.91–0.93, 대신 benign 2.8–3.4k행이 web으로 → precision 0.12–0.14. XGB(recall 0.48, P 0.105)보다 F1 +0.04–0.07 — 균등 배분이 web 컨텍스트를 61 → 761행으로 늘린 직접 효과.
