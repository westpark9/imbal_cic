RACE-PFN: Residual-Advantage-Guided Context Experts on a Frozen Tabular Foundation Model

We replaced the TAILGUARD design (per-family experts + energy gates) with a foundation-model architecture in which experts are discovered from the global model's failures and invoked through calibrated gates.

Status in one sentence: expert construction and safety are verified (oracle upper bound 0.83–0.87 > XGBoost 0.755; 4 harmful flips out of 4.02M rows); the remaining bottleneck — recovery of that potential — is localized; we come with a decision point on where to spend the next cycle.

1 · Why we changed course

Three reasons, in numbers

  • 1 · It lost, and it was expensive. The per-family expert pipeline beat the plain global XGBoost baseline in 3 / 28 configurations (median macro-F1 −0.184) — while running every expert on every sample. (The new design averages 1.16 model calls per sample.)
  • 2 · The OOD part was the weakest link — so it is deferred, not deleted. Unseen-class resolution landed at median accuracy 0.125, and its energy scores degrade toward chance exactly under long-tailed training. OOD detection presupposes a closed-set base you can trust — we rebuild that base first; OOD returns as an extension once the base is verified. (The scenario framework of the previous draft is retained.)
  • 3 · Too much of it was hand-designed. Expert scopes named by us; gates and thresholds hand-tuned on validation — none of it transferred under chronological splits. Each of these becomes a measured or pre-registered choice in the new design (slide 3).

Decision: rebuild on a backbone where specialization is data, not weights (slide 2), with every remaining design choice measured on a held-out split or fixed by a pre-registered rule (slide 3).

The evaluation design of the previous draft (temporal / cross-dataset scenarios A–E) is retained unchanged — only the method is replaced.

2 · The new backbone

TabPFN: prediction by reading labeled rows, not by training on them

A transformer pre-trained once on millions of synthetic tabular tasks. At inference it receives a labeled context set and a query row, and predicts by in-context learning — one forward pass, θ frozen: p(y|x) = Fθ(C, x). The context C is the only thing we ever choose.

Honest cost note: TFM inference is far heavier than XGBoost per call — the architecture holds the average at 1.16 forward passes/sample by invoking at most one expert, only when a gate predicts positive gain.

5 · What the data looks like at each stage

Failure signature → regime → expert context, with real rows

① A failure becomes a vector. For every held-out row the global model got wrong, we record how it failed:

true: web · global said: benign .85, web .08
signature = [ position in feature space (16d) | global's belief p₀ | direction y−p₀: web +.92, benign −.85 | severity 6.1 ]
true: inf · global said: dos .55, inf .35
same "wrong", different direction → different signature → different regime

Signatures use only the global model's outputs + labels on held-out data — no hand-defined categories.

② Signatures cluster into regimes (one record run, 2M mined rows):

regime (discovered)rowsfailure mass

Regimes are failure types, not class labels — a class may split into several regimes, and a confusion boundary (e.g. benign↔inf) keeps both sides in one regime. Each row belongs to exactly one regime.

③ A regime becomes an expert's context:

C_k =
anchor — 2,000 rows × every class
(keeps the full label space: the expert can still answer sensibly outside its specialty)
∪
regime rows — up to 186k, chosen to cover the regime (budget ∝ failure mass, ≥1 per sub-area)
≈ 199k labeled rows → handed to the frozen model as-is

Then each expert is kept only if removing it measurably hurts the bank on its own regime — and everything downstream (gates, thresholds) is trained/fixed on later, disjoint splits.

9 · The finding that sets the next phase

The highest-value failure regime does not exist in the later tuning window — drift is real, and measured

  • Verified by scenario labels: the hard regime is SSH-bruteforce (starts 18:01), the easy one is FTP-bruteforce (afternoon) — same class label, different tool, different traffic shape. The frozen model solves FTP and misses all 37,696 SSH rows in test; the tuning window (15:31–15:43) ends before SSH begins, so the SSH specialist is unmeasurable there and dropped.
  • Consequence: its specialist is unmeasurable on the tuning split and is dropped by the support rule — which is exactly why brute-force F1 stays frozen at 0.725 in every configuration, the single largest item of the XGBoost gap.
  • Reading: the character of brute-force failures changes over time within this dataset. This is direct, quantified evidence of temporal drift — the phenomenon the frozen-backbone / context-refresh architecture was chosen to handle in the first place.

What this buys us: the temporal-refresh phase of the plan (update contexts with a few verified labels per window, evaluate on the next window) is no longer a speculative differentiator — our own IID experiments produced its motivating evidence, and the calibrated safety machinery built this cycle is its prerequisite.

11 · Decision requested

Where should the next cycle go?

Branch AKeep pursuing IID parity with XGBoost

  • 2–3 recovery knobs remain: measure unmeasurable regimes on the gate-training split; temper the class-weight scale that biases gates toward web; iterate the scorer.
  • Upside: closes the headline number. Risk: even at parity, "why not just XGBoost" remains unanswered on IID alone.

Branch BPivot to the temporal / long-tail scenarios now

  • Drift evidence is in hand (slide 9); scenario framework A–E already designed in the draft; safety machinery (calibrated gates) is the prerequisite and is done.
  • These are the settings where a frozen backbone with editable contexts is structurally advantaged over retraining-based baselines — the paper's actual claim.

Recommendation: Branch B as the main line, with Branch A limited to the one cheap knob (regime measurement fallback) that directly unblocks brute-force — it serves both branches.
