SOTA PFN 3종 비교: BoostPFN(AISTATS 2025)·LoCalPFN(NeurIPS 2024)·DistPFN(ICML 2026) (MixturePFN not released)

TabPFN을 큰 데이터로 확장하는 공개 코드 3종을 우리 NF-CSE-CIC-IDS2018 chrono split에 이식해 비교했다. 구성: 1. C0(100k · benign 0.75 · 공격 6종 균등 · seed 42)로 훈련, 테스트 4,023,114행으로 평가한 비교 → 2. 참고용) 각 저장소의 원본 데이터에서 논문 수치가 재현되는지 확인 → 3. (예정) bot_iot · ton_iot. 모든 IDS 수치는 같은 split·같은 테스트·같은 run 안에서 계산됐다(랩로그 lablog/report/0904.md §5–§9). MixturePFN(ICLR 2025)은 공개 코드가 없어 제외.

1. C0(100k, benign 0.75, 공격 균등, seed 42)로 훈련 → 테스트 4,023,114행

기록 run(20260904_010654, chain 13 seed 42, global 0.7623)과 행 단위로 같은 C0를 다시 뽑아(exp31의 추첨 함수 그대로, 시나리오별 구성 15항목 일치) ours를 재현하고(0.7617; GPU 동시실행 밴드 ±0.0016 안), 외부 방법은 그 100k를 훈련 풀로 받는다. BoostPFN과 LoCalPFN은 TabPFN v1 위에 있어 컨텍스트가 1,024행을 넘지 못하므로(attention 메모리가 컨텍스트 길이의 제곱) 100k를 한 번에 컨텍스트로 넣을 수 없고, 대신 BoostPFN은 C0에서 500행 표본을 라운드마다 뽑고, LoCalPFN은 C0에서 테스트 행마다 1000-NN을 검색한다. DistPFN은 ours·XGB-c0의 예측 확률에 플러그인. TabPFN-v3는 fit_with_cache · n_estimators 4 · batch 500k(기록과 동일).

방법별 판독

  • BoostPFN — 여기서 "라운드"는 부스팅 반복 1회다: 가중치로 500행을 뽑아 → TabPFN-v1을 한 번 fit하고 → 훈련 100k + 테스트 4.02M 전체를 예측한 뒤 → 이 학습기의 가중치 γ_t를 정하고 → 표본 가중치를 갱신한다(epoch 개념은 없고, 라운드 = 약한 학습기 1개 추가). 궤적은 4라운드에 정점 0.7418, 6라운드에 0.655로 급락(ftp_bruteforce↔slowhttptest의 바이트까지 동일한 벡터 쌍이 통째로 뒤집혀 brute 0.916→0.493, dos 0.750→0.584), 10라운드에 0.7389로 복구, 이후 정체 → 최종 0.7369. 정체의 원인 두 가지. (a) 표본 가중치의 쏠림: 매 라운드 틀리는 infiltration 행(~1,400개, 라벨-충돌 쌍둥이)의 가중치가 ×e씩 불어나 500행 표본의 400개 이상이 inf가 된다. ESS(effective sample size, 1/Σw²)는 "가중치가 사실상 몇 행에 걸쳐 있나"인데 100k → 1,200이 됐으니 사실상 1,200행에서만 표본을 뽑는 셈. (b) γ_t≈0: 각 학습기의 가중치 γ_t는 훈련 100k행 전체의 평균 손실을 가장 줄이는 값으로 정하는데(line search), inf/web 위주 표본으로 만든 학습기는 benign 75k행의 예측을 나쁘게 하므로 최적 γ_t가 0 근처가 되고 그 학습기는 사실상 버려진다. 그래서 후반 학습기가 web을 50–110행씩 담아도 web F1이 0.197에서 움직이지 않는다.
  • LoCalPFN — 논문이 제안하는 최종 모델은 kNN 검색 + 미세조정(표의 "LoCalPFN")이고, TabPFN-kNN은 같은 논문의 검색만 하는 중간 단계(ablation 기준선)다. 검색만 하면 꼬리는 ours급(inf 0.396, web 0.225; tail 0.539로 XGB-c0 상회)이지만 라벨 충돌 지역에서 head가 무너진다(brute 0.736, ddos 0.866: 1000개 이웃 안에 두 라벨이 섞여 들어옴). 미세조정(21 epoch, val AUC 0.936→0.941 @ epoch 4)을 하면 head는 완전히 돌아오지만(brute 0.916, ddos 0.998) inf가 0.275로 내려간다 — 미세조정이 head를 되찾고 tail을 내준 셈이라 macro는 +0.028, tail은 −0.040. 저장소 평가 루프가 배치마다 디코더 출력 전체를 GPU에 붙들고 있어 4.02M행에서 17.6 GB 누수로 OOM → 러너에서 출력 복사 한 줄로 해결(수치 불변).
  • DistPFN — 논문 지표는 accuracy·평균 순위·ECE·precision이고 F1·ROC·log-loss는 보고하지 않는다. 방법은 "모델이 추정한 테스트 클래스 비율 ÷ 컨텍스트의 클래스 비율"을 각 클래스 확률에 곱하는 것이라, 컨텍스트에서 부풀린 공격 클래스에는 1보다 작은 인자가 걸린다: benign ×1.13, ddos ×1.31, bot ×0.21, brute ×0.42, dos ×0.35, inf ×0.81, web ×0.60 — 꼬리에 낮은 가중치. 그래서 자기 지표(log-loss 0.0853→0.0830, XGB 0.0804→0.0701)는 개선되지만 macro-F1은 중립(−0.0008). C0가 꼬리를 일부러 과대표집한 컨텍스트이므로 정확히 이 방법이 되돌리는 방향과 반대로 채점되는 것이지 이식 오류가 아니다(2절의 그들 벤치마크에선 accuracy 개선이 재현됨).

DistPFN-T(온도조절판)는 표에 넣지 않았다. 공개 스크립트는 평균 확률(1-D)을 2-D용 helper에 넘겨 AxisError가 나고 예외 처리로 데이터셋을 건너뛰어 어떤 데이터에서도 실행되지 않는다(그들 OpenML 30종에서도 전부 skip). 논문 식(τ = CE(추정 비율, 컨텍스트 비율) 스칼라, softmax(비율/τ))대로 구현하면 우리 데이터에서 web 인자 ×14가 되어 붕괴(macro 0.6255)하고, helper 시그니처에 맞춘 다른 두 해석(샘플별 τ 0.7119, README 한 토큰 수정 0.6250)도 마찬가지라 결론이 해석에 좌우되지 않는다. 기본 DistPFN만 플러그인 열로 유지(exp37 --no-distpfn-t).
