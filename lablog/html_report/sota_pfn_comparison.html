방법별 판독

  • BoostPFN — 4라운드에 정점 0.7418, 6라운드에 port-21 동일벡터 쌍(ftp↔slowhttptest)이 뒤집혀 0.655로 급락(brute 0.916→0.493, dos 0.750→0.584), 10라운드 음수 γ로 복구 0.7389, 이후 |γ|<0.03으로 정체. exphadamard 가중치가 매 라운드 놓친 infiltration ~1,375행(라벨-충돌 쌍둥이)에 몰려 ESS 100k→1.2k, 표본이 inf 400+/web 50–110행으로 고정 — 후반 학습기가 web을 담아도 line search(행-평균 deviance, benign 75%)가 γ≈0을 준다. 18만 풀에서 이미 같은 병리. TabPFN-v1 내부 seed(42 vs upstream 기본 0) 영향은 ≤0.003(run 20260908_133300 0.7361).
  • LoCalPFN — kNN은 꼬리가 ours급(inf 0.396, web 0.225; tail 0.539로 XGB-c0 상회)이지만 라벨 충돌 지역에서 head가 무너진다(brute 0.736, ddos 0.866: 1000-NN이 두 라벨을 섞어 담음). 미세조정(21 epoch, val AUC 0.9363→0.9409 @ epoch 4)은 head를 완전히 되찾지만(brute 0.916, ddos 0.998) inf를 0.275로 판다 — head를 사고 꼬리를 판 셈. 저장소 평가 루프가 배치마다 디코더 출력 전체의 뷰를 보관해 4.02M행에서 17.6 GB 누수로 OOM → 러너의 .clone() 래퍼로 해결(수치 불변).
  • DistPFN — 보정 인자 = P_test_avg/컨텍스트 prior: benign ×1.13, ddos ×1.31, bot ×0.21, dos ×0.35, web ×0.60. C0가 꼬리를 일부러 과대표집한 컨텍스트라 보정이 꼬리를 자연 prior 쪽으로 깎는다. 자기 지표(log-loss 0.0853→0.0830, XGB 0.0804→0.0701)는 개선되지만 macro-F1은 중립. 논문 지표는 accuracy·rank·ECE·precision이고 F1은 보고하지 않는다 — 전이가 안 되는 이유는 방법 결함보다 목적함수 차이.

DistPFN-T를 비교에서 제외한 근거 (09-08 결정)

  • 공개 스크립트 eval_TABPFN_shift_O.py는 P_test_avg = y_prob.mean(axis=0)(항상 1-D)를 axis=1로 합치는 helper에 넘겨 AxisError(ValueError 하위)가 나고, except ValueError가 이를 삼켜 데이터셋을 skip한다. 기본 플래그가 DistPFN_T=True라 README 커맨드 그대로면 전부 skip → 끝에서 0-나누기. 그들 OpenML 목록 첫 8개에서 스크립트를 무수정으로 실행해 확인(이진·다중 모두 실패, exit 1).
  • 논문 §4.3 식(5)(6)·부록 pseudocode는 τ = CE(p̂(y), p_train(y)) 스칼라, p̂_T = softmax(p̂/τ)(확률 벡터에 softmax)를 정의한다. 이대로 구현하면 우리 데이터에서 web 인자 ×14로 붕괴(0.6255); helper 시그니처에 맞춘 두 다른 해석(샘플별 τ_i 0.7119, README 한 토큰 수정 0.6250)도 마찬가지. 릴리스 helper에 (1, C) 입력을 주면 우리 스칼라 구현과 4.02M×7에서 완전히 같다.
  • 결정: 기본 DistPFN은 플러그인 행으로 유지, -T는 표에서 제외(exp37 --no-distpfn-t). 저자 문의는 보류.
