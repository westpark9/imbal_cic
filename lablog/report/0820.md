# 0820 — EXP4: Tail-Anchored Context Bagging (TACB) 사전 등록 + 캠페인 시작

새 스크립트: `tabpfn/nfv3_v3_exp4_tail_anchored_bagging.py` (frozen 코드 무수정,
`nfv3_v3_common`을 import-only로 재사용). 이 문서는 **결과가 나오기 전에** 쓰는
사전 등록이다: anchor 정의, 컨트롤 목록, run ladder, 숫자 성공 기준을 먼저 고정한다.

## 0. 논문 서사와 이 실험이 공격하는 숫자

주장 흐름: XGBoost는 전체 분류는 강하지만 tail 클래스에서 (1) class imbalance,
(2) temporal domain shift에 취약하다 → context 구성을 tail-친화적으로 설계한
TabPFN 앙상블(TACB)이 이를 얼마나 견디는지 측정한다.

공격하는 frontier 숫자 (CLAUDE.md): TabPFN 트랙의 "정직한 프로토콜에서 XGB에
4/4 패배" (0818). 구체적으로 exp1(1M 비례 context)의 cic2018 tail:
web_attacks XGB 0.162 / TabPFN 0.161 — 둘 다 죽어 있는 상태.

- open-set/unseen 축은 이번 캠페인에서 **제외** (사용자 확정, 2026-08-20).
  estimator 간 OOD 게이트 없음 — 확률 평균만 (F7/F9 회피가 설계 의도).
- 평가 축: ① imbalance 강건성 (context 예산 스윕, Fig 1),
  ② temporal drift 강건성 (`--eval-split val` 근미래 vs test 원미래, Fig 2).

## 1. Anchor 정의 (F8 경계선 — 사전 등록)

- pool count ≤ `--anchor-threshold` (**5,000**)인 클래스는 모든 estimator context에
  **자연 pool의 100%** 포함. 복제·오버샘플·합성 없음 (한 context 내 중복 0).
- head 클래스는 남은 예산을 **자연 비례**(largest-remainder)로 채우고 context 간
  disjoint 분할. `--context-floor`는 이번 캠페인에서 0 (anchor만 사용).
- k=1M에서 anchor 질량: cic2018 = web_attacks 1,522 rows = **0.15%** of context.
- s41(F8, 완전 class-balanced 샘플링이 양 다리 다 짐)과의 구분: head 분포 불변,
  tail은 자기 자연량 상한. 이것은 rebalancing이 아니라 "샘플링이 tail을 지우지
  않게 하는" few-shot context 구성이다. threshold 5,000은 pool 통계만 사용 —
  val prediction에 fit되는 것 없음 (F3 회피).
- k=100k 같은 소예산 anchored 점에서는 tail share가 1.5%+로 오름 → Fig 1에서
  stress test로만 라벨, 제안 config는 k=1M.

## 3. Run ladder (cic2018 먼저 — 사용자 확정. one knob per run)

공통: `--seed 42 --test-cap-per-class 0` (정직한 프로토콜, 0818).
GPU 필요 run은 로컬 GPU 복구 후 (현재 driver mismatch로 CUDA 불가).

| run | 명령 (핵심 args) | vs (knob) | 질문 |
|---|---|---|---|
| **R2a** | `--context-size -1 --n-contexts 1 --skip-tabpfn` | exp2 (가중치만) | 정직한 XGB bar: sqrt 가중 full-pool. **CPU 가능, GPU 복구 전 실행** |
| **R1a** | `--n-contexts 1 --context-size 1000000 --anchor-threshold 5000` | exp1 (샘플러만) | 구성만으로 tail이 사는가 (web_attacks 126→1,522 rows). XGB+XGB_sqrt 같은 union으로 in-run → model-agnostic 여부 즉답 |
| **R3c** | `--n-contexts 4 --context-size 1000000 --anchor-threshold 0 --ignore-pretraining-limits` | exp1 (E만) | E-only 컨트롤 (비례 bagging) |
| **R3a** | `--n-contexts 4 --context-size 1000000 --anchor-threshold 5000 --ignore-pretraining-limits` | R3c (anchor만) / R1a (E만) | 헤드라인. {prop,anchor}×{E=1,4} factorial 완성 |
| **S-p/a 100k, 300k** | `--context-size {100000,300000}` × threshold {0,5000} | 예산 스윕 | Fig 1: 0813의 표본효율(13 rows: XGB 0 vs TabPFN 0.56)을 uncapped로 재확립 |
| **W5** | 위 승자 config + `--eval-split val` | predict-only | Fig 2: 근미래 vs 원미래 열화 (XGB 대비) |

balance_probabilities는 **run이 아니라 컬럼**: 모든 run이 평균 확률을 덤프하고
`tabpfn_tacb_bp`를 post-hoc으로 계산한다 (스모크에서 실제 bp fit과 동치 검증 완료
— classifier.py:1623-1630에서 bp는 estimator 평균 후 마지막 단계라 정확히 재현됨).

판정 규칙 (사전 등록):
- R1a에서 **floored XGB가 이미 bar에 도달**하면 → 효과는 model-agnostic. 서사 피벗:
  "per-class floor가 기여, TabPFN의 남은 주장은 저예산 영역(Fig 1 왼쪽)".
- R1a에서 TabPFN이 XGB보다 **+0.05 이상 더** 얻으면 → R3 진행.
- 둘 다 안 움직이면 (precision ~0.10 정체) → tail은 구성이 아니라 shift/overlap
  한계 → Wave 4 소예산 스윕(표본효율 fallback)과 W5(shift 축)가 본론.

## 4. 성공 기준 (숫자, 사전 등록 — R2a 후 bar 1회 갱신 외 불변)

현재 bar (uncapped full-pool 무가중 XGB): web_attacks **0.172**. R2a의
xgboost_sqrt가 이를 갱신하면 그 값이 bar.

- **승리**: web_attacks F1 ≥ bar + 0.05, AND macro ≥ exp1 XGB − 0.010 (≥ 0.7468),
  AND benign F1 ≥ exp1 XGB − 0.005 (≥ 0.990), AND 비-tail 클래스 손실 ≤ 0.02.
- **shift 기준** (W5): tail의 val→test 열화가 같은 조건 XGB 열화의 ≤ 절반.
- **Fallback A** (model-agnostic): floored XGB가 TACB ±0.03 이내 → 기여는 context
  floor. 지지 조건: k=100k에서 비례-TabPFN ≥ 비례-XGB + 0.10 (표본효율 주장).
- **Fallback B** (clean negative): 아무것도 bar를 못 넘음 → "기존 TabPFN tail 우위는
  test-cap 아티팩트; 정직한 프로토콜에서는 weighted XGB + floor가 bar"라는 측정 결과.

제외 목록 (어떤 결과가 나와도 tail 주장에 사용 금지, 0819 §3):
cic2018 slowhttptest/ftp-bruteforce (단일 벡터 mislabel), ton_iot scanning
(97% benign 충돌), ton_iot backdoor (203k rows, tail 아님), bot_iot theft
(purity 0.2446 = 천장), cic2017 전체 (val-discard 결함 + tail test n≤8),
heartbleed (test n=3).

## 5. 구현 노트 (검증 기록)

- 훅: TabPFN 8.2.0 `inference_config={"SUBSAMPLE_SAMPLES": [arr,...]}` — estimator별
  positional 인덱스가 전처리 전 그대로 적용 (transform.py:66-68; dispatch
  ensemble.py:525-543, len(list)==n_estimators이면 identity). `auto_scale_n_estimators=False`
  필수. fit()에는 context들의 **union**만 전달 (1M guard는 union에 적용).
- `--n-contexts`(E)와 `--n-estimators`(총원, E의 배수) 분리 — context마다
  n_estimators/E개의 전처리 variant. exp1과의 one-knob 체인용.
- `save_fitted_tabpfn_model`은 list-form SUBSAMPLE_SAMPLES를 JSON 직렬화 못함
  (ndarray TypeError, 확인) → TabPFN fit 체크포인트 없음. resume 지점은
  예측 확률 npy (fit은 결정적, `{tag}_contexts.npz`로 context 결정성 검증).
- 시드 밴드: context builder는 seed+950+class_id (기존 +500+i/+800/+850/+900과 비충돌).
- CPU 스모크 (cic2018_capped, k=2000, E=2, web_attacks anchor) 전부 통과:
  결정성(바이트 동일), resume 동일, bp post-hoc == bp fit, E=1 vs E=2 확률 상이,
  가드 4종 SystemExit, --eval-split val 동작, composition CSV == bincount.
- 이 머신 CUDA 불가 (Error 804 driver mismatch) → GPU run은 드라이버 복구 후.
  RAM 125GB — full-pool XGB(R2a)는 CPU로 즉시 가능.

## 5b. 스크립트 적대 리뷰 (17-agent workflow, GPU 지출 전) — 12건 확정, 전부 수정 반영

Major 4건 (수정 완료):
1. **context×전처리기 교락**: TabPFN은 전처리 variant를 estimator 슬롯에 블록 배정
   (ensemble.py:1063-1067)하는데 context 리스트도 블록 반복이면 context가 특정
   variant에 고정됨 → **인터리브 배정으로 수정** (context e가 슬롯 {e, e+E, …} 차지).
   E==n_estimators면 context당 1 variant는 불가피 — R3a/R3c가 같은 구조라 anchor
   knob 비교는 유효 (docstring에 명시).
2. **auto-E 커버리지 미달**: pool-비율 추정이 floor 복제/반올림 유실을 무시 →
   **E = max ceil(pool_c / t_c)** (실제 타깃 기반)로 수정 + 커버리지 부족 시 경고 출력.
3. **exp1 링크의 숨은 2번째 knob**: 클래스별 카운트는 같아도 행 실현이 다름
   (+850 draw vs +950 permutation) → docstring에 명시 + **R0 브릿지 run**
   (`--max-train-samples 1000000 --context-size -1` = exp1의 context를 그대로 재구성) 추가.
4. **XGB 하이퍼파라미터가 resume 키에 없음** → XGB 체크포인트에 7개 파라미터 시그니처 추가.

Minor: largest-remainder ≥1 bump의 예산 초과 walk-back(+assert), resume tag에
data/ckpt 경로 해시 추가, contexts.npz에 global row id 저장·대조, **`tabpfn_tacb_bpctx`
컬럼 추가** (bp는 union prior로 나누는데 anchored 클래스는 per-context prior가 ~E배
큼 — context prior 버전을 공짜 컬럼으로), E>1에서 union-XGB의 anchor 희석(~E배) 명시.

수정 후 스모크 재통과: 결정성/resume/bp동치/E-민감도/가드/auto-E 전량 커버리지 전부 OK.

## 7. GPU 복구 후 실행 기록 (2026-08-20 12시대, 결과 나오기 전 기록)

재부팅으로 driver 복구: 580.173.02 / CUDA 13.0, torch 2.11.0+cu130, RTX 4090 24GB.

**1차 발사 (12:17, fit_preprocessors 기본값) → R0/R1a 둘 다 TabPFN predict에서 CUDA OOM.**
- 원인: exp4 기본 `fit_mode=fit_preprocessors`는 test 청킹이 없는 경로라 4.02M test를
  한 forward로 실체화. 내부 자동 청킹(`TABPFN_MAX_BATCHED_TEST_ROWS`=32768,
  inference.py:1190-1218)은 **fit_with_cache 전용**.
- exp1이 이 4090에서 1M ctx × 4.02M test를 완주(predict 5,290s)할 수 있었던 이유가
  바로 이것 (exp1은 cache mode). nfv3_v3_common의 예측 공식(`n_test_batch × 12,343B`)은
  청킹 도입 전 측정치라 cache mode에서 과대 예측 (exp1 timings의 predicted 58.88 GiB에도
  실제 완주). fit_preprocessors 경로에는 공식이 여전히 유효 → 이번 OOM.
- 1차 크래시 run은 results/에 dir을 남기지 않음 (record 오염 없음).

**발견: TabPFN-3의 fit_with_cache는 KV cache를 기본 int8 양자화** (inference.py:860,
`kv_cache_precision` 기본 None → int8 resolve). 두 fit_mode는 **다른 모델이다**:
capped 스모크(k=2000, E=2, 동일 contexts.npz 확인)에서 두 모드의 확률
max|diff| 0.486, mean 0.030, argmax 일치율 79.0%. exp1 기록(web_attacks 0.1615)은
int8-cache 모델의 숫자.

**GPU 검증 배터리 (본 run 전, 전부 통과):**
1. cache mode 결정성: fresh resume dir 재실행 → probs npy md5 동일.
2. SUBSAMPLE_SAMPLES 훅 × cache mode: 토이 체크(E=2, 800/1,200행 인덱스)에서
   estimator별 KV 캐시 row 차원이 각자 context 크기와 정확히 일치 (800/1,200;
   int8 KV + fp16 보조 텐서 확인) → 훅이 캐시 빌드에 상속됨. E>1 설계 유효.
3. 컨텍스트 빌더는 fit_mode 무관: 두 모드의 contexts.npz 동일.

**결정 (사전 등록 — R0/R1a 결과 보기 전): 캠페인 전체를 `--fit-mode fit_with_cache`로
진행.** 근거: (a) exp1 부모가 cache mode → R0 브릿지는 같은 경로여야 exp1 기록과 직접
재현 대조가 됨. (b) 이 카드에서 fit_preprocessors는 250k 배치 필요 → context 재인코딩
17×4회 ≈ run당 ~7h; cache mode는 ~1.9h. (c) 스크립트 무수정, 인자만 추가 — Args 덤프에
기록. 부작용: fm 태그 차이로 R1a의 XGB가 R2c 체크포인트를 재사용하지 못하고 재학습
(동일 데이터/시드/파라미터라 동일 결과 기대; 판정은 어차피 in-run 비교).

**12:32 R0(cache) → R1a(cache) 순차 재발사 → R0 다시 predict OOM (2차, ~13:00).**

## 8. EXP5 사전 등록 — Energy-weighted View-MoE (2026-08-20, 결과 전 고정)

사용자 방향 확정: "s44의 XGB expert를 TabPFN으로, closed-set으로, tail을 살리는
context 분배를 파보자." 구조는 s44의 직계이되 기록된 함정을 피하도록 재설계:

- **View = 클래스 절단이 아니라 분포 기울임.** view v의 클래스 예산
  ∝ pool_c^α, pool_c 상한(오버샘플 없음), largest-remainder + waterfill.
  α ∈ {1.0(natural/head), 0.5(sqrt/중간), 0.0(balanced/tail-max)}. 모든 view가
  전체 클래스를 포함 → (a) 선택 실수가 "불가능한 예측"이 되지 않음, (b) 클래스 수
  동일로 energy 비교 가능(s01/s20 padding 함정 회피). 행은 클래스별 공유 permutation
  (seed+950+class_id, exp4와 같은 밴드)의 prefix → view 간 차이는 per-class 개수뿐.
- **선택 = threshold 없는 softmax 가중** (실패 모드 #2 회피): view별
  E_v(x) = −T·logsumexp(logits_v(x)/T) (T=1, estimator 평균), w_v = softmax(−E_v/τ).
  τ→∞ = 단순 평균(bagging), τ→0 = argmin(s44식 hard 선택) — **한 run이 연속체 전체를
  post-hoc 컬럼으로 담는다** (τ ∈ {0.25, 1, 4} + argmin + avg). TTA 없음 (s23).
- **TabPFN logits**: `_raw_predict(X, return_raw_logits=True)` → (m, n, C) 원시
  logit (un-permuted, 온도/평균 전; classifier.py:1337/1632). 후처리는
  `logits_to_probabilities`로 공식 경로 재현 (스모크에서 predict_proba와 동치 검증).
- **XGB 미러 컨트롤**: 같은 view 행으로 view별 XGB(무가중)도 학습, margin에서 같은
  energy/선택 컬럼 → "선택이 되면 그것은 ICL 덕인가"를 in-run으로 판정 (s44 직접 비교).
- **스코프**: cic2018, closed-set만 (unseen/OOD 축 없음 — 사용자 확정), uncapped test.

- 판정: E2 확정 web F1이 bar(0.2427) 이상이면 "무가중·구성+보정만으로 √가중 full-pool

## 10. EXP7 사전 등록 — TabPFN energy-score OOD (스코프 변경: OOD 축 재개방)

**스코프 변경 (사용자 지시)**: closed-set 한정을 해제하고 s43/s44의 unseen 프로토콜로

TabPFN-v3 출력은 log-softmax라 출력-energy는 퇴화하지만(§8a), 헤드가 어텐션형
디코더라 **softmax 직전 원시 점수(scores_BHMN, tabpfn_v3.py:586)가 존재** — hook으로
추출 가능(라이브러리 무수정). `get_embeddings` 공식 API도 미사용 자원.

**프로토콜 (s43/s44 그대로):**
- **ID** = cic2018에서 unseen 클래스를 제외한 클래스들 (context도 이들로만 구성).
- **OOD(평가)** = cic2018에서 선택한 unseen 클래스의 test-구간 행. 1차: `--unseen bot`
  (CLAUDE.md 표준 예시). 후속: infiltration, web_attacks.
- **aux OOD(보조)** = bot_iot/ton_iot/unsw에서 cic2018 family와 이름이 안 겹치는 공격
  클래스만 (0819 §3 오염 family 제외: ton_iot scanning, bot_iot theft). 용도는
  **평가가 아니라 보조** — tau 캘리브레이션 및 별도 role 행으로 보고.
- 컨텍스트: 자연 비례 1M (unseen 제외 6클래스), m=1 (m=4는 후속), cache mode + 500k
  배치, seed 42.

**스코어 (한 fit에서 전부 캡처):**
1. **헤드 energy** (headline): softmax 직전 scores_BHMN에서 −logsumexp — hook 캡처.
2. max log-prob / entropy (확률 기반 대조군).
3. embedding kNN 거리 (`get_embeddings`, ID-context 행 대비).
4. **변형 B (TabPFN-native outlier exposure)**: aux OOD 행을 context에 **"other" 8번째
   클래스로 라벨해 포함** — P(other)가 threshold 없는 unknown 스코어. 학습이 필요한
   기존 OE를 ICL로 대체하는, 이 모델에서만 가능한 구조.

**산출물: 기존 3a/3b/3c 형식 그대로** (단일 stage이므로 pre/post 열은 단일):
3a = 스코어×role(unseen/aux/ID-val) AUROC·AUPR·FPR95 표, 3b = ID-val 분위수 tau와
tau에서의 id_retain/ood_detect ("accept if score ≥ tau" 규약, 부호 정렬 주의 —
기존 스크립트 간 sign 상이 경고 준수), 3c = 스코어별 ID vs unseen vs aux 히스토그램
2×2 + tau 선.

**판정 (사전 등록)**: 헤드 energy의 unseen AUROC를 s37의 global MLP energy 기록
**0.954**와 대조. ≥0.90이면 "TabPFN energy OOD 성립"으로 기록하고 expert별

### §10d. EXP9 사전 등록 — energy score fine-tuning (aux OOD, 예전 pre/post 형식)

사용자 정정 두 가지를 반영: ① **energy = energy_head** (softmax-직전 유사도의
−logsumexp — TabPFN에서 예전 공식이 성립하는 자리)로 확정, 용어 통일.
② fine-tuning 대상은 backbone이 아니라 **frozen 모델의 로짓/유사도로부터 계산되는
energy score 자체** — 예전 파이프라인의 pre/post 구조 그대로.

- expert별 소형 score head: 입력 = 헤드별 logsumexp/max 유사도 + 출력 확률
  max/entropy → 스칼라. **양성 = 소유 family의 train-슬라이스 held-out 행**(context
  제외분; val 불사용 — F3 회피, 자기-retrieval 오염 회피), **음성 = aux OOD의
  학습-절반**(평가-절반과 분리).
- 산출물: 예전 3a 컬럼(pre_/post_ auroc·fpr95·detect), 3b(tau pre/post),
  3c `_pretrained` / `_finetuned` 두 장. 스윕: unseen 6-family, exp8 구성 재사용.
- **판정 질문 (사전 등록)**: post가 aux에서만 좋아지는가, unseen까지 좋아지는가.
  변형 B(aux 0.993/unseen 0.390)와 s31–37("energy fine-tuning이 OOD 악화/반전")의
  재대면 — post_unseen ≥ pre_unseen이면 OE-일반화 성립, 반대면 aux-과적합으로 기록.
  스크립트: `tabpfn/nfv3_v3_exp9_energy_score_finetune.py`.

## 11. HCE 설계 + EXP10 사전 등록 (closed-set 분류, unseen 제외 — 사용자 방향)

사용자 확인 사항: ① TabPFN이 무겁지만 학습 불필요라 기존 backbone 대체 가능성 확인,
② **taxonomy-disjoint expert의 "분류 성능"은 미측정** — 이것부터 측정, ③ global +
disjoint experts 구조에서 배정 방법 구체화 (TTA 부활 포함, unseen은 다음 단계).

**HCE (Hierarchical Context Experts)** — 구조도는 통합 보고서 §8:
- 배정 = 선택이 아니라 **체인룰 인수분해**: p(c|x) = p(g(c)|x) · p_expert(c|x, g).
  p(g|x)는 별도 라우터 없이 global expert의 그룹-내 확률 합산. 선택 단계가 없어
  D1의 선택-실패와 실패 모드 #1을 구조적으로 회피; EXP6의 prior 침수는 "부풀린
  prior가 그룹 조건부 안에만 존재"하므로 봉쇄 (web은 tail-그룹 안에서 0.64%).
- 보정층(측정 후 채택, 원노브 순차): ownership score head(exp9식)로 p(g|x) 재보정;
  **TTA는 그룹-불확실 행 한정 보조 특징으로 재시험** (s23과 다른 스코프: 선택이
  아니라 보정 입력, 후보 행만이라 비용 무시 가능); hard routing은 대조군.

**EXP10 결과 (완료)**: 체인룰 인수분해 ≈ global (web +0.007, dos ±0.000, val-선택도
λ=0 선택) → **기각**. 대신 oracle 배정 컬럼이 상한 확정: **macro 0.964, infiltration
0.994, dos 1.000, web 0.754** — expert 조건부는 이미 충분, 승부는 배정(특히 benign
경계). 부가 분석: global의 이진 benign/attack 경계는 web 46%/inf 5%만 통과(@FPR
0.1%)로 부족하나, 강화-context 판별(web_ctrl)은 web 93%@0.087% — 통합 구조 v3
(disjoint expert 게이트 겨루기 + 검증된 덮어쓰기, 보고서 §8 그림)의 근거.

### §12k. TTA 검토용 margin 해부 + benign-반환 오라클 스윕 (⚠ test-스윕 진단, 확정치 아님)

**margin 해부 (12c gate_scores 덤프, GPU 없음)**: 오류 유형별 "승자−진짜expert" 격차 —
benign→tail 14.9만 행은 **2위가 99.9% benign expert**, margin 중앙값 0.60 (옳은 행
1-2위 격차 중앙값 2.9 대비 박빙; 42%가 <0.5). inf→benign은 중앙값 1.52 (박빙 아님,
5%만 <0.25). dos 오류는 **전 행 margin 정확히 0.434** (동일-벡터 블록 — TTA 원리적
불가 재확증). bot/web 오류는 소수·대격차.
→ TTA-류 스무딩이 닿는 영역은 benign↔tail 박빙 하나뿐이고, 그 영역은 TTA 없이
margin 규칙으로 도달 가능.

**benign-반환 오라클 스윕**: tail 승리 행 중 s_tail−s_benign < δ를 benign으로 반환
(오프라인, 조건부 재실행 불필요 — benign은 이진 판정이라 라벨=benign).
δ=2.5 피크: **macro 0.7347 vs global 0.7012 (+0.033)** — benign 0.9927(>global),
web 0.1910(>0.1601, P 0.110/R 0.735), inf 0.2727(>0.0968), ddos 0.9939 유지.
반환 순도: 13.0만 flip 중 98% 진짜 benign. **단 δ=2.5→3.0에서 inf 절벽**(진짜 inf의
tail-margin이 2.5~3.0 구간에 밀집; 8천 행 추가 flip 시 inf 붕괴 0.27→0.006) —
γ-전이 실패(§9b) 전례상 δ의 시간 안정성이 관건.

**정직 절차 제안 (exp13 후보)**: val 게이트 점수 산출(GPU ~1-2h) → δ를 val에서 선택
(macro-최적이 아니라 inf-recall 보호 제약 하 보수 선택 권장, 절벽 회피) → test 1회
확정. TTA 자체는 이 상한 안쪽에서만 움직이고 비용 k×featurize(수 시간)라 후순위.
사용자 결정 대기.

### §12l. EXP13 사전 등록 — TTA tie-break activation (사용자 설계, 결과 전 고정)

**사용자 지시**: "exp들끼리 점수 높은 expert가 여럿이면 TTA로 결정 — perturb해서 여러
exp에 대해 가중치를 얻게 하라." §12k의 margin-반환 δ와 달리 **라벨-의존 임계값 없이**
박빙을 TTA 평균으로 재결정하는 구현.

**설계 (원노브: 12c + TTA 재결정 단계, 나머지 동일)**
- 경합 정의: 1·2위가 {benign, tail}이고 gap < δ_c=2.0 인 행 (**139만 행**; 도달 가능
  오배정의 82%=14.4만 포함). δ_c·pair 선택은 §12k 해부(라벨 사용)에 근거함을 고지 —
  단 상수로 고정, 스윕 없음.
- TTA: 사본 K=8 (원본 1 + perturb 7), x' = x + ε, ε~N(0,(α·σ_f)²), α=0.1,
  σ_f = train 풀 결정적 1M 서브샘플의 per-feature std (라벨-비의존). 같은 사본을
  benign·tail 두 expert가 공유(동일 seed 재생성).
- 재결정: 경합 행의 승자 = argmax{ mean_K score_benign, mean_K score_tail }
  (pair 내부만, 점수 평균 = 가중의 최단순형). 비경합 행 불변. 원본 사본 점수는
  pass-1 재사용.
- pass 2: 12c 동일 (tail로 유입된 행 포함 재실행).
- 비용: TTA featurize 139만×7×2 ≈ pass-1의 1.2배 → 총 ~2.5-3h.

**가설**: 노이즈로 뒤집힌 박빙 tail 승리가 TTA 평균에서 benign으로 복귀 →
benign→tail 14.8만 중 박빙 구간 회복, web precision 상승. inf→benign(대격차 다수)과
dos(동일 벡터 — TTA 사본도 동일 분포)는 원리상 못 고침.

**판정 (결과 전 고정)**: ① 기존 튜플 vs 12c와 global. ② §12k 오라클(δ=2.5,
macro 0.7347) 대비 — TTA가 오라클에 근접하면 "임계값 없는 반환" 성립, 12c 수준이면
perturbation 평균이 무정보(s23의 TTA 실패 양식 재현)로 기록. ③ 부작용 감시: 옳던
박빙 행(진짜 inf/web의 tail 승리)이 benign으로 밀리는 수 — web recall 0.788 유지가
경계선. 스크립트: `tabpfn/nfv3_v3_exp13_tta_tiebreak.py` (12c 복사 + TTA 단계).

**메커니즘 (양성 아닌 원리적 실패)**: 가우시안 perturb는 행을 밀집 manifold에서

이동(bias)**을 만든다. s23("TTA는 소유 expert를 못 찾는다")의 세 번째 독립 확증이며
이번에 메커니즘까지 특정됨.

**방향 제한 변형 (덤프 오프라인, 라벨-비의존 규칙 "tail 승리만 재심")**: 반환 1.6만

val-보정 margin 반환(§12k)이 남은 경로.
