## §1. EXP24A 사전 등록 — 원노브: §12 marginal을 regime-조건부로 (+min-support), anchor 2,000 고정 (결과 전 고정)

스크립트: `tabpfn/nfv3_v3_exp24a_racepfn_regprune.py` (exp23b 사본).
**원노브**: `greedy_regime_prune()` — expert k의 marginal을 **자기 regime에
hard-배정된 masked tune 행 위에서만** 측정: `mean(min_{bank−k} L) −
mean(min_{bank} L)` (balanced-loss 단위). 그 행들에선 anchor의 일반의 기여가
양변에 동일하게 깔려 상쇄되고 블록 고유 가치만 남음(exp23 실측: hard-brute
regime에서 전문가 유무 = oracle ~0.92 vs anchor 상한 ~0.80). greedy 반복
유지. min-support: regime tune 행 < 50이면 후보 제외(23c 9행 bot 방지).
`--prune-mode off` = coverage-생존 전원 유지 ablation 스위치. 문턱
`--prune-min-regime-gain 0.01`(선언 상수). assign_tune은 tune의 full
signature(r̄는 D_expert의 r_max로 클립)로 산출 — 시간순·역할 위반 없음.
합성 테스트: anchor-일반의 교란 하에서 전문가 생존(marginal 2.0)·mega
제거(0.005)·min-support 차단·off 모드 확인.
**예상**: 균형 anchor를 유지한 채 brute·inf·web 전문가 생존 → oracle
0.85±, 시스템은 관문이 여전히 좁아 소폭 개선 예상(관문은 24b 담당).
**판정**: 같은-run 튜플, 관심 = 2e 생존 구성(7a 복원)·oracle·recall.

## §2. EXP24B 사전 등록 — 원노브: scorer를 회귀 → sign 분류 P(U>0)로 (결과 전 고정)

스크립트: `tabpfn/nfv3_v3_exp24b_racepfn_signscorer.py` (exp24a 사본).
**원노브**: scorer = XGBClassifier(binary:logistic), label = 1[U>0]
(U = b_OOF·G − λc 정의 동일), sample_weight = log1p(|G|), Û = P(U>0) ∈
[0,1] — 6자릿수 절대-이득 회귀가 죽이던 판별력을 부호 문제로 전환.
τ_pre 선택(quantile grid)·verifier·pruning(24a) 등 전부 동일. label
단일클래스 퇴화 시 SystemExit.
**예상**: 제안 recall 0.05~0.16 → 대폭 상승, harmful은 verifier가 방어.
**대조군**: 같은 스크립트 `--prune-mode off` 1 run — "bank vs 관문" 원인
분리(24b만 좋아지고 off도 같으면 pruning 무관, off에서만 좋아지면 pruning
잔존 병목).
**실행 체인**: 24a 스모크→기록, 24b 스모크→기록, 24b(--prune-mode off)
기록. 전부 --skip-xgboost(0.7548 인용). 판정 기준: 같은-run 튜플 +
깔때기(제안 recall·utility 실현) + §24 Gate 재판정. 보고서는 exp23 계열
아래 가로선 구분 후 exp24 섹션 신설(사용자 지시).

## §3-결과. EXP24A/24B/24B-off (`144730`/`161322`/`174858`) — 두 knob 모두 기계적으로 작동, 최고는 24b-off(+0.028·harmful 4); 새 병목 발견: hard-brute regime이 D_tune에 부재

**튜플 (system / global / oracle / recall / harmful)**:
- 24a (regime-prune): 0.6721 / 0.6461 (+0.026) / 0.7815 / 0.204 / 52
  — 생존 5 (dos·inf·dos혼합·easy-brute·web-129행), marginal 1.0~10.2로
  재분화 ✓. 단 이 run global 자체가 붕괴(inf .205 — 최대 폭 drift).
- 24b (sign-scorer): 0.6824 / 0.6690 (+0.013) / 0.8206 / 0.184 / 241
  — 채택 138.8k(10×), dos .486→.720, **web .163→.012 붕괴**(web-140행
  expert가 생존한 상태에서 관대해진 관문이 web FP 대량 통과).
- **24b-off (pruning off)**: **0.6978 / 0.6698 (+0.028) / 0.8294 / 0.261 /
  4 (precision 0.9997)** — exp24 최고. web 무손상, dos +0.194, 호출 1.158.

**knob 판정**:
1. **regime-조건부 marginal ✓** — anchor 유지 하에 5명 생존, marginal이
   1.0~10.2로 분리(24a 2e). exp23b의 "쌍둥이 붕괴" 해결.
2. **sign-scorer ✓** — 제안 recall 0.086→0.18~0.26, τ_pre가 확률 단위
   (0.94~0.99)로 안정화, 채택 10×. 단 utility 실현은 여전히 ~0.20.
3. **ablation 귀속**: 24b-off > 24b → pruning은 여전히 소폭 손해
   (run 간 clustering drift로 정밀 귀속은 제한).

**신규 병목 — hard-brute regime의 D_tune 부재**: 세 run 모두 hard-brute
regime(질량 0.36~0.40 최대)이 **masked tune 행 0개**로 min-support 탈락.
D_expert(시간상 앞)의 hard-brute형 실패 서명이 D_tune(val 앞 40%) 구간에
없음 — brute 공격의 성격이 시간에 따라 변한 **temporal drift의 직접
증거**이자, "tune에서 잴 수 없는 전문가" 문제. brute F1이 전 계열에서
0.725에 동결된 이유. 후속 knob: tune-부재 regime은 marginal을 D_route에서
측정(fallback) 또는 D_expert 후반부를 검증용으로 분할.

**24b web 붕괴 메커니즘**: w_bal(web≈1500)이 손실-oracle과 관문을 web
방향으로 편향 — oracle조차 web 0.024(참조 불능). γ tempering이 재부상.

**위치**: 24b-off가 exp23(+0.032)과 유사 macro를 **훨씬 건강한 깔때기**
(recall 3×, harmful 96→4)로 달성. XGB 0.7548 대비로는 여전히 −0.057.
보고서는 exp23 계열 아래 가로선 후 exp24 섹션 신설.
