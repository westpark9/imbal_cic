## 1. BoostPFN (Wang et al., AISTATS 2025) — `tabpfn/scripts/nfv3_v3_exp35_boostpfn.py`

방법: TabPFN-v1을 weak learner로 gradient boosting. 라운드마다 부스팅 가중치로 500행 표본 → v1 in-context fit → train+test logit →
multinomial deviance line search γ_t → w ← w·exp(1−p_true). 예측 = softmax(Σ γ_t h_t).

### 포팅 (`../SOTA/BoostPFN/IMBALCIC_PORT_NOTES.md`)
- 상류는 TabPFN v1(pip 0.1.9)+sklearn 0.24+torch 1.9. 우리 env(py3.13/torch 2.11/sklearn 1.8/numpy 2.4)에서 `tabpfn` 이름은 v3 fork라
  v1을 `tabpfn_v1/`로 **벤더링**(wheel 소스, import 재작성). 체크포인트는 v1.0.0 태그에서 받아(sha256 3c9aadae…, 103,350,223 B)
  `models_diff/..._epoch_100.cpkt`로 배치 — 원본 로더가 epoch 100부터 탐색하며 **없으면 죽은 URL에서 내려받아 그 이름으로 저장**하는
  구조라 404 HTML이 ckpt로 저장되는 사고가 스모크에서 실제로 발생 → 다운로드 분기를 FileNotFoundError로 교체.
- 패치 5종(산술 무변경): `force_all_finite→ensure_all_finite`, `_gb_losses` 제거 → `gb_losses_compat.py`(0.24.2 전사),
  `torch.load(weights_only=False)`, `checkpoint()` 우회(inference) + `torch.autocast`, `layer.py` typing import.
- 합성 스모크: 3라운드 0.3 s, GPU 332 MiB. capped 데이터 스모크 4.9 s.

## 2. LoCalPFN / TabPFN-kNN (Thomas et al., NeurIPS 2024) — `tabpfn/scripts/nfv3_v3_exp36_localpfn.py`

방법: test 행마다 faiss exact-L2로 훈련 풀에서 1000 NN을 컨텍스트로 검색(knn, frozen v1); LoCalPFN(ft)은 같은 검색으로 v1을
AdamW 1e-5로 미세조정(21 epoch × 30 step × 2 query, 각 query에 1000+1000 NN), val AUC로 early stop 후 knn 평가.
- 포팅: 자체 v1 재구현(`pfn.py`)이라 소스 무수정. 유일한 결손 의존성 `faiss-cpu 1.15.0` 설치. 전처리는 저장소의
  `load_tabzilla_data`대로 StandardScaler(train fit)+clip ±10 재현. val = chrono 20% 슬라이스를 클래스당 5,000 캡(전량 4M은 epoch마다 못 돎).
- 비용 실측: 컨텍스트 1000, 배치 256 → 0.76 s/forward, 5.15 GiB(배치 512는 10.2 GiB). 44만 test 전량 ≈ 22분/평가.
- capped 스모크: knn 12 s / ft 27 s 통과.
- **18만 1차 knn run은 97%(3,336/3,440 배치)에서 CUDA OOM**: 저장소 `eval_pfknn`/`eval_ft_knn`이 배치마다 `logits = model(...)[..., :K]`
  — 디코더 출력 전체(1001×B×10)의 **뷰** — 를 `y_pred`에 보관해 GPU에 배치당 5.1 MiB 누적(실측 5.4 MiB; 44만 행 → 17.6 GB).
  TabZilla(≤20만 행)에선 안 드러나는 스케일 문제. 조치: 러너에서 `model.forward` 출력을 `.clone()`하는 래퍼(저장소 무수정, 수치 동일)
  + `--ft-workdir`(학습 workdir의 model_best.pth로 평가만 재실행). ft run은 학습만 끝내고 죽인 뒤 평가만 재실행(전체 재학습 회피).
- **knn 18만 run 완료 (run `20260904_172920`)**: 44만 행 평가 2,732 s(배치 128, ft와 병행), 피크 2.67 GiB(누수 해결 확인).
  macro **0.692** / tail 0.483 vs XGB 같은 행 0.801 / 0.682. 클래스별: benign 0.877, bot 0.989, brute 0.842, ddos 0.902, dos 0.776, inf 0.459,
  **web 0.000**. 스모크 수준 관찰: 1000-NN 컨텍스트에 web(풀 23행)이 들어올 일이 거의 없어 web은 구조적으로 0(BoostPFN과 같은 원인);
  head는 XGB 근접, ddos −0.095. 해석 보류.
- ft 학습(workdir `tabpfn/resume/exp36_localpfn_ft_20260904_155442_2315084`, 21 epoch × 30 step × 2 query, lr 1e-5, ~3.5분/epoch — 대부분
  val 35k행 평가 비용): val(chrono 20%, 클래스당 5k 캡) AUC(ovo) 0.9166(epoch 0 = frozen TabPFN-kNN) → **최고 0.9289 @ epoch 5**
  (= model_best) / weighted-F1 0.803 → 0.810(epoch 5–6) → epoch 7부터 0.71–0.72로 흔들리다 18–19에 0.81 회복 → 20에 0.72.
  즉 미세조정 이득은 val AUC +0.012·F1 +0.008 수준이고 궤적이 불안정(2-query 배치, 30 step/epoch). 해석은 보류.

  vs XGB 0.801 / 0.875 / 0.682. 클래스별: benign 0.877, bot 0.996, brute 0.901, ddos 0.993, dos 0.779, inf 0.464, **web 0.000**.

## 3. DistPFN / DistPFN-T (Lee et al., ICML 2026) — `tabpfn/scripts/nfv3_v3_exp37_distpfn.py`

방법: 학습 없는 사후 보정 `p ∝ y_prob · P_test_avg / prior_train` (P_test_avg = 예측 posterior 평균; -T는 P_test_avg를
τ=CE(P_test_avg, prior)로 softmax 온도조절). 모델 무관 12줄이라 저장소의 TabPFN(pip v2 API) 대신 **우리 TabPFN-v3 fork**에 적용.
- 주의: 저장소의 `cross_entropy(P_test_avg, prior)`는 2-D 입력용이라 1-D에서 AxisError → 바깥 try/except가 데이터셋을 조용히 건너뜀.
  README 의도대로 스칼라 τ로 구현했고, softmax를 **확률 벡터에** 적용하는 것도 원문 그대로.
- 우리 평가셋은 클래스당 10만 캡이라 **컨텍스트 prior(benign 87%) vs 평가 prior(benign 23%)의 라벨 시프트가 구조적으로 존재** —
  1a_prior_shift.csv에 명시. XGB predict_proba에도 같은 보정을 걸어 6행 표로 냄(플러그인 거동 확인용).
- capped 스모크 5.5 s 통과.
- **18만 run 완료 (run `20260904_160005`)**: TabPFN-v3 180k ctx, n_est 4, fit_preprocessors, 44만 행 단일 배치 — predict 379 s, 피크 8.67 GiB
  (메모리 모델 예측 8.37). 파이프라인 정상. 숫자(스모크 수준):

| macro-F1 | raw | +DistPFN | +DistPFN-T |
|---|---|---|---|
| TabPFN-v3 (180k ctx) | 0.796 | 0.800 | 0.745 |
| XGB (같은 18만) | 0.801 | 0.809 | 0.769 |

  - 보정 인자(1a): benign ×0.34, bot ×9.1, brute ×8.1, dos ×8.7, ddos ×3.4, inf ×3.0–3.2, web ×3.2–5.0 — 캡 평가셋의 라벨 시프트를 P_test_avg가
    대체로 잡아냄(benign 예측 prior 0.29 vs 참 0.23). DistPFN-T는 온도조절 후 prior가 거의 균등(0.135–0.15)이 되어 web 인자 ×1057 →
    web precision 붕괴(F1 0.567→0.156), benign도 하락. 해석은 보류하되 **-T 변형은 이 시프트 규모에서 그대로 쓰기 어려움**은 기록.

## 5. 비교 실험 — 같은 C0(100k, benign 0.75, 공격 균등, seed 42) 위에 SOTA 3종 (17:58 발사)

사용자 질문(17:47): "500–1000행은 한계인가, 통상인가?" → **한계**. BoostPFN·LoCalPFN은 TabPFN **v1**(`fit`이 1,024행 초과를 거부, attention이
컨텍스트 길이에 2차 메모리; v1은 ≤1,024행으로 사전학습)을 쓴다. BoostPFN은 "weak learner = 500행"이 설계 자체이고, LoCalPFN은 kNN 컨텍스트
1,000(`--dynamic`도 10√n을 1,000에 캡). 100k 컨텍스트는 v1로 불가(100k² attention). 대신 **같은 100k C0를 각 방법의 '풀'로** 주면 정보 예산이
같아진다: BoostPFN은 C0에서 500행 표본을 뽑고(web 761/100k → 표본당 ~3.8행), LoCalPFN은 C0에서 1000-NN을 검색·미세조정, DistPFN은 C0 위의
TabPFN-v3(=ours)와 XGB-c0에 플러그인. 이것이 캠페인이 XGB-c0를 비교한 방식과 같다.

## 8. BoostPFN 재현 코드 검토 (0908) — "import도 안 되는데 뭘 재현했나"에 대한 사실관계

- **무엇이 import 안 되는가**: upstream 드라이버 `largedataset_boostpfn.py`는 첫 줄부터 `scripts.differentiable_pfn_evaluation`(→ `tabular_evaluation` →
  `tabular_baselines` → **catboost·hyperopt**) 과 `datasets`(→ **openml**)를 import한다. 이들은 논문의 GBDT/AutoML **베이스라인과 OpenML 벤치마크용**
  의존성이지 BoostPFN 방법과 무관하며, 우리 env에 없었다(catboost·openml·hyperopt·gpytorch·autogluon·ConfigSpace). 그래서 upstream 드라이버는
  import에서 죽었고, 부스팅 클래스(`gradient_boost_tabpfn.SamplingGradientboost`, `boost_tabpfn.SamplingAdaboost`, `utils.splitting_predict_proba`,
  `scripts.transformer_prediction_interface.TabPFNClassifier`)는 처음부터 정상 import됐다.
- **내가 실제로 실행한 것**: 위 클래스들을 upstream 드라이버와 같은 인자로 호출하는 우리 러너(exp35). 대응표 —
  upstream 250–258행 `SamplingGradientboost(TabPFNClassifier(device, N_ensemble_configurations=1), ensemble_num, sampling_size, args, split_test=True,
  max_samples=maxsample, batch_test=test_batch, version=2)` → `fit(train_xs, train_ys, test_xs)` → `predict_proba(test_xs)` = exp35 347/390/414/415행.
  README 커맨드 인자(`--sampling_size 0.001 --test_batch 50000 --maxsample 500 --updating exphadamard --ensemble_num 10`, N_en=1, loss CE, replacement False) 전부 동일.

- **논문 정의(arXiv 2605.04363v2 §4.2–4.3, Appendix M)**: DistPFN = Norm(p̂·p̂(y)/p_train(y)), 기본은 p̂(y) = test 평균 예측분포("Multiple").

  공개 코드는 ROC·logloss·acc를 계산하고 n_estimators∈{4,8,16,32} 중 **test ROC 최대**를 고름(논문 미기재).
