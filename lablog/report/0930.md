## 2. EXP62 — 현재 bank(seed 43 · K=4)의 S/V (S1V0)

`tabpfn/scripts/exp62_sv_current_bank.py`(런처 `scripts/run_exp62_local.py`), 결과 `tabpfn/results/20260930_exp62_sv_current_bank_s43/`, 수치 검증 [exp62_numeric_validation.json](../../docs/research/20260930/exp62_numeric_validation.json)(6 arm 모두 metrics·교정/훼손 재집계 일치, threshold 적용 검증 통과), 발표용 멘트 [exp62_briefing_ko.md](../../docs/research/20260930/exp62_briefing_ko.md). 0918.md의 후보 B(K=4 bank에 S/V 재학습)의 첫 실행이다.

**설정.** EXP59의 context ID·Global fitted state·test 확률·PCA·학습 표현을 재사용하고, expert는 같은 context로 **재학습해 fitted state를 저장**한 뒤 그 동일 모델로 route/cal/test를 모두 계산했다. S = class-balanced direct decision-gain regression, V = NLL-gain quantile regression(α=0.25) — 09-17 EXP51의 s1v0 구성. 정책·임계값은 validation(select → confirm 두 구간)에서만 선택(`selected_on_test: false`). max_parallel 2, batch 65,536.

**실행 기록.** attempt 1·2는 두 데이터 모두 `assert_allclose(got, expected, atol=1e-4)`에서 실패 — 재학습한 expert 예측이 EXP59 저장 예측과 일치하지 않았다. EXP59는 expert fitted state를 저장하지 않았고, 같은 context·seed·batch로 다시 fit해도 예측이 완전히 같지 않다(ToN e1 replay check: 160,229행, 최대 절대차 0.0832, argmax 불일치 251). attempt 3(`source_revision 3`)에서 저장 예측 재사용을 포기하고(`expert_test_predictions_reused: false`) 전 단계를 새 fitted bank로 일관되게 재계산했다. 완료 ToN 10:44:02 / CIC 10:48:59, wall 1,886 s / 2,183 s, RSS 최대 25.2 GiB, GPU 최대 4.9 GiB. **따라서 §3의 EXP59 진단(09-28 저장 예측)과 이 절의 S/V 성능은 다른 fitted bank의 결과이며 섞어 읽지 않는다.**

tail F1 = 스크립트의 `tail_classes` 평균(CIC bot·infiltration·web, ToN MitM·ransomware). 호출·채택은 저장 예측에 정책을 적용한 **논리적 건수**이며, 준비 단계에서 모든 expert 예측을 계산했으므로 이 실행시간을 희소 호출의 온라인 비용으로 쓰지 않는다.

- **CIC2018: Global 유지.** validation에서 탐색한 78개 개입 정책 전부 macro-F1 감소 + benign FPR·tail F1 제약 위반 → τ 미선택, 호출 0. 이전 seed 42·K=8(EXP47/51, 0.8107)과 같은 양상이다. 후보 자체가 없는지, S/V 점수가 교정과 훼손을 못 가르는지를 validation의 후보별 교정·훼손으로 먼저 가른다.
- **ToN: +0.0821, 거의 전부 Scanning.** 선택 정책은 τ_pre = −∞(모든 행 호출), τ_post = 0.7096. validation select 구간 Δmacro +0.0894 / Δtail +0.0003 / Δbenign FPR 0. 클래스별 test 변화: Scanning F1 0.0394→**0.8587**(교정 4,736), Benign 0.9217→0.9231(훼손 1,101 전부 benign), Injection +0.0020(교정 632), Ransomware −0.0012, MitM 0. 채택해도 Global과 같은 클래스를 내는 경우가 있어 채택 28,035 ≠ 변경 6,504.
- **주의 3가지.** ① 호출률 100%라 "호출을 생략하는 기능"은 아직 없다. validation 성능이 같으면서 가중 호출률 38.08%인 후보가 있었으나 현재 선택기는 동점이면 먼저 본 정책을 유지한다 — 다음엔 호출 비용을 동점 해소 기준으로 넣되, 38.08%를 그 후보의 test 호출률로 제시하지 않는다. ② tail: select 구간에서는 유지됐지만 confirm 구간에서 −0.0501, test에서 −0.0006. 전체 macro 개선이 tail 개선을 뜻하지 않는다. ③ 이 결과는 **S/V 결합 효과**다. S와 V 각각의 기여는 같은 bank의 제거 비교(global / S·V 없음 / S만 / V만 / S+V)로 확인해야 하며 아직 실행하지 않았다(슬라이드 8장 TBD).
- **SOTA 대비 위치.** ToN S+V 0.7617은 같은 100k 최고 XGB 0.6983과 전체 train XGB 0.7162보다 높지만, 제안 모델은 expert·route에 추가 학습 데이터를 쓰므로 동일 예산의 우위로 해석하지 않는다. CIC는 0.7824로 DistPFN 0.7839 아래.
- 이전 seed 42·K=8/7 S/V(EXP56: CIC 0.8107 호출 0, ToN 0.7555)와 seed·bank가 다르므로 개선량으로 빼지 않는다.

## 3. Expert 역량 A/B 재정리 (EXP59 저장 예측, 09-29 화면 개편)

- 정정한 oracle(test 정답 residual → 가장 가까운 학습 cluster → 그 담당 expert의 예측을 그대로 채점; "여러 expert 중 맞힌 것 선택"은 폐기): CIC 0.7824→0.8996(+0.1172), ToN 0.6796→0.7437(+0.0641). 정답 소속을 아는 조건의 진단이지 상한이 아니다.
- A = 정답 residual 배정 영역, B = 입력 표현·Global 확률로 최근접 배정한 표본군(A 안팎 모두 포함, "담당영역 밖"이 아님). 표본이 다르므로 F1을 빼지 않고 각 범위 안에서 Global 대비 교정/훼손을 읽는다.

| 대표 expert | A 교정 / 훼손 | B 교정 / 훼손 | 판정 |
|---|---:|---:|---|
| CIC e3 (infiltration) | 9,598 / 0 | 776 / 14,119 | R3 infiltration F1 0.440→0.967. B에서는 benign 22,165 중 21,535를 infiltration으로 오인(precision 12.4%) |

### 10-01 분석 — tail 클래스의 benign 혼동은 feature 유사성 문제인가? (저장 예측·feature 재집계, 추가 추론 없음)

### 10-01 분석 — ToN scanning이 Global에서 낮은 이유는 C0의 운영점(benign:scanning 비율)이다

- C0 레시피(benign 0.75, 공격 균등)상 scanning은 약 2,800행(D_global 풀에 8,940행 보유)이고 benign은 75,000행이라 context 내 비율은 약 27:1이다. 절대 수가 "너무 적은" 것이 아니라 다른 공격 클래스와 같다.
- EXP63 K=6 cache의 Global 확률(`eval_p0`)로 보면 true scanning 6,029행 중 Global이 benign으로 부른 비율 97.6%, **scanning 확률이 2위인 행 97%**, 중앙값 p(scanning)=0.142 vs p(benign)=0.846. 즉 scanning 신호는 있고 benign prior에 눌린 운영점 문제다.
- 그러나 현재 C0 위에서 prior만 바꾸는 것으로는 expert만큼 못 간다. scanning 확률 ×5 → recall 0.46·benign FP 약 3,600, ×10 → recall 0.64·FP 약 28,800(benign 1/20 표본 추정). expert e1(scanning block 4,470 + anchor)과 V는 recall 0.87·FP 323이다. block은 posterior의 모양을 바꾸지 prior만 바꾸지 않는다.
- 함의: C0에 scanning을 더 넣고(풀에 8,940행 있음) β를 train slice에서 고정한 Global이 기준점이 되어야 한다. EXP54에서 balanced context + β0.5 = 0.7713 > 당시 시스템 0.7540(ToN, 20k context, β는 test 판독)이 이미 그 방향을 보여줬고, 0918.md 09-29 후보 A(matched global control)가 그 실험이며 미실행이다. ToN S+V의 +0.082(0.6796 대비)는 그 기준점 위에서 다시 재야 한다.
