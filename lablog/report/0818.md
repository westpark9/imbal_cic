# 0818 — exp1 재실행 (test cap 제거), 보고서 갱신

## 무엇을 바꿨나

`test_cap_per_class`를 100000 → 0으로 바꿔 exp1(100만 행 XGB vs TabPFN)을 4개 데이터셋에
재실행했다. 한 knob만 바뀐 run 쌍이 남아 있다:

- capped: `20260817_072033/081129/090418/093806_*_exp1_1m`
- uncapped: `20260818_030904/042459/053139/071152_*_exp1_1m`

exp2(full-XGB)도 같은 짝이 있다 — `20260817_161427_nfv3_cic2018_exp2_fullxgb`(cap 100k)와
`20260818_111317_nfv3_cic2018_exp2_fullxgb`(cap 없음)은 `test_cap_per_class` 외 args가 동일하다.

## 결과

### 1. test cap이 소수 클래스 F1을 부풀린다 (CIC2018 full-XGB, 학습 조건 동일)

| | cap 100k | cap 없음 | Δ |
|---|---|---|---|
| `web_attacks` F1 (509행) | 0.603 | 0.162 | −0.441 |
| `infiltration` F1 | 0.488 | 0.429 | −0.059 |
| `benign` F1 | 0.876 | 0.995 | +0.119 |
| macro | 0.8063 | 0.7548 | −0.052 |
| weighted | 0.874 | 0.983 | +0.109 |

cap은 test 분포를 평탄화해 소수 클래스 precision을 올린다. **0812/0813 보고서의 macro 숫자는
이 회차 숫자와 직접 비교 불가.**

### 2. exp1 (동일한 100만 행, test pool 전체) — macro F1

| 데이터셋 | XGB | TabPFN | Δ | 시간 배수 |
|---|---|---|---|---|
| CIC2018 | 0.7568 | 0.7518 | −0.005 | 65.7× |
| BoT-IoT | 0.5639 | 0.5492 | −0.015 | 69.4× |
| ToN-IoT | 0.6964 | 0.6672 | −0.029 | 46.9× |
| CIC2017 | 0.6538 | 0.6505 | −0.003 | 7.9× |

12개 지표(4 데이터셋 × macro/weighted/tail) 중 TabPFN이 앞선 것은 2개:
CIC2017 tail +0.049(전부 `heartbleed` — **test 3행**), BoT-IoT weighted +0.015
(`ddos` 0.031→0.067, 양쪽 다 붕괴).

TabPFN `fit`은 데이터셋 무관 1,241–1,265초로 일정(컨텍스트가 항상 100만 행).
predict만 test 행 수에 비례(56만 행 754초 → 550만 행 7,315초).

### 3. 100만 행 → 전체 행 (XGB, 같은 test set)

| 데이터셋 | 100만 | 전체 | Δ | 학습 배수 |
|---|---|---|---|---|
| CIC2018 | 0.7568 | 0.7548 | −0.002 | 12.1× |
| BoT-IoT | 0.5639 | 0.5610 | −0.003 | 10.2× |
| ToN-IoT | 0.6964 | 0.6687 | **−0.028** | 16.5× |
| CIC2017 | 0.6538 | 0.7643 | **+0.111** | 1.7× |

- ToN-IoT 하락은 `ransomware` 0.385→0.150, `mitm` 0.208→0.162. 795행·1,204행짜리 클래스가
  물량이 늘수록 더 밀린다.
- CIC2017 상승 +0.111은 두 클래스가 전부다: `heartbleed`(test 3행) 0.000→0.800,
  `infiltration`(test 8행) 0.000→0.857. (0.800+0.857)/15 = 0.110.
  100만 stratified 샘플링이 이 둘의 학습 행을 4개·12개로 깎은 것이 원인 —
  **데이터 양의 효과가 아니라 샘플링이 마이크로 클래스를 지운 효과.**

## 결론

- **TabPFN 100만 상한은 이 데이터에서 병목이 아니다.** 병목은 chronological drift와
  마이크로 클래스이며, 둘 다 데이터를 더 넣어서 해결되지 않는다.
- **동일 데이터 조건에서 TabPFN은 4/4 데이터셋 macro F1이 XGBoost보다 낮다.** 0812/0813의
  "명확히 이기는 설정 없음"이 test cap 제거 후에도 유지되며, 오히려 더 명확해졌다.
- **stratified ratio-preserving 샘플링은 마이크로 클래스에 대해 안전하지 않다.**
  클래스당 최소 행 보장이 없으면 학습 행이 한 자리수까지 떨어진다.
