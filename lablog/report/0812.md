# 0812 Experiment Log: `tabpfn/` TabPFN-v3 vs XGBoost multiclass sanity check

## Goal

- `tabpfn/` 서브체크아웃(Prior-Labs TabPFN-v3)에 대해, 이 프로젝트가 쓰는 실제 CIC 데이터
  (CIC-IDS2017 전체 클래스 raw / NF-CSE-CIC-IDS2018-v3)에서 TabPFN-v3가 XGBoost baseline
  대비 얼마나 하는지 standalone sanity check.
- **주의**: 이 로그는 `src/s2x_code_ood_*.py` 계열의 frozen 실험 기록이 아님. 스크립트
  자체 docstring에도 명시: "a quick standalone check of the TabPFN library itself, not
  part of that paper's experiment record". CLAUDE.md의 results/Args 로그 관례는 지키되,
  OOD-MoE 논문 프론티어(`s30_code_ood_v2_resnet_cifar.py`)와는 별개 트랙.

## Setup

- Script: `tabpfn/nfv3_cic2018_multiclass_test.py` (단일 스크립트, `--target-dataset` /
  `--protocol` 두 축으로 4가지 조합 실행)
- 데이터셋 두 종류:
  - `cic2018` → `data/nfv3_energy_suite_uncapped_scenarios.pkl`에서 `dataset_names ==
    "cse_cic_ids2018"` 서브셋만 사용 (NetFlow-v3, 53-col 스키마)
  - `cic2017_full` → `data/cic2017_full_raw.pkl`, CICFlowMeter 원본 15개 클래스 전부
    (Mon-Thu/Friday 제외 없음 — `chrono_v2`와는 다른 split)
- `--protocol`이 split 정책 + train cap 정책을 한 번에 결정:
  - `reproduce` = random 60/20/20 stratified split + **class당 3,000개 고정 cap**
    (참조 논문 TabPFN-IDS의 재현 설계, Sec III.E.4)
  - `sota` = chronological split(cic2018은 real timestamp, cic2017_full은 synthetic
    `time_proxy` — 실제 타임스탬프 없음) + `--max-train-samples`로 **자연 클래스 비율을
    유지한 stratified train budget** (CLAUDE.md M4 기준 이 프로젝트의 기본 입장)
- 체크포인트: `tabpfn-v3-classifier-v3_20260417_multiclass.ckpt`, `n_estimators=4`
  (참조 논문 값), feature scaling 없음(TabPFN 내부 전처리에 위임).
- XGBoost baseline은 `s43`/`s44` expert와 동일 하이퍼파라미터, TabPFN과 완전히 같은
  train/test row에 대해 같은 스크립트 안에서 학습·평가.

## Results (macro F1 / tail F1 / weighted F1, `test_cap_per_class=100,000`)

### cic2018 (NF-CSE-CIC-IDS2018-v3)

| protocol | tabpfn_v3 macro/tail/weighted | xgboost macro/tail/weighted |
|---|---|---|
| reproduce (3,000/class, random split) | 0.795 / 0.721 / 0.848 | 0.810 / 0.737 / 0.861 |
| sota (chronological, 100k stratified) | 0.795 / 0.668 / 0.871 | 0.718 / 0.488 / 0.874 |

- `reproduce`에서는 XGBoost가 세 지표 모두 근소 우위.
- `sota`(chronological split)에서는 **TabPFN이 macro/tail에서 XGBoost를 앞섬** — chronological
  split으로 넘어가면서 XGBoost tail F1이 0.737→0.488로 크게 떨어지는 반면 TabPFN은
  0.721→0.668로 덜 떨어짐. weighted F1은 거의 동률.

### cic2017_full (raw 15-class)

| protocol | tabpfn_v3 macro/tail/weighted | xgboost macro/tail/weighted |
|---|---|---|
| sota (chronological time_proxy, 1M stratified) | 0.670 / 0.328 / 0.968 | 0.717 / 0.446 / 0.973 |
| reproduce (3,000/class, random split) | 0.761 / 0.403 / 0.993 | 0.856 / 0.628 / 0.995 |

- 두 protocol 모두 **XGBoost가 전 지표 우위**, 특히 tail F1 격차가 큼(reproduce: 0.403 vs
  0.628).
- `sota` run은 학습 row를 1,000,000까지 그대로 사용해서 TabPFN fit+predict가 약 4.1시간
  걸림(XGBoost는 292초, 약 50배 차이) — 스크립트 docstring이 권하는 "dial it down yourself
  for faster sota runs"를 따르지 않은 채로 돌린 run이라 다음에 재현할 때는
  `--max-train-samples`를 낮춰서 도는 게 맞음.

## Takeaway

- **`reproduce` protocol(논문 그대로 class당 3,000 cap)에서는 두 데이터셋 모두 XGBoost가
  TabPFN-v3보다 우위.** cic2017_full에서는 그 격차가 특히 크다(tail F1 0.403 vs 0.628).
- **`sota` protocol(chronological split + 자연 분포비율 유지 budget)에서는 결과가 갈림:**
  cic2018에서는 TabPFN이 macro/tail에서 XGBoost를 앞서지만, cic2017_full에서는 여전히
  XGBoost가 전 지표 우위.
- 종합하면, 이 프로젝트 데이터(강한 tail-class 불균형 + chronological/전체-클래스 split)에서
  **TabPFN-v3가 XGBoost baseline을 확실히 능가하는 케이스는 없었다** — cic2018 sota에서
  부분적 우위 정도가 전부.
- 학습 row 수가 늘어날수록(100k, 1M) TabPFN의 fit+predict 시간이 XGBoost 대비 수십~수백 배로
  벌어짐 (cic2017_full sota: 14,636s vs 292s). 성능 우위가 없는 상황에서 이 비용 격차는
  실용성 면에서 TabPFN을 더 불리하게 만듦.
- **Open question**: cic2018 sota가 유일하게 TabPFN 우위를 보인 케이스인데, 원인이 (a)
  real timestamp 기반 chronological split(cic2017_full은 synthetic `time_proxy`라 진짜
  chronological이 아님) 때문인지, (b) NetFlow-v3 스키마(53 feature) 자체의 특성 때문인지
  구분이 안 됨 — 분리 확인 필요.
