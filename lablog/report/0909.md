# 0909 — 고정 global 위의 scorer/verifier 교정 실험

**결론: 이번 실험에서 최종 모델 성능은 개선되지 않았다.** Test 4,023,114행의 최종 예측은 6조건 모두 global과 같다. EXP38·39가 정상 종료했다는 사실과 연구 목표를 달성했다는 것은 다르다.

2026-09-10 설명 보완: 이번에 실행한 것은 **기존 context·global·expert bank를 고정한 scorer/verifier 비교**다. 세부 패턴의 context 지원 보강과 새 expert 구성은 아직 실행하지 않았다. 아래 단계 번호는 모델 내 위치이며, 6조건을 차례로 연결한 하나의 모델을 뜻하지 않는다. 각 조건은 별도로 평가했다.

이전 표에서 혼동을 만든 **expert 전체 강제 적용의 큰 훼손 수**는 최종 모델의 훼손 수가 아니다. 실제 적용 결과는 §3-A, 무조건 적용 진단은 §3-B, 어디서 교정 후보가 사라졌는지는 §4-A에서 각각 확인한다.

| ⑦ Verifier 학습 목표 | Normalized NLL gain의 0.25 분위수 예측. | `decision_post_raw`는 raw 입력을 유지하고 **결정 손익의 평균 회귀**로 변경. Route의 클래스별 균형 sample weight 적용. | Expert만 정답 +1, global만 정답 −1, 나머지 0. 중간 클래스 교정도 보상. 목표와 회귀 방식이 함께 바뀌는 하나의 구성 변경으로 기록. |
| ⑧ Calibration → 최종 교정 | NLL 순이득 최대화, 기존 오경보·harmful fraction·호출량 제약. | 모든 조건에 **Δmacro-F1 최대화**, tail 평균 ΔF1≥0, brute_force/ddos/dos 각각 ΔF1≥0, benign ΔFPR≤0.0005, 결정 손익 표본≥30 적용. | 학습 손익은 F1과 다르므로 최종 예측의 F1을 직접 계산. 과거 train prior로 confusion matrix를 표준화. 이 공통 평가 변경과 각 arm의 모델 변경을 구분. |
| ⑨ 확인 구간·비용 | 기존 calibration을 이용한 임계값 선택. | Route와 겹치는 hash 제외 후 class×scenario 안에서 앞 70% 선택 / 뒤 30% 확인. 확인 구간의 선택 구간 중복 hash도 제외. 호출 상한은 1.0, harmful fraction은 진단 지표로 전환. | 표본 비중 차이와 시간 전이를 구분. 이번 우선 목표는 교정 성능이며 비용만 줄어든 결과를 개선으로 세지 않음. 전역 달력 절단이 아닌 scenario 내부 시간 분할. |

학습 목표 `Δk = 1[expert 정답] − 1[global 정답]`. 학습은 모든 pair의 관측 결과를 이용한 지도학습이다. 실제 추론은 **global → scorer의 예상 점수 → 선택 expert만 실행 → verifier 채택/거절** 순서를 유지한다.

## 3. 최종 결과와 expert 진단을 구분해서 읽기

### 3-A. 실제 선택된 최종 정책 — 성능 개선 0

교정은 `global 오답 → 최종 정답`, 훼손은 `global 정답 → 최종 오답`인 행 수다. 한 행에서 두 모델 모두 오답인 상태로 라벨만 바뀌면 어느 쪽에도 포함하지 않는다.

| 방법 | Macro-F1 | Tail F1 | Benign FPR | 교정 / 훼손 행 | 해석 |
|---|---:|---:|---:|---:|---|
| global | 0.762086 | 0.548877 | 0.1523% | 0 / 0 | 기준선 |
| legacy | 0.762086 | 0.548877 | 0.1523% | 0 / 0 | global 유지 |
| post_z | 0.762086 | 0.548877 | 0.1523% | 0 / 0 | global 유지 |
| post_raw | 0.762086 | 0.548877 | 0.1523% | 0 / 0 | global 유지 |
| decision_post_raw | 0.762086 | 0.548877 | 0.1523% | 0 / 0 | global 유지 |
| decision_both_raw | 0.762086 | 0.548877 | 0.1523% | 0 / 0 | global 유지 |
| dense_decision_raw | 0.762086 | 0.548877 | 0.1523% | 0 / 0 | global 유지 |

**“개입 0”은 calibration에서 임계값 쌍을 고를 때 모든 후보가 탈락해, test에 들어가기 전에 “항상 global 사용” 정책을 선택했다는 뜻이다.** Code의 `global_fallback`은 pre/post 임계값을 `None`으로 저장하고 global 예측을 그대로 반환한다. Test 각 행에서 verifier가 판단한 끝에 전부 거절했다는 뜻이 아니다.

따라서 이 표로 확인한 최종 성과는 **Δmacro-F1=0, Δtail-F1=0, 교정=0, 훼손=0**이다. 성능 개선 성공으로 볼 수 없다. 비교용 cache를 만들 때는 모든 expert를 이미 실행했으므로 이 결과를 실측 계산비용 절감으로도 주장하지 않는다.

### 3-B. 진단용 강제 적용 — 최종 정책에 사용하지 않은 예측

아래는 scorer·verifier를 우회한 별도 계산이다. `expert1_always`는 test 전체 4,023,114행을 expert 1의 정답 여부와 관계없이 그 expert의 예측으로 바꾼다. 반대로 oracle은 실제 정답을 보고 맞힐 수 있는 expert를 선택한다. **§3-A의 모델 처리 결과에 이어서 적용한 단계가 아니다.**

| 진단 | Macro-F1 | Tail F1 | Benign FPR | 교정 / 훼손 행 | 계산 방법 |
|---|---:|---:|---:|---:|---|
| correctness_oracle | 0.849159 | 0.748924 | 0.0693% | 30,663 / 0 | 정답을 사용하는 진단 |
| expert1_always | 0.631228 | 0.362831 | 53.4832% | 27,673 / 1,869,000 | 단일 expert 전체 적용 |
| expert2_always | 0.694409 | 0.409213 | 0.1343% | 2,951 / 35,400 | 단일 expert 전체 적용 |
| expert3_always | 0.651426 | 0.367657 | 38.5245% | 24,524 / 1,344,307 | 단일 expert 전체 적용 |

즉 **1,869,000건 훼손은 expert 1을 전 행에 강제 적용했을 때**의 결과다. 이 expert가 일부 global 오류를 고칠 수 있더라도, 다른 영역에서 global의 정답을 대량으로 망가뜨린다. 그래서 expert를 단독 대체 모델로 쓸 수 없고, 도움이 되는 구간을 선별해야 한다. Correctness oracle의 30,663건은 현재 bank가 제공하는 교정 가능 사례 수이며, 학습된 라우터가 전부 회수할 수 있다는 보장은 없다.

## 4. 무엇을 바꿨고, 어디서 교정이 막혔는가

### 4-A. 임계값을 적용하기 전의 단계별 진단

2026-09-10에 저장된 예측을 다시 집계했다. 재학습이나 새 정책의 test 실행은 하지 않았다. Calibration 선택 구간은 81,472행이며 global 오답 6,814행 중 **6,025행은 bank의 어떤 expert가 정답**이다.

다음 표는 pre 임계값을 잠시 우회하고 scorer가 1위로 고른 expert를 조사한 것이다. “Verifier 양수”는 그 후보에 `post > 0`만 적용한 진단이며, calibration이 최종 채택한 정책이 아니다. Dense 행은 scorer 대신 모든 expert의 post 정보를 사용하므로 별도 진단이다.

| 조건 | 1위 후보가 교정 가능한 행 / 6,025 | 후보 회수율 | Verifier 양수 중 교정 / 훼손 | 이 비교에서 확인한 점 |
|---|---:|---:|---:|---|
| legacy | 5,286 | 87.7% | 0 / 0 | Scorer가 맞는 후보를 상당수 골랐지만 NLL verifier의 양수 영역에 교정 사례가 없음 |
| post_z | 5,286 | 87.7% | 0 / 0 | z 추가만으로 이 현상을 해결하지 못함 |
| post_raw | 5,286 | 87.7% | 0 / 0 | raw 추가만으로 이 현상을 해결하지 못함 |
| decision_post_raw | 5,286 | 87.7% | 2,250 / 1,590 | 기존 scorer를 유지하고 verifier를 결정 손익으로 바꾸면 교정 후보가 통과하지만 훼손도 통과 |
| decision_both_raw | 2,793 | 46.4% | 2,022 / 1,205 | 새 scorer는 후보 단계에서 더 많은 교정 기회를 잃음. Scorer 개선이 확인된 것이 아님 |
| dense_decision_raw | 3,029 | 50.3% | 2,821 / 2,211 | 모든 post 정보를 보아도 현재 verifier 점수만으로 교정/훼손 구분이 충분하지 않음 |

**이번 calibration에서 가장 먼저 확인된 차단점은 NLL verifier의 양수 판정이다.** 최종 채택 0만 보고 scorer가 아무 후보도 찾지 못했다고 해석하면 안 된다. 또한 새 scorer에서는 감독 신호·회귀 방식·가중치가 함께 바뀌었으므로 “임시 verifier 의존성을 제거한 것만이 회수율 하락의 원인”이라고 단정할 수도 없다.

이 관찰을 test 전체로 일반화하지 않는다. 같은 `post_raw`의 `post > 0` 진단은 calibration 선택에서는 교정/훼손 0/0이지만, 저장된 test 예측에서는 2,238/177이다. 이는 **선택 구간에서 관측한 교정 양상이 그대로 반복되지 않았음**을 보여 주며 calibration의 시간·scenario·오류 패턴 대표성을 점검할 이유다. 이 사후 수치로 임계값을 새로 선택하지 않았고, 원래 test 최종 정책은 계속 global 유지다.

### 4-B. 최종 임계값 선택에서 남은 후보가 없는 이유

다음 수치는 **calibration 선택 구간에서 기존 격자의 최고 macro 후보**이며 채택된 정책이나 test 개선 수치가 아니다. ΔF1은 과거 train prior로 표준화한 confusion matrix에서 계산했다. 교정/훼손은 원래 calibration 표본의 행 수다.

| 조건 | 양의 macro 후보 / 전체 | 최고 Δmacro | 해당 Δtail | 해당 Δbenign FPR | 교정 / 훼손 | 선택되지 않은 이유 |
|---|---:|---:|---:|---:|---:|---|
| legacy | 0 / 52 | +0.000000 | +0.000000 | +0.0000%p | 0 / 0 | 교정 표본 부족·일부 tail 하락 |
| post_z | 0 / 52 | +0.000000 | +0.000000 | +0.0000%p | 0 / 0 | 교정 표본 부족·일부 tail 하락 |
| post_raw | 0 / 52 | +0.000000 | +0.000000 | +0.0000%p | 0 / 0 | 교정 표본 부족(라벨 변경 0) |
| decision_post_raw | 50 / 65 | +0.018208 | +0.042495 | +0.1254%p | 764 / 28 | benign FPR 상한 초과 |
| decision_both_raw | 65 / 65 | +0.018270 | +0.042661 | +0.1478%p | 780 / 33 | benign FPR 상한 초과 |
| dense_decision_raw | 4 / 18 | +0.016003 | +0.037473 | +0.2060%p | 764 / 46 | benign FPR·일부 중간 클래스 제약 또는 표본 부족 |

§4-A의 후보에 pre/post 임계값을 함께 적용하면 위 후보들로 좁혀진다. 같은 raw 입력에서 **결정 손익 목표**로 바꾸면 최고 macro 후보에 infiltration 교정 764행과 benign 훼손 28행이 남는다. Scorer까지 바꾸면 교정 780행(infiltration 779·dos 1)과 benign 훼손 33행이다. 이것은 calibration에서 관측한 목표·회귀·가중 방식 변경의 효과이며, 최종 test 향상으로 주장할 수 없다.

선택 구간의 benign은 22,325행이다. ΔFPR≤0.0005를 지키려면 기존 오경보 교정을 차감한 신규 오경보가 약 11행 이하여야 한다. 28·33행을 함께 채택하는 기존 후보들은 이 상한을 넘는다.

## 5. 사후 진단: 임계값 격자에서 빠진 구간

기존 격자는 전체 행 점수의 99% 분위수까지만 생성했다. `decision_both_raw`의 post 임계값 최댓값은 **0.611627**이지만, 라벨이 바뀌는 후보의 post 점수 95% 분위수는 **0.910811**이다. Pre 점수 역시 변경 후보 상위 구간이 충분히 포함되지 않았다. 후보가 적은 교정 문제에서 전체 행의 분위수만 사용하면 필요한 세밀한 선택 범위가 빠질 수 있다.

**완료된 모델·cache와 calibration 선택 구간만 사용**해 라벨 변경 후보 점수의 분위수를 추가했다. Benign·tail·중간 클래스·최소 교정 표본 제약은 그대로 유지했다. 확인 구간과 test에는 새 후보를 적용하지 않았고, 원래 EXP39의 결과를 덮어쓰지 않았다.

| 조건 | 추가 격자의 pre / post 후보 | Calibration Δmacro | Calibration Δtail | Calibration Δbenign FPR | 교정 / 훼손 |
|---|---:|---:|---:|---:|---:|
| decision_post_raw | 0.968356 / 0.870510 | +0.008035 | +0.018750 | +0.0493%p | 310 / 11 |
| decision_both_raw | 0.926194 / 0.611627 | +0.009718 | +0.022659 | +0.0493%p | 376 / 11 |
| dense_decision_raw | -inf / 0.929575 | +0.005550 | +0.012926 | +0.0269%p | 215 / 6 |

이 결과는 **제약을 완화하지 않고도 탐색 격자를 수정할 근거**다. 새 모델의 검증된 성능으로 보고하지 않는다. 특히 11행 후보는 상한 근처이므로 다음 독립 확인 구간에서 안정성을 확인해야 한다. §4-A에서 확인한 구간별 차이도 있어, **격자만 보완하면 test 성능이 나아진다는 결론은 아직 없다.**

![Calibration 임계값 후보와 benign 오경보 상한](../html_report/assets/exp39_calibration_frontier.svg)

그림은 calibration의 낮은 오경보 증가 영역(0–0.25%p)을 표시한다. 원래 격자와 사후 보완 격자를 구분하며, 모두 test 수치가 아니다.

## 8. 9/10 보완 — 신규 논문의 성능 비교군 포함 판단

| 방법 | 이번 판단 | 우리 모델과의 관계·비교 범위 |
|---|---|---|
| Xiaomi-TabLDM | **주요 성능 비교군에 포함** | 공식 분류 코드·checkpoint가 있어 실행 비교가 가능하다. 프리프린트라는 이유로 제외하지 않는다. 내부 FFN MoE와 우리 context별 PFN expert는 학습·선택 단위가 다르지만, 조건부 expert 사용의 관련 연구로도 다룬다. [공식 코드](https://github.com/xiaomi-research/xiaomi-tabldm), [논문](https://arxiv.org/abs/2609.03880) |
| HINT | **조건부 호출 방식 비교군에 포함** | kNN confidence → 검색 context를 넣은 TabPFN 호출이 우리 gate/context 주장과 가깝다. Streaming 원문과 fixed-split adaptation을 구분하고, test 라벨로 memory를 갱신하지 않는 비교부터 수행한다. [원문](https://arxiv.org/html/2609.07956v1) |
| LoGIC | **관련 연구 포함, 현재 주 성능표에서는 제외** | 그래프 node 분류의 구조 검색·unlabeled halo가 핵심이다. NetFlow에 feature/coverage 부분만 이식하면 LoGIC-inspired adaptation으로 표시한다. [원문](https://arxiv.org/html/2609.05955v1) |

MoE라는 공통점만으로 우리의 독창성을 주장할 수 없다. Xiaomi는 사전학습된 Transformer 내부 표현의 expert 선택, 우리는 frozen PFN의 context별 출력 선택과 교정을 다룬다. 우리의 기여는 같은 global 위에서 실제 교정이 늘어나는 결과로 입증해야 하며, 이번 최종 ΔF1=0으로는 아직 그 성능 기여를 입증하지 못했다.

Xiaomi와 같은 C0 100k를 사용한 비교는 backbone 비교다. Ours 전체 시스템은 expert bank·route의 추가 라벨도 쓰므로 별도로 접근 가능한 train pool과 검증 예산을 맞춰야 한다. [상세 비교 판단과 프로토콜](../../docs/research/20260910/sota_inclusion_decision.md).
