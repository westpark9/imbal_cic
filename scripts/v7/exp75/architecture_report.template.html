1. 무엇을 바꾸었고, 무엇을 비교하는가

기존 구조는 Global이 놓친 공격을 expert와 S/V가 교정하도록 설계했다. 10/14 시나리오에서는 자연 배분 두 데이터 모두 호출 0건이었고, 균등 배분의 일부 교정만으로는 단일 TabPFN을 넘지 못했다. 이번에는 입력이 tail인지 먼저 판별해야 하는 호출 절차 없이 분류를 개선할 수 있는지 두 경로를 시험했다.

2안 · 공통 표현 + 세 분류 head

누적 전체 context→고정 TabPFN 표현→분포별 head 3개→log score 평균

전체 누적 context와 네 estimator를 유지하고, 공통 embedding 위에 작은 MLP 세 개를 학습했다. 각 head는 전체 클래스를 예측하되 목표 prior가 자연·균형·역빈도로 다르다. 클래스 하나씩을 맡는 expert가 아니다.

BalPoE (CVPR 2023)의 분포별 학습과 보정된 log-space 결합을 TabPFN 표현에 적용한 탐색안이다.

3안 · 고정 TabPFN의 context 최적화

학습 풀에서 2,048행→context feature 최적화→고정 TabPFN 추론

클래스 균형으로 초기 context를 뽑고, 나머지 train을 맞히는 손실로 feature만 갱신했다. Context 라벨과 backbone은 고정한다. 동일한 초기 context의 미최적화 대조군도 평가했다.

In-Context Data Distillation with TabPFN (2024)을 참고했다. 학습된 feature token을 실제 생성 가능한 네트워크 flow로 해석하지 않는다.

공통 시나리오·데이터·라벨 사용량

최종 train은 Benign 75,000행 + 공격 25,000행이다. 두 배분은 공격 안에서 자연비율 또는 균등을 적용하며 가용 사례 수로 제한된다. Benign도 단계마다 추가한다. 최초 공격 출현 순서를 따르지만 raw timestamp·환경 drift 재현은 아니다.

CIC2018: Benign/Brute Force/DoS → DDoS → Web attacks → Infiltration → Bot.
ToN: Benign/Scanning/DoS → Injection/DDoS → Password → XSS → Ransomware/Backdoor → MitM.

기존 EXP72/73의 train·validation·test ID와 순서를 그대로 재사용했다. 정책별로 CIC2018 3,042,473행, ToN 2,271,723행을 각각 한 번 평가한다. 별도 validation은 최종 약 8천 행이며 공개된 클래스만 사용한다.

2안은 validation tune 약 40%를 head 학습에, cal의 두 절반을 epoch 선택과 temperature 보정에 각각 사용한다. XGB·단일 TabPFN에도 같은 추가 라벨 접근을 허용했지만 실제로는 사용하지 않았다. 따라서 같은 수의 학습 라벨을 소비한 구조 단독 비교는 아니다. 단독 head와 결합의 비교는 같은 추가 라벨과 표현을 공유한다.

3안은 train 일부를 context, 나머지를 학습 query로 쓰고 validation cal로 checkpoint를 선택한다. 모든 구조에서 test 정답은 학습·선택에 사용하지 않는다. 과거 S/V 모델은 train을 Global/expert/route로 나눴으므로 새 구조와의 차이에는 Global context 크기도 포함된다.

2. 두 구조의 최종 출력은 아직 단일 TabPFN을 넘지 못했다

아래는 전체 순차 재생 Macro-F1 (%)이다. 최종 버전 하나의 test 성적이 아니다. 기본값인 지연 없음은 매 단계 준비된 새 버전을 바로 사용하는 비교이며 oracle이 아니다.

기존 S/V는 EXP73, XGB·TabPFN은 EXP72의 동일 시나리오 결과다. 2안의 주 결과는 세 head 결합, 3안의 주 결과는 validation이 선택한 context다. 단독 head는 다음 절의 진단 결과로 분리했다. 나머지 SOTA 3종은 10/14 탭에서 확인할 수 있다.

3. 2안: 단독 head에 남아 있는 능력을 결합이 살리지 못했다

이 절의 단독 head 비교는 항상 갱신 지연 없음 · 전체 재생이다.

자연분포 head는 현재 누적 train prior를 목표로 한다. 균등 공격 배분에서도 Benign까지 균등한 prior는 아니다. 아래 단독 head는 같은 embedding·추가 라벨·test 행에서 측정했다.

자연 배분 · CIC2018

자연분포 head의 Macro-F1은 79.27%로 단일 PFN 77.72%보다 높다. Infiltration F1은 23.36 → 37.02%지만 Web attacks는 22.22 → 19.77%다. 모든 희소 클래스가 함께 좋아진 결과는 아니다.

자연 배분 · ToN

자연분포 head는 78.11%로 PFN 73.66%보다 높고 XGB 79.37%보다 낮다. Scanning F1은 0.00 → 48.33%, MitM은 17.98 → 25.47%로 오른다. Ransomware는 60.92 → 49.02%로 내려간다.

결합에서 확인한 병목: 세 목표 prior의 지수 1·0·−1을 같은 가중치로 결합해 prior 효과가 상쇄되는 설계다. 보정·학습 가정 아래 균형 목표를 지향하지만, 불균형한 IDS 평가에서 Macro-F1이나 낮은 정상 오탐을 보장하지 않는다. 실제로 자연 배분의 Benign FPR은 자연 head → 결합에서 CIC2018 0.017 → 8.533%, ToN 8.018 → 20.187%로 증가했다.

자연 배분 CIC2018의 결합은 Infiltration Recall을 PFN의 13.45 → 79.97%로 높이지만 Precision은 88.75 → 3.06%로 낮춘다. ToN Ransomware도 Recall 70.24 → 98.45%, Precision 53.78 → 1.75%다. 공격을 더 많이 맞히면서도 다른 행을 그 공격으로 훨씬 더 많이 부른다.

선택 조건의 head별 F1과 오탐

Head별 전체 클래스 F1 · 같은 test 행의 비교

오탐이 어디서 들어왔는가

항상 지연 없음. FP를 실제 Benign에서 온 행과 다른 공격에서 온 행으로 분리한다. 이 표는 같은 평가 전체에서 계산한 분류 능력이며, 정답으로 담당 영역을 배정한 oracle 평가가 아니다.

해석: 같은 표현을 쓰는 자연 head가 일부 희소 공격을 구분하므로, 현재 결과만으로 TabPFN 표현에 분류 정보가 없다고 판단할 수 없다. 결합의 균형 prior와 실제 평가 분포, 보정 품질을 먼저 분리해 검증할 근거가 생겼다. Test를 본 뒤 선택한 자연 head를 검증 완료한 최종 모델로 채택한 것은 아니다.

분류 head 학습·보정의 구현 범위

네 estimator의 2,048차원 연결 표현 위에 hidden 128 MLP를 학습했다. Embedding mixup 0.2, 최대 100 epochs, class-balanced validation NLL로 epoch를 선택한다. 학습 사례의 prior와 누적 train prior가 다름을 logit-adjusted loss에서 반영한다. 별도 split에서 scalar temperature를 추정한 뒤 log score를 평균한다.

원 BalPoE의 이론은 적절히 보정된 expert 등의 가정에서 balanced error를 다룬다. 이 IDS 적용의 클래스별 보정이 충분한지, Macro-F1·정상 오탐 목표에 맞는지는 별도 검증 대상이다. 원 논문의 vision 모델 재현이나 이론의 반례로 주장하지 않는다.

4. 3안: context 최적화는 균등 배분에서 효과가 있었다

이 절은 항상 갱신 지연 없음 · 초기 context와 선택 context의 비교다.

초기·최적화 모델은 같은 2,048행 context, 같은 estimator 1개, 같은 전처리를 쓴다. 이 대조가 최적화 효과를 가장 직접적으로 보여준다. 단일 PFN 기준선은 최대 10만 context·4 estimators이므로 기준선과의 차이에는 압축·전처리·ensemble 차이가 함께 들어간다.

균등 배분 · 효과가 나타난 클래스

ToN Macro-F1이 64.53 → 68.68%로 오른다. MitM은 11.18 → 23.55%, Ransomware는 7.16 → 25.81%지만 Scanning은 14.80 → 14.14%다. CIC2018의 전체 증가는 +0.73%p다.

자연 배분 · 양상은 다르다

CIC2018은 72.73 → 72.72%로 거의 같다. ToN은 69.86 → 65.74%로 감소한다. Ransomware F1이 44.63 → 8.17%로 낮아지며, Recall 증가보다 Precision 감소가 크다.

학습이 작동했는가, 선택 목표가 맞았는가

초기 상태까지 포함해 validation의 class-balanced NLL이 가장 작은 context를 고른다. CIC2018 자연 배분은 Web attacks·Infiltration·Bot 도입의 세 버전 모두 초기 상태(step 0)가 선택됐다. 이후 단계에서 최적화된 context를 채택하지 않았으므로 해당 단계의 지연 없는 결과도 대조군과 같다.

ToN 자연 배분은 학습한 context가 선택돼도 test F1이 낮아지는 단계가 있다. Ransomware/Backdoor 도입 단계의 validation NLL은 0.329 → 0.278로 낮아졌지만, 해당 단계 test F1은 77.50 → 72.29%였다. 선택 손실의 개선과 실제 희소 공격 F1의 개선이 일치하지 않았다는 관찰이다. 손실 함수 하나만을 원인으로 확정하지 않는다.

선택 조건의 단계별 checkpoint · validation 지표 · test F1

각 단계 최대 300 step을 수행한 뒤 초기 상태를 포함해 선택했다. Step 0이 선택되어도 탐색에 든 비용은 발생한다. Validation FPR은 해당 단계 cal 표본군, test F1은 해당 재생 구간으로 모집단이 다르다.

최종 단계의 학습 사례 수와 실제 context 구성

각 클래스의 최소 절반을 최적화 query에 남기므로 자연 배분의 CIC2018 Web attacks는 train 9행 중 context 4행, ToN Ransomware는 20행 중 10행, MitM은 31행 중 15행만 들어간다. 균형 sampling은 확보한 고유 사례 수를 늘리지 않는다.

표는 test 표본 수 내림차순이다. 최적화 후 context 행 수·라벨은 같고 feature만 바뀐다. 작은 고유 표본 수는 제약이지만, 그것만으로 모든 성능 차이를 설명하거나 표본을 늘리면 반드시 개선된다고 단정하지 않는다.

후속 검증의 방향: 같은 context·query 예산에서 배분과 posterior 보정을 구분하고, validation의 NLL뿐 아니라 희소 공격 Precision·Recall과 Benign FPR이 함께 유지되는지 확인해야 한다. 현재 최적화는 Benign FPR을 기록하지만 선택 제약으로 사용하지 않았다.

5. 작은 context는 추론을 줄였지만 최적화에 갱신 시간이 들었다

후속 갱신 합계는 초기 구축을 제외한 CIC2018 4회·ToN 5회다. 추론은 선택 정책의 서비스 시간 합계를 평가 행 수로 나눈 값이며 배치 수집·큐 대기를 제외한다. 실제 처리는 1,024행 배치다.

지연 없는 평가에서 단일 PFN은 256–268μs/행, 초기·최적화 context는 약 77–78μs/행이었다. Context 길이와 estimator 수·전처리가 함께 달라져 이 속도 차이를 최적화만의 효과로 볼 수는 없다. 최적화 context의 후속 갱신은 277–350초로 단일 PFN의 41–50초보다 오래 걸렸다. 고정 backbone이어도 task별 context 최적화는 갱신 작업이다.

2안은 원 TabPFN 준비 비용에 validation embedding 추출·head 학습·보정 비용을 더했다. 기존 fit을 재사용했다고 0초로 처리하지 않는다. 단독 head의 독립 운영 비용은 측정하지 않았다. 3안은 매 단계 처음부터 최적화했고 초기 대조군에는 준비 시간만 적용했다. GPU 비용 worker는 RTX 4090에서 겹치지 않게 실행했다.

갱신이 늦어지는 동안 구버전을 사용하면

ToN 균등의 최적화 context는 지연 없음 68.68%에서 1,000행/초 66.07%로 낮아진다. 초기 context 대비 이득은 남지만 줄어든다. CIC2018 균등은 72.20 → 71.20%로 낮아져, 1,000행/초에서는 초기 context 71.47%보다도 낮다.

모델 버전은 배치 수집 완료 시점에 고정한다. 갱신 지연에 따른 구버전 사용과 추론 대기열은 구분하며, 늦게 응답한 행을 자동 오답 처리하지 않는다. 단일 head 진단에는 별도 갱신 시계를 적용하지 않았다.

선택 정책의 단계별 F1·클래스별 F1·갱신 시간

단계 F1은 해당 시점까지 등장한 클래스의 평균이다. 단계마다 클래스 구성이 달라 점수 변화만으로 망각을 판단하지 않는다. 지연 정책에서는 한 평가 구간에 여러 모델 버전이 쓰일 수 있다.

6. 다음에는 무엇을 남기고 무엇을 검증할 것인가

  1. 자연분포 head를 후속 비교의 기준 후보로 남긴다. 자연 배분 두 데이터에서 개선한 클래스가 있어 공통 표현을 활용할 가능성은 있다. 같은 validation 라벨을 소비하는 단일 head·결합 모델을 비교하고 별도 확인 split에서 재검증한다. 현 test 성적만으로 최종 모델을 선택하지 않는다.
  2. 균형 결합의 목표를 검증 데이터에서 학습·선택한다. 목표 prior와 결합 가중치를 검증 자료에서 정하고, 희소 공격 성능과 Benign FPR 제약을 함께 본다. Uniform-target 결합·natural head·학습된 결합을 대조하면 단순한 공격 Recall 증가와 실제 분류 개선을 구분할 수 있다. 이 후속안은 아직 실행하지 않았다.
  3. Context 최적화는 같은 초기 조건의 대조를 유지한다. 균등 배분의 일부 개선은 확인됐다. Prior 보정과 선택 기준을 분리한 비교를 먼저 하고, 품질이 유지되는 설정에서 단계 간 context 재사용으로 갱신 비용을 줄일 수 있는지 평가한다. Warm start 효과는 현재 결과에 포함되지 않는다.

두 주 결과 모두 현재 단일 PFN을 넘지 못했다. 다만 단독 head와 초기 context 대조군 덕분에, 추가 모델 수보다 목표 분포·오탐·선택 기준을 우선 개선해야 할 근거가 구체화됐다. 단일 seed의 탐색 결과이며 방법론·성능 우위·연구 버전 변경을 확정한 보고서는 아니다.

근거 논문과 이번 적용의 범위

  • Sanchez Aimar et al. — Balanced Product of Calibrated Experts for Long-Tailed Recognition, CVPR 2023. 서로 다른 목표 분포를 갖는 expert의 보정·결합을 다룬다. Discussion: 보정 가정 아래 balanced error를 다루는 이론과 IDS의 Macro-F1·정상 오탐 목표는 구분해야 한다. 이번 적용은 TabPFN 공통 표현을 고정한 head 구조이며, 단독 head와 결합의 FP 차이가 목표·보정을 재검토할 근거다.
  • Ma et al. — In-Context Data Distillation with TabPFN, 2024. 제한된 context를 최적화해 큰 tabular 데이터의 정보를 담는 접근이다. Discussion: IDS의 순차 공격 도입에서 희소 클래스 정밀도나 갱신 비용 우위를 보장하지 않는다. 이번에는 초기 context와 최적화 context를 같은 조건으로 비교하고 비용까지 측정했다. 균등 배분의 개선과 자연 배분의 저하를 구분해 후속 설계를 정한다.
실행 출처·검증·구현 기록

각 results.json의 COMPLETE SHA-256, 혼동행렬 합계, 클래스별 Macro-F1 재계산, test 전체 행 수와 기존 독립 검증 통과를 확인했다. 단독 head는 지연 없음에서만 수집된 진단이며 같은 test를 반복 학습·선택에 사용하지 않았다.
